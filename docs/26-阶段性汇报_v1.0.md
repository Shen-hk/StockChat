## 一、项目是什么（一句话）

**股问 StockChat**：基于腾讯 Kuikly（Kotlin Multiplatform）的 AI 股票问答 App，面向 A 股散户新手。

定位一句话：**做股民的解释器，不做荐股机。**

- 技术底座：Kuikly 跨端（Android 主验证 + H5 演示）+ DeepSeek 真实 API + 腾讯/东财公开行情
- 核心架构亮点：**意图与数据分离（ADR-11）** —— LLM 只产出卡片意图，行情数字由端侧 Provider 填真实数据，幻觉无法污染任何一个数字
- 合规锚点：按中证协 2026-06 分级准入，"持仓分析"是低风险可优先推广场景，本产品定位精准落在这个格子；不做推荐、不做估值、不做目标价

## 三、阶段成果

### 3.1 架构与工程

1. **跨端一套代码**：Kuikly KMP，页面/状态/协议/Provider/卡片算法全部在 `commonMain`，Android 与 H5 共用；iOS/OHOS 保留工程壳。
2. **意图与数据分离（ADR-11）**：AI 返回卡片意图骨架，端侧 QuoteProvider 填真实行情 —— 从架构上杜绝"AI 编造行情数字"。
3. **数据层多源 + 三级降级**：腾讯行情（快照/分时/K线）、东财（资金流/板块/涨停池/龙虎榜/财报/公告/研报/股东户数）、新浪（全市场列表），统一走 **真实 → 缓存 → 离线 Mock** 降级链；信源分层 + 数据时间戳显式展示。
4. **AI 闭环**：应用内 API 配置、DeepSeek 真 SSE 流式、多轮上下文、会话持久化、结构化卡片协议（14 类卡片）。
5. **单测**：协议解析、实体识别、图表算法、东财字段解析、架构边界约束、实体拖拽等，字段解析器以 curl 实测返回固化基线。

## 四、遇到的问题与解决（重点）

### 4.1 Kuikly 动画注册滞后一个变更周期（本周最有价值的源码级发现）

**症状**：欢迎页入场动画"从不播放"、自选行左滑松手吸附"静默跳变"、玻璃浮起效果丢失——三类症状，一个根因。

**源码级定位**：Kuikly `attr` 闭包每个变更周期按固定顺序执行——先消费**上一周期**注册的动画，再重跑闭包注册本周期动画。即：**本次变更播放的动画 = 上一个周期注册的那个**。旧代码在挂载周期注册了 `linear(0f)`（想做瞬时复位），结果 flip 周期消费的正是它，真正的 easeOut 入场动画永远无人消费。

**解决**：① 预期下一次变更播放的动画必须在**当前周期无条件注册**；② 禁止在 pre-state 周期注册零时长"复位"动画；③ 入场动效补版本号守卫兜底 timer，防 ref/Timer 链断裂导致视图卡在 opacity 0。已修复并真机验证通过，规则沉淀为 `AGENTS.md` 的 **R1–R5 动画规则**（含"reactive reads only"“animate 绑定块内最后读取的 observable key"等 5 条）。

### 4.2 animate() 静默绑定错误的 observable（不报错的坑）

`animate()` 的 value 实参不参与判定，它绑定 attr 块内**最后一次读取的 observable key**。自选页 `swipeOffset()` 按分支提前 return，导致开态注册到 A、关态注册到 B，而真正驱动位移的是 C——key 不匹配，spring 永不消费，**无任何报错**。修复：固定读取顺序、驱动 key 恒为最后读。同类坑还有 `page.theme` 这类"主题型 observable"混入 attr 会抢占动画 key。

### 4.3 输入框光标/删除失效（doc 13 根因分析）

Kuikly 输入组件非受控行为与 Android 光标/软删除冲突，曾出现删除键失效、光标跳位。通过 adb logcat 真机抓包定位，改为非受控架构 + `KRComposerCursorHandler` 专门处理 Android 光标与软删除，最小 diff 修复。

### 4.4 数据源侦察：推翻自己的过期结论

立项文档 ADR-6 曾记录"东财接口反爬空返回、弃用"。本周 curl 实测发现**东财三大接口族全部可用**，据此一次性补齐资金流/涨停池/龙虎榜/财报/公告/研报等 13 项行业标配数据维度（此前命中 0 项）。工程要点：东财返回 UTF-8、腾讯返回 GBK，解码必须按源区分；需加 UA + 请求间隔 ≥200ms 防限流。

### 4.5 跨端 API 的隐式差异（commonMain 约束）

- `Translate(x, y)` 的参数是**百分比**（-1~1）不是 dp，`offsetX/offsetY` 才是 dp——上滑动效曾因此错位
- `vif` 新建的 View 没有首帧变化可驱动，**做不了入场动画**（UndoBar 直接出现，反而是符合 Snackbar 规范的正确取舍）
- commonMain 无跨平台时间源（`getTimeMillis` 是 JVM-only），快扫速度判定改为双阈值距离吸附
- H5 无原生 radial-gradient，柔光背景改用**四层同心胶囊洋葱**近似（层数越多台阶越小）

### 4.6 工程与环境问题

- **H5 构建阻塞**：`jsBrowserDistribution` 卡在 kotlinNpmInstall 被环境 safe-delete 保护拦截，本机无法验证，只能在终端手动跑——已定位为环境限制而非代码问题
- **Gradle 缓存锁间歇性失败**（journal-1.lock 拒绝访问）：摸索出"失败但 class 已产出"的产物级验证方法，避免误判编译失败
- **gitignore 曾吞文件**：全局 `*.js` 规则误吞 static_server；排查发现 37 个源文件 + 21 篇文档未入库，已修复 ignore 规则并分批提交
- **CRLF/LF 行尾不一致**：跨平台补丁前统一转换 LF

### 4.7 设计返工的教训

- 市场页 v1.0 被驳回（未做调研、AI 触点过多、Demo 太小），v2.0 按五条指责重做——教训：**设计先行调研、AI 触点做减法、原型用真实数据**
- 吸顶指数条原设计为独立浮层，与顶栏必然重叠——立铁律：**常驻信息条一律并入顶栏滚动紧凑态，绝不做独立浮层**
- 详情页视觉方案两轮迭代（玻璃+蓝 → 琥珀金+暖黑 → 深蓝+浅色定稿），教训：先定色彩 token 权威源，再写实现，避免双份真值漂移
