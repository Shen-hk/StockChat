## 0. 摘要与范围

把「自选 · 异动预警 · 风险地图」整合为**我的小空间**：自选页升级为空间首页（聚合头 + 预警收件箱预览 + 速览卡），预警从「盯价格」升级为三类消息（行情异动 / 事件临近 / 暴露变化）的应用内收件箱，风险地图成为预警的生产端（事件 → 转为预警）。

**不做**：远程推送（维持 doc 23 N-R6）、评分/等级/匹配词汇、任何买卖建议、新路由注册（复用 `Routes.ALERTS` / `Routes.WATCHLIST` / `Routes.RISK`，页类名不改，避免 router 破坏）。

三页分工与联动：

```
自选页（小空间首页）            收件箱页                       风险地图
├ 聚合头（不变）          →    ├ 三类消息时间线          ←    事件时间轴「转预警」出口
├ InboxPreviewRow(新)    →    ├ 筛选 chips（含计数）          暴露快照变化 → EXPOSURE 消息
├ 关注行（不变）               ├ 展开=已读 + 归因事实卡
└ 速览卡(新，条件触发)         ├ 问AI出口(openChatWithQuestion)
                              └ 静默 / 免打扰（持久化）
```

## 1. 合规与文案铁律（评审一票否决）

1. 全量文案禁词：`风险承受 / 匹配 / 适配 / 你的风险等级 / 评分 / 健康分 / 建议仓位 / 止损 / 止盈 / 调仓`。
2. 每条消息**只陈述已发生事实**，展开区标题用「归因检查顺序」或「事实卡」，页内常驻一行「只解释已发生的事 · 不构成操作建议 · 无远程推送」。
3. EXPOSURE 消息必须带口径角标（`等权估算`）；快照数据 < 2 条时**不生成** EXPOSURE 消息（不编造对比）。
4. 「问 AI」一律 `openChatWithQuestion(问题, 来源路由)` 走对话页 AttributionIntent 链路，**页内不自行生成 AI 回答**。
5. 免打扰/静默优先于提醒感：静默按钮是消息级一等动作，不是藏起来的设置。
6. 红涨绿跌（`theme.rise`/`theme.fall`），平盘 `theme.flat`；EXPOSURE 用品牌蓝不用涨跌色（风险不制造情绪）。

## 2. 数据契约（唯一签名源）

### 2.1 新文件 `data/AlertInboxStore.kt`

```kotlin
package com.kuikly.stockchat.data

import com.kuikly.stockchat.data.provider.Quote
import com.kuikly.stockchat.data.provider.MarketCalendarEvent
import com.kuikly.stockchat.data.provider.CalendarEventKind
import com.kuikly.stockchat.data.provider.platformCurrentTimeMillis
import com.kuikly.stockchat.data.storage.KeyValueStorage
import com.tencent.kuikly.core.nvi.serialization.json.JSONArray
import com.tencent.kuikly.core.nvi.serialization.json.JSONObject

enum class AlertKind(val label: String) {
    MOVE("行情异动"), EVENT("事件临近"), EXPOSURE("暴露变化")
}

data class AlertMessage(
    val id: String,              // 稳定去重键，见 §2.2 id 规则
    val kind: AlertKind,
    val symbol: String,          // EXPOSURE 类为 ""
    val name: String,            // EXPOSURE 类为 "组合"
    val title: String,
    val summary: String,         // 收起态一行事实
    val facts: List<String>,     // 展开态：归因检查顺序/事实卡，每条一行，规则引擎产出
    val createdAtMillis: Long,
    val askQuestion: String,     // 「问 AI」预填问题（openChatWithQuestion 用）
    val termKey: String = "",    // 可选术语出口（如 UNLOCK）；空 = 无
    /** true = RiskMapPage「转预警」手工写入（持久化），false = 每次构建派生 */
    val pinned: Boolean = false,
)

class AlertInboxStore(private val storage: KeyValueStorage) {
    fun readIds(): Set<String>                       // 已读消息 id
    fun markRead(id: String)
    fun markAllRead(ids: List<String>)
    fun unreadCount(messages: List<AlertMessage>): Int =
        messages.count { it.id !in readIds() }
    fun mutedRuleSymbols(): Set<String>              // 静默的价格规则 symbol
    fun toggleMute(symbol: String)
    fun exposureMuted(): Boolean; fun setExposureMuted(Boolean)
    fun quietHoursEnabled(): Boolean; fun setQuietHours(Boolean)   // 收盘后免打扰，默认 false
    fun extraMessages(): List<AlertMessage>          // pinned 消息持久化（RiskMapPage 写入）
    fun putExtraMessage(msg: AlertMessage)           // 按 id 去重；不自动写已读
    companion object { private const val KEY = "stockchat_alert_inbox_v1" }  // 一个 key 存全部状态 JSON
}
```

序列化要求：照抄 `AlertStore`/`RiskSnapshotStore` 的 JSONArray 读写风格；`facts` 存 JSONArray of string；所有解析 `runCatching` 降级为空值，不崩溃。**磁盘结构是内部实现，页不得依赖 JSON 字段。**

### 2.2 新文件 `data/AlertInboxBuilder.kt`（纯函数，无副作用）

```kotlin
object AlertInboxBuilder {
    /**
     * @param rules        alertStore.list()（启用的规则才产生 MOVE）
     * @param quotes       symbol -> 当前 Quote（可含 null；缓存放这里，构建不触网）
     * @param events       未来 30 天事件（insightRepository.loadCalendar ∩ 自选，调用方过滤）
     * @param snapshots    riskSnapshotStore.all()（≥2 条才可能产生 EXPOSURE）
     * @param mutedSymbols 静默规则
     * @param exposureMuted 暴露变化静默
     * @param quietHours   true 时丢弃 15:05 之后触发的 MOVE（合并进次日，v1 简化：直接不生成）
     */
    fun build(
        watchlist: List<WatchlistItem>,
        rules: List<AlertRule>,
        quotes: Map<String, Quote?>,
        events: List<MarketCalendarEvent>,
        snapshots: List<RiskSnapshot>,
        mutedSymbols: Set<String>,
        exposureMuted: Boolean,
        quietHours: Boolean,
        nowMillis: Long,
        today: String,               // platformCurrentDate() 口径 yyyy-MM-dd
    ): List<AlertMessage>            // 按 createdAt 倒序（EVENT 用事件日期，EXPOSURE 用快照时间）
}
```

生成规则（全部规则引擎，禁止 LLM）：

| kind | 触发 | id 规则 | title/summary 形态 |
|---|---|---|---|
| MOVE | `LocalAlertProvider.evaluate(rule, quote) != null` 且 rule.enabled 且 symbol ∉ mutedSymbols 且 !quietHours 时段 | `"MOVE:$symbol:${rule.thresholdPercent}"` | title=`${name}上涨/下跌达到 X%`；facts=归因检查顺序三条（① 板块是否同步——「建议对照同板块行情」句式，**不下结论**；② 近 7 天公告；③ 量价关系，quote 有换手/量数据就带，没有就省略该条） |
| EVENT | `events` 中 30 天内 UNLOCK/EARNINGS/DIVIDEND（IPO 不产生消息） | `"EVENT:$symbol:${event.date}"` | title=`${name}：${kind.label}进入 30 天窗口`（EARNINGS 用「财报预约披露 ${date}」）；facts=事实卡（解禁带规模与「解禁≠减持」口径；财报带「统计描述，不是预测」） |
| EXPOSURE | 最后两条 snapshot 满足 `|ΔCR3| ≥ 10`（百分点）或 memberCount 变化，且 !exposureMuted | `"EXPOSURE:${newer.capturedAtMillis}"` | title=`你的组合比上次更${集中/分散}了`；facts=「Top 行业 CR3：A% → B%」「成员数：n → m」「变化主因见风险地图 · 等权估算」；symbol="" name="组合" |

`pinned`（RiskMapPage 手工转的 EVENT）恒出现在结果里（build 内先取 extraMessages? **不**——build 不读 store；调用方把 `store.extraMessages()` 合并进结果并按 id 去重、按时间排序）。`askQuestion` 形态：MOVE=`「${name}今天为什么${涨/跌}这么多？」`、EVENT=`「${name}的${解禁/财报}意味着什么？」`、EXPOSURE=`「我的自选组合集中度变化说明什么？」`。

## 3. 页面规格

### 3.1 AlertCenterPage（Agent A 独占，重写内容区，@Page 名与 Routes.ALERTS 不变）

- 顶栏：title `预警收件箱`，subtitle `行情异动 · 事件临近 · 暴露变化 · 只解释已发生的事`；actions 加 `全部已读`。
- **筛选行**：`全部 / 行情异动 / 事件临近 / 暴露变化` chips（带计数）。observable `inboxFilter: String`（""/MOVE/EVENT/EXPOSURE），切筛选经 `refreshDisplay()` 落 ObservableList（vfor 只吃 ObservableList，照抄 WatchlistPage 模式）。
- **消息卡**（vfor）：
  - 未读卡左缘 3dp `theme.rise` 色条 + 未读时 title 前小圆点；已读卡整体降透明度 0.72。
  - kind 徽标配色：MOVE=riseSoft/rise，EVENT=`Color(0xFFFFF7E8)`/`Color(0xFFA66A00)`，EXPOSURE=brandSoft/brand（light 主题硬编码仅此一处，dark 用对应 soft 色，参照 theme 里现成 soft token 的 dark 值逻辑）。
  - 点击卡 = 展开/收起（observable `openMessageId`，同屏只开一张）；**展开即 markRead**。
  - 展开区：brandSoft 底事实卡，标题 `✦ 归因检查顺序`（MOVE）或 `✦ 事实卡`（EVENT/EXPOSURE），逐条 facts 文本；下方动作行：`问 AI`（primary，`openChatWithQuestion(msg.askQuestion, Routes.ALERTS)`）、`看详情`（symbol 非空时 `openStockDetail(symbol, Routes.ALERTS)`）、`静默本规则`（MOVE）/`不再提醒此类`（EXPOSURE）/EVENT 无静默（事件天然过期）。静默后按钮文案变 `已静默 ✓`（读 store 状态渲染，不做一次性 state）。
  - termKey 非空时事实卡底部加 `「${termKey.label}」是什么意思 ›`（EVENT 的 UNLOCK）→ `glossaryStore.encounter(termKey)`（C-2 单点收口）后 toast/行内提示即可，不强制跳页。
- **免打扰卡**：底部一张卡「收盘后免打扰」+ 副文案「15:05 后触发的异动合并到次日」+ 开关（读 `quietHoursEnabled`，点击翻转持久化）。开关态是 observable，切换有滑块位移动画（R2：animate 绑定该 observable key）。
- **监控规则区**（保留旧能力，降级为收件箱下方的次级区）：「从自选添加」（candidates）+「价格监控规则」列表（启用中/已暂停、暂停/恢复、删除）。文案 `启用 ±3%` 等沿用。
- 空态：无消息 → 「收件箱是干净的 · 异动和事件触发后会出现在这里」；无自选 → 引导去自选页（`openPage(Routes.WATCHLIST)`）。
- **动效**（全部走 R1–R5，先读 `AGENTS.md`）：消息卡入场用 R4 两拍（`inboxPresented` observable + `setTimeout(0)` 翻转），未读卡 translate 12→0 + opacity 0→1，`reduceMotion` 直出；展开区高度不动画（vif 直出），只有 opacity/translate 做两拍入场；`animate()` 恒定注册（R5），驱动 key 为 `openMessageId` / `inboxPresented` / `inboxFilter`，`theme` 在构建作用域先捕获（R2）。

### 3.2 WatchlistPage（Agent B 独占）

- 顶栏：title `我的小空间`，subtitle `自选 · 预警 · 风险 · 速览，都在这里`；actions 加 `预警`（→ Routes.ALERTS）。
- **InboxPreviewRow**（聚合头下、筛选行上，z2 卡）：
  - 显示条件：`messages.isNotEmpty()`（构建见 §2.4）。
  - 内容：左 36dp 圆角图标位（brandSoft 底 + `⚡` 字符）叠未读 badge（rise 底白字数字，unread=0 不画 badge）；中间两行：`预警收件箱 · N 条未读`（未读 0 时 `预警收件箱 · 暂无新消息`）+ 最新一条 summary（单行截断语义即可，超长加 `…`）；右 `查看 ›`。整卡 click → `openPage(Routes.ALERTS)`。
  - 入场动效 R4 两拍（`inboxPreviewPresented`），translate 12→0 + opacity 0→1；reduceMotion 直出。
- **速览卡**（列表行之后、底部通路之前，z3 玻璃或 surface 卡，条件触发）：
  - 显示条件：`aggregate().moverCount > 0` 或 30 天内有 EVENT。
  - 头行：徽标 `速览`（brand 底白字，**不用 "AI" 字样**——内容由规则引擎产出，冒称 AI 反而违规）+ 标题 `今日速览 · 9:30 前看完` + 箭头；整卡点击翻转 `briefOpen`。
  - 展开内容 2–4 行事实句（纯规则）：① 等权涨跌 vs 结论（复用 aggregate 现有字段，句式「你的 N 只自选等权 X%，弱于/强于大盘」——大盘对比 v1 可省略，无数据不写）；② 最大异动行事实（「${name} ${±X}% ${放量/缩量」量数据缺省就只写涨跌）；③ 最近一条 EVENT 事实；④ 收尾行固定 `由规则引擎从行情与事件整理 · 非预测非建议`（textTertiary 9.5f）。
  - 展开动画 R4 两拍 + R5 恒注册，驱动 key `briefOpen`。
- **不动**：聚合头、筛选、行渲染、左滑、长按菜单、理由浮层（全部保持现状）。

### 3.3 RiskMapPage（Agent C 独占，最小侵入）

- `renderEventTimeline` 每条事件行右端加动作：
  - 未转：`转预警 ›`（brand 11f）→ `alertInboxStore.putExtraMessage(AlertMessage(id="EVENT:$sym:${date}", kind=EVENT, pinned=true, title/summary/facts 由该行事件数据组装, askQuestion=§2.2 句式, termKey=UNLOCK 时带))`，随后把 observable `eventToInboxHint` 置为 `已加入预警收件箱 ✓`（时间轴底部一行 brand 色 10.5f 条件渲染，2.5s 后经 `setTimeout` 清空——清空写法注意同值 early-return 陷阱，先置 "" 再置回）。
  - 已转（id ∈ `extraMessages()` 的 id 集，构建时读一次存 observable）：静态 `已在收件箱 ✓`（textTertiary 10f）。
- 快照历史面板底部（≥2 条快照时）加一行 `对比上次 · 生成暴露变化预警 ›`（条件：`|ΔCR3| ≥ 10`），点击 `putExtraMessage` EXPOSURE 消息（id=`"EXPOSURE:${newer.capturedAtMillis}"`，与 builder 同 id 规则避免重复）。同样有已生成态。
- **不动**：六维面板、AI 注释、术语出口、快照采集逻辑。

## 4. 动效不变量（摘自 AGENTS.md，违者返工）

1. observable 只在 `attr{}/event{}/vif{}/vfor{}/vbind{}` 内读；构建闭包读的是首帧快照。
2. `animate()` 是 attr 块里**最后一个**读 observable 的操作；`theme` 在构建作用域先捕获再进 attr（R2 高危）。
3. 每个驱动 key 只注册一条动画；入场动画**无条件恒注册**（R5：本周期注册、下拍消费），禁止注册零时长动画。
4. 新挂载视图动效走两拍 `mounted → presented`（`setTimeout(0)`），presented 态必须在目标 attr 内被读到。
5. `platformPrefersReducedMotion()` 为 true 时全部直出。

## 6. 实施记录（2026-09-07 深夜）

全部落地，本节记录与 §3 规格的偏差（均为有意取舍）：

| WatchlistPage | 小空间首页化 | 改名 + 「预警」顶栏入口；InboxPreviewRow（badge = unread，attr 内读 inboxMessages/inboxUnread 保证响应式）；今日速览卡（徽标「速览」非 AI 字样；事实行 = 聚合结论/最异常行/最近事件，缺数据不写）；日历拉取口径照抄 RiskMapPage（take(8) 替代 30 天字符串数学） |
| RiskMapPage | 转预警出口 | 事件行「转预警 ›」/已转态；快照面板 \|ΔCR3\|≥10 时「生成暴露变化预警」；均 putExtraMessage 只写不读，显示态由构建期 id 集合驱动 |

**偏差记录**：
1. §3.1/§3.2 的「展开区 opacity/translate 两拍入场」简化为 **vif 直出**——高度不动画的前提下单独做透明度两拍收益低、且多一个 per-message presented 状态易踩 R5 陷阱；与聚合头/hover 等既有交互保持同口径。
2. 消息时间显示用业务口径标签而非 HH:mm（跨端无分钟级格式化 expect，避免为原型引入平台 API）。
