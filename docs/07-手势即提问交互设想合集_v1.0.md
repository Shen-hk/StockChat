## 1. 文档定位

02 号文档建立了「三流合一交互模型」（文本流 × 卡片流 × 联动层），06 号文档解决了「卡片怎么展开」。本文档回答第三个问题：**卡片怎么被操纵**——用户不靠打字、只靠手势，就能完成浏览、关联、分析、推演、感知、个性化六类动作。

七个设想并非都要落地 Demo，本文档明确给出：

- 每个设想的**定义、触发、视觉、状态机、工程沉淀、排期**（给开发）
- 与现有体系（三流合一 / 渐进披露 / Context Bar）的**关系论证**（给评审）
- **优先级排序与裁剪预案**（给项目）

## 2. 设计哲学：四条宪章

沿用 02 号文档三条宪章，新增第四条：

| 宪章 | 内涵 | 对手势设计的约束 |
|---|---|---|
| 一 · 抑制冲动 | 降低理解成本，不刺激交易 | 手势只触发"理解"行为，不触发"交易"行为 |
| 二 · 渐进披露 | 默认给结论，按需给数据 | 手势是"按需"的执行手段，不是花活 |
| 三 · 聊看一体 | 问与看不被迫切换 | 手势的结果尽量不离开聊天流 |
| **四 · 手势即提问** | **一切手势的语义都必须能被翻译回一句自然语言提问** | 可撤销、可学习、可演示——这是手势设计的底线 |

第四条是本文档的核心论点：**交互创新的终局，是把"组织语言 → 打字"的提问成本，降为"一个手势"的肌肉记忆。**追问 chips 让提问变成"点一下"（零成本分支），手势让提问变成"划一下、拖一下、圈一下"（零打字提问）。

**手势可翻译性检查**：每个手势都必须有一个文字等价物（如"拖拽连线" = "茅台和五粮液的相关性如何"）。意义有三：

1. **可学习**：用户不会时，有文字说明兜底
2. **可撤销**：误触时用户知道这个动作"意味着什么"
3. **可演示**：演示时即使手势失败，也能用文字/按钮等效完成

## 4. ① 堆叠洗牌 StackDeck（用户提出，纳入）

**定义**：AI 一次回答常带 3-5 张结构化卡片。传统做法是垂直堆叠往下排（越长越累），堆叠洗牌把一组卡片叠成一叠牌组，用户上下滑动逐张翻看，把"线性阅读"变成"快速过牌"。

**适用场景**：多标的浏览（"茅台、五粮液、泸州老窖最近怎么样"→ 三张行情卡）、多因子速览（归因卡的多因子轮播）、多资讯速览。

**触发与手势**：

- 卡片组默认以堆叠形态呈现（顶部卡 + 底下露出 2-3 张的侧切面厚度）
- 上滑 → 下一张翻入（顶部卡翻出，下一张上浮）
- 下滑 → 上一张翻回
- 单击顶部卡 → 进入该卡的正常交互（渐进披露，见 06 号文档）
- 牌组最后一张底部留「展开全部 ▼」按钮 → 转为常规垂直列表（兜底入口）

**视觉规范**：

- 堆叠厚度：露出 8-12dp 侧切面，暗示"底下还有 N 张"
- 侧切面边缘加数字角标（2/5），明确剩余张数——**解决"隐藏后续卡"的最大缺陷**
- 翻卡动画：translateY + scale（顶部卡上移缩小淡出，下一卡上浮至顶），250ms ease-out
- 翻卡时 Haptic 轻反馈

**状态转换**：

```
idle(堆叠态, 顶部卡=第1张)
  ├─ 上滑 ──→ 翻出第 N 张，第 N+1 张上浮至顶
  ├─ 下滑 ──→ 翻回第 N-1 张
  ├─ 单击顶部卡 ──→ 进入该卡渐进披露（展开/详情），堆叠暂停
  ├─ 滑动过快 ──→ 惯性翻到牌组边界（阻尼回弹）
  └─ 最后一张 ──→ 出现「展开全部 ▼」→ 转为垂直列表
```

**与其他形式的关系**：堆叠洗牌是"多卡切换"，渐进披露是"单卡深挖"——正交互补。堆叠解决"3-5 张卡怎么快速扫"，渐进披露解决"一张卡怎么深入看"。二者可组合：堆叠中单击顶部卡 → 该卡展开。

**工程要点**：

- `StackDeck` 通用容器：持有 `List<CardModel>` + 当前索引，翻卡动画只动 transform（不重排）
- 与卡片流的关系：聊天消息列表中的**连续同类卡**（如同一标的的行情+走势）自动聚合成一组 StackDeck；异类卡不聚合
- 聚合规则是纯函数（`DeckAggregator.group(blocks)`），可单测
- 与列表滚动手势冲突防御：堆叠内部滑动用独立手势域，翻到边界后事件交还给列表滚动

**排期**：P1（M5）。聚合规则 + StackDeck 容器 = 约 1 人日，性价比高。

## 5. ② 时间轴拖拽回溯 TimeAxisRecall

**定义**：聊天页底部一条可拖拽的时间轴，手指划到某天，整段对话中的行情卡、归因卡、资讯卡全部"倒带"为那天的快照。问"茅台 3 月暴跌怎么回事"，拖到 3 月 15 日，看到的是那天的行情、那天的归因、那天的新闻——**股票天然有时间维度，这是通用 AI 助手永远做不了的能力**。

**适用场景**：盘后复盘（"上周四那根大阴线发生了什么"）、事件回溯（"公告那天市场什么反应"）、对比验证（"3 月和 5 月两次下跌的原因一样吗"）。

**触发与手势**：

- 长按聊天页底部时间胶囊（默认显示今天）→ 展开时间轴轨道
- 在轨道上左右拖动 → 进入 scrubbing（拖动预览）态
- 松手 → 吸附到最近日期，卡片组切换为该日快照
- 再次点击时间胶囊 → 回到"实时"态

**视觉规范**：

- 时间轴为一条细轨道，上面有刻度与关键事件点（涨跌超 ±3% 的日期用涨跌色点标记）
- scrubbing 态：顶部浮出大字号日期 + 当日涨跌幅（如"2026-03-15 · 茅台 -5.2%"）
- 卡片切换动画：旧卡淡出、新卡以当日涨跌色描边淡入（暗示"这是历史快照"）
- 历史态卡片右上角加「历史快照 03-15」角标，与实时数据明确区分

**状态转换**：

```
normal(实时态)
  ├─ 长按时间胶囊 ──→ timeline 展开
  ├─ 拖动轨道 ──→ scrubbing(拖动预览, 顶部浮层跟随)
  ├─ 松手 ──→ snapTo(nearestDate) → 卡片组切换为历史快照
  ├─ 点时间胶囊 ──→ 回到实时态（卡片组恢复实时数据）
  └─ 拖回今天 ──→ 恢复实时态
```

**与其他形式的关系**：这是"三流合一"的场景层扩展——文本流不变（对话内容仍在），卡片流整体变为历史快照。与归因链卡天然配合：历史归因卡展示"那天"的四因子，而不是今天的。

**工程要点**：

- 核心依赖 `SessionSnapshotter`：会话中每张行情类卡片的渲染数据（symbol + 时间戳）记录在案，回溯时按日期重新向 QuoteProvider 拉历史快照
- 腾讯接口日K线自带日期字段，历史快照数据源天然可用（ADR-6 实测验证）
- 时间轴事件点数据来自行情历史（涨跌超阈值标记），是纯函数计算（`TimelineMarker.compute(quotes)`）
- 注意：AI 生成的文本结论（归因分析）不回溯——LLM 无法重放历史推理。历史态只回溯**数据类卡片**，文本保持原样并在顶部提示"以下为 03-15 数据快照"

**排期**：P1（M5 增强项）。依赖会话快照机制，建议在 M2 持久化完成后预留记录接口；工期紧可整项裁剪（不影响闭环）。

## 6. ③ 拖拽关联 DragLink

**定义**：把一张股票卡长按拖到另一张卡上，两张卡之间拉出一根连线，AI 立刻给出两者的相关性分析——不用打字问"茅台和五粮液什么关系"，手势即提问。

**适用场景**：多标的关联（"A 和 B 谁带动谁"）、板块联动验证（拖个股卡到板块卡上看联动强度）、归因链延伸（拖归因卡的"资金面"因子到资金流向卡上，展开联动详情）。

**触发与手势**：

- 长按任意卡片 ≥ 350ms → 卡片抬升（scale 1.03 + 阴影加深），进入"可拖拽"态
- 拖移卡片至另一张卡片上方 → 目标卡高亮（品牌色描边），预览连线
- 松手 → 连线定格，AI 生成相关性分析卡（或就地展开联动层）
- 拖到空白处松手 → 取消（卡片回原位）
- 卡片底部出现"拖拽关联"提示条（首用引导，一次后隐藏）

**视觉规范**：

- 连线为一条贝塞尔曲线，从源卡中心到目标卡中心，2dp 品牌色，带箭头
- 连线过程中源卡半透明，目标卡高亮；连上后两卡同框轻微放大
- 相关性结果以一张新卡（`CorrelationCard`）就地插入两张卡之间，或浮层展示
- 拖拽全程 Haptic 反馈（抬起/悬停/落点三档）

**状态转换**：

```
idle
  ├─ 长按 350ms ──→ lifted(抬升, 可拖拽)
  ├─ 拖到目标卡上方 ──→ hovering(目标高亮, 预览连线)
  ├─ 松手 ──→ linked → AI 生成相关性卡（流式渲染）
  ├─ 拖到空白 ──→ 回原位（cancel）
  └─ 移动阈值超 8dp 前松手 ──→ 视为普通点击（不触发拖拽）
```

**与其他形式的关系**：与堆叠洗牌共用一套"长按 → 抬升 → 拖移"手势系统——**开发成本是叠加的而不是翻倍的**（同一手势识别器，不同落点语义）。与归因链卡的"板块联动"因子直接呼应：归因链指出"板块联动贡献 20%"，拖拽关联把它变成可主动验证的动作。

**工程要点**：

- 通用容器 `DraggableCard`：封装长按识别 + 拖移 + 落点检测，业务方只声明 `onDrop(target)` 回调
- 落点检测是纯函数（`DropTargetResolver.hitTest(cards, pos)`），可单测
- 相关性分析 = 一次新的 AI 请求，System Prompt 注入两个标的的实时行情上下文（复用 ADR-11 意图与数据分离）
- 手势冲突防御：长按 350ms + 移动阈值 8dp，与列表滚动、Context Bar 共用同一套冲突策略

**排期**：P1（M5 增强项）。与堆叠洗牌共用手势系统，可打包评估；工期紧两项一起砍。

## 7. ④ 手势画线分析 GestureChart

**定义**：在 K 线/分时图上直接用手指画——画趋势线 AI 验证是否有效、圈一段区域 AI 算区间涨跌、两点连线 AI 算区间收益率。图表从"只读"变成"可对话的画布"。

**适用场景**：技术分析验证（"这条上升趋势线现在还成立吗"）、区间统计（圈出 3 月 1 日到 3 月 15 日，问区间跌幅）、形态询问（框住一段走势，问"这是什么形态"）。

**触发与手势**：

- 详情页图表区默认"查看"模式；点击图表右上角画笔图标 → 进入"绘制"模式
- 绘制模式三种工具（顶部小工具栏切换）：
  - 趋势线：两点划线 → AI 输出"趋势线有效性 + 当前价格相对位置 + 支撑/压力位"
  - 区间框：拖框圈选一段 → AI 输出"区间涨跌幅 + 最大回撤 + 成交量特征"
  - 标记点：点一个日期 → AI 输出"当日发生了什么 + 前后 5 日表现"
- 绘制完成自动触发 AI 分析（流式结果以卡片形式嵌在图表下方）
- 再次点击画笔图标退出绘制模式，恢复图表常规手势

**视觉规范**：

- 绘制模式中画笔线为品牌色实线，可撤销（点右上角撤销按钮，支持多步撤销）
- 分析结果卡（`ChartAnalysisCard`）嵌在图表下方，与图表的框选区域用虚线连接
- 圈选区域用 30% 透明度品牌色填充，边界 1.5dp 实线
- 趋势线两端延长到图表边缘（示意"延续"），跌破/突破点用小圆点标注

**状态转换**：

```
view(查看模式)
  ├─ 点画笔图标 ──→ draw(绘制模式)
  ├─ 选工具 + 绘制 ──→ stroke(绘制中, 可撤销)
  ├─ 绘制完成 ──→ analyzing(AI 流式分析) → 分析卡嵌入图表下方
  ├─ 再次绘制 ──→ 新分析（旧分析卡保留，可对比）
  └─ 点画笔图标 ──→ 退出绘制模式，回 view
```

**与其他形式的关系**：这是"图表引擎"（04 号文档 chart/model 纯函数层）的交互增强——坐标计算、命中检测已在 model 层（issue #1477 方法论），画线只是把"几何输入"转成 model 可消费的数据。与场景模拟器配合：画完趋势线，拨杆"如果跌破支撑位"，AI 在当前分析上继续推演。

**工程要点**：

- 核心是 `ChartGestureLayer`：叠加在 Canvas 上的手势捕获层，输出"线/框/点"三类几何对象（纯数据）
- `GeometryParser`（纯函数）把几何对象转成分析请求上下文："两点连线 = 计算区间涨跌 + 拟合趋势线斜率"等
- AI 请求复用 ADR-11：只注入几何对应的真实行情数据，LLM 输出定性分析
- 可撤销栈是 `List<GeometryObject>` 的 push/pop，纯数据可单测

**排期**：P1（M5 增强项，依赖 M4 图表引擎完成后）。差异化最强，是"把图表变成可对话画布"的核心设想，评审亮点候选；工期紧可整项裁剪。

## 8. ⑤ 场景模拟器 WhatIfSimulator

**定义**：AI 回答顶部一组快速拨杆 chip："如果明天涨 3%" / "如果跌破支撑位" / "如果北向资金流入 50 亿" / "如果降息落地"。拨一下，AI 在**当前分析上下文上叠加推演**——不是重新问，而是在已有归因基础上算"会发生什么"。

**适用场景**：归因卡/洞察卡之后的自然延伸（看完"为什么跌"，立刻想知道"什么情况下会反转"）；风险预演（"如果明天大盘跌 2%，我的持仓会怎样"——配合持仓锚定⑦）。

**触发与手势**：

- 回答中带归因/洞察卡时，卡片下方渲染"如果…"拨杆行（2-3 个由 AI 协议生成的假设项）
- 点击拨杆 → 该假设项展开为推演子卡（`WhatIfCard`），AI 流式生成推演内容
- 推演子卡可再叠加第二层假设（"如果跌破支撑位"+"且北向流出"）
- 点击拨杆外的其他区域 / 新回答到达 → 推演子卡收起

**视觉规范**：

- 拨杆 chip 用虚线描边（与追问 chips 的实底/描边体系区分，语义 = "假设"而非"提问"）
- 推演子卡顶部一条 2dp 虚线 + 「假设」标签，与事实内容明确区分——**推演 ≠ 预测，视觉上必须诚实**
- 推演结果中的数字（"预计影响 PE 至 18.5"）用浅色而非主数字色，弱化确定性
- 推演卡底部固定脚注："以上为情景推演，非预测，不构成投资建议"（合规）

**状态转换**：

```
answer(含归因/洞察卡)
  ├─ 渲染拨杆行（AI 协议生成假设项）
  ├─ 点拨杆 A ──→ WhatIfCard(假设A) 展开，AI 流式推演
  ├─ 推演中可再点拨杆 B ──→ 叠加假设 B（假设栈，可回溯）
  ├─ 点推演卡外 ──→ 收起
  └─ 新回答到达 ──→ 拨杆行替换为新假设项
```

**与其他形式的关系**：场景模拟器是"嵌套对话展开"（06 号文档 4.4）的轻量变体——同样"展开即深聊"，但更克制：不开放自由输入，只允许在 AI 预生成的假设项中选择。好处：① 不产生自由对话分支（状态简单）② 假设项由 AI 生成（与场景契合）③ 天然防止"诱导预测"的合规风险（假设边界由 AI 框定）。

**工程要点**：

- 协议扩展：AI 回答的响应中新增 `whatIfs: [{"id","label","params"}]` 字段，拨杆由协议驱动（复用 suggestions 机制，见 02 号文档 #08）
- 推演请求 = 追加一条携带假设参数的 AI 调用，System Prompt 注入当前归因上下文 + 假设条件（"这是假设推演，输出情景分析，禁止确定性表述"）
- 假设栈是纯数据（`List<WhatIfParam>`），可撤销
- 成本：单次推演 ≈ 单次问答（0.008 元），演示可负担

**排期**：P0/P1 边界——拨杆渲染 + 单层推演为 P1-M5 轻量项（约 1 人日）；双层假设栈可裁剪。

## 9. ⑥ 行情脉搏 MarketPulse

**定义**：屏幕边缘一条极细的呼吸光带——大盘涨时暖色缓脉、跌时冷色急脉、成交量放大时节奏加快。不用看数字，市场"喘气的节奏"就在视线余光里。完全在注意力外缘，不打扰阅读。

**适用场景**：聊天阅读长回答时对大盘的持续感知；盘后复盘时的市场情绪底色；演示时的氛围营造。

**触发与手势**：无主动触发——**环境层常驻，零交互**。这是七个设想中唯一不依赖手势的（它服务于"手势场景"的情绪背景）。

**视觉规范**：

- 位置：屏幕顶部边缘一条 2-3dp 光带（不遮挡内容区）
- 颜色映射：涨跌家数比 > 1 → 暖色（riseColor 系）缓脉（周期 ~2s）；< 1 → 冷色（fallColor 系）急脉（~1s）；接近 1 → 中性灰平缓
- 亮度/节奏：成交量放量时光带更亮、脉搏更急促
- 仅动画 opacity（呼吸感），不动画颜色/位置——性能安全（宪章：只动画 transform 与 opacity）
- 深色/浅色主题下均可适配（光带颜色取 theme token）

**数据来源与降级**：涨跌家数比来自腾讯接口快照批量查询（ADR-6 实测支持多标的批量，可一次拉 50-100 个代码统计），失败走 Mock 数据（不阻塞主流程）。**状态点（在线/缓存/离线）同样适用于光带**——离线演示时光带用 Mock 情绪数据，不误导。

**与其他形式的关系**：感知层与操纵层正交——它不抢占任何手势，只是让用户"始终知道大盘在喘什么气"。与情绪温度计（02 号文档 #14）的区别：温度计是显式组件（可点击、有数字），脉搏是隐式氛围（无数字、不打断）。

**工程要点**：

- `MarketPulseLayer` 页面级覆盖层，聊天页/详情页共用
- 数据源 `PulseProvider`（涨跌家数比 + 量能），60s 缓存轮询
- 纯函数 `PulseMapper.map(advanceDecline, volume)` → `(color, period, alpha)`，可单测
- 可一键关闭（设置页开关，尊重用户专注）

**排期**：P2。实现成本极低（一个覆盖层 + 一个纯函数），但属于"锦上添花"，优先保障 P0/P1 后再做。

## 10. ⑦ 持仓锚定 PositionAnchor

**定义**：长按任意股票实体，选择"这是我的持仓"。之后所有 AI 回答中涉及该标的的内容会**微妙高亮**——不是红色边框那种粗暴方式，而是字重/背景色微调。对话变成"持仓感知"的：你问大盘新闻，AI 回答时自然关联到你的持仓。

**适用场景**：持仓相关提问（"我的茅台跌了要不要看" → AI 知道茅台是你的持仓，回答主动关联持仓成本、浮盈浮亏）；多标的回答中的优先级（回答同时提茅台和五粮液，你的持仓标的排前面、高亮）；盘后复盘（配合时间轴②看持仓那天发生了什么）。

**触发与手势**：

- 长按回答文本中的股票实体 → 弹出操作浮层（现有 Context Bar 的扩展）：「设为持仓」/「移除持仓」
- 设为持仓后，该实体 chip 增加一个微小的持仓标记（如 2dp 圆点 + 持仓成本角标）
- 之后该标的出现在任何 AI 回答中 → 实体渲染为持仓态（字重 + 背景微调 + 持仓标记）

**视觉规范**（克制原则，宪章一落地）：

- 持仓态 = 实体文字加粗 + 背景 8% 透明度品牌色圆角底 + 2dp 圆点标记
- 不使用高饱和边框、不加动画、不加音效——高亮是为了"让用户注意到"，不是"炫耀持仓"
- 持仓成本/浮盈浮亏显示在详情页行情头部（点击持仓态实体可展开）
- 涨跌色语义不变（持仓态与涨跌色正交，可叠加）

**状态转换**：

```
unset(普通实体)
  ├─ 长按实体 ──→ 操作浮层（Context Bar + 「设为持仓」）
  ├─ 设为持仓 ──→ anchored(持仓态渲染)
  ├─ 长按持仓实体 ──→ 「移除持仓」→ 回 unset
  └─ anchored 态下新回答含该标的 ──→ 自动持仓态渲染
```

**与其他形式的关系**：持仓锚定是"实体高亮"（02 号文档 #06）的增强——实体高亮解决"识别"，持仓锚定解决"个性化"。与场景模拟器⑤配合最强：持仓 + 假设 = "如果明天跌 3%，我的持仓会怎样"（个性化风险预演，这是通用 AI 助手做不到的）。与数据模式无关，纯端侧本地状态（存 DataStore）。

**工程要点**：

- `PositionStore`（本地持久化 `Set<symbol> + 成本价`，DataStore/文件，ADR-10 同栈）
- 渲染增强在 `EntityRichText` 层：持仓态是实体渲染器的一个装饰器（`PositionDecorator`），不侵入识别逻辑
- AI 上下文注入：System Prompt 携带持仓列表（"用户的持仓：600519（成本 1200 元）"），LLM 输出时自然关联
- 隐私注意：持仓只存本地，不上传；AI 调用时注入属于产品设计（可设置关闭）

**排期**：P1（M5，顺手项）。改动集中在现有实体高亮 + Context 注入，约 1 人日，性价比高——直接补上"个性化"这块通用聊天产品没有的体验。

### 11.1 对三流合一模型的扩展

| 流 | 职责 | 新增设想 |
|---|---|---|

| ③ 联动层 | 瞬时预览 | 场景模拟器⑤（回答顶部叠加）、行情脉搏⑥（环境感知层） |
| （新）场景层 | 历史与推演 | 时间轴回溯②、手势画线④ |

### 11.2 与 06 号文档的关系

- **渐进披露（06）解决"一张卡怎么深入"**：手风琴/递进下钻/底部 Sheet
- **手势设想（07）解决"多张卡怎么操纵"**：堆叠切换 / 拖拽关联 / 画线分析
- 二者正交，可自由组合：堆叠中单击 → 该卡渐进披露；归因卡递进下钻 → 底部拨杆场景模拟
- 组合规则：**一个交互动作只改变一个维度**（要么切卡，要么展开，要么推演），避免手势/状态机爆炸

### 11.3 与 Context Bar 的关系

Context Bar 是"长按实体 → 瞬时预览"，拖拽关联是"长按卡片 → 拖移关联"——共用同一套长按识别（350ms + 移动阈值 8dp），语义不同：前者是"瞟一眼"，后者是"连一连"。工程上共用手势识别器，落点语义各自注册。

## 13. 风险与克制设计

### 13.1 手势冲突防御

| 冲突场景 | 防御策略 |
|---|---|
| 长按 vs 列表滚动 | 长按延迟 350ms + 移动阈值 8dp 取消（沿用 Context Bar 策略） |
| 堆叠翻卡 vs 列表滚动 | 堆叠内部滑动独立手势域，边界事件交还列表 |
| 拖拽 vs 卡片点击 | 拖拽前移动超阈值则取消点击语义（抬起≠点击） |
| 画线 vs 图表平移/缩放 | 绘制模式独占手势域，退出绘制模式恢复图表手势 |
| 时间轴拖动 vs 回答流式更新 | scrubbing 期间冻结卡片 diff（快照态不随实时数据跳动） |

### 13.2 状态机克制（防爆炸）

- 每个手势只绑定**一种语义**：长按实体=预览、长按卡片=拖拽、图表绘制=分析——不允许多义手势
- 每个设想的主路径状态 ≤ 4 个（idle/active/result/cancel 模式）
- 手势与手势不叠加：一次只能处于一种手势状态（全局手势仲裁器）

### 13.3 克制设计（宪章一落地）

| 设想 | 克制点 |
|---|---|
| 场景模拟器 | 推演 ≠ 预测：视觉虚线区分、脚注合规、假设项由 AI 框定（防诱导） |
| 行情脉搏 | 只动画 opacity；可一键关闭；数据模式状态点同样适用（不伪装） |
| 持仓锚定 | 高亮用字重/背景微调，无边框无动画；持仓只存本地 |
| 全部手势 | 每个手势都有文字等价物（可撤销、可学习、可演示） |

### 13.4 无障碍

- 所有手势动作提供非手势等效入口（按钮/文字说明）——画线有"区间选择"按钮替代，拖拽有"添加对比标的"按钮替代
- 减弱动效（prefers-reduced-motion）下：翻卡/连线/推演动画 → 直接状态切换
- 屏幕阅读器对持仓态播报"这是你的持仓"；堆叠牌组播报"第 N 张，共 M 张"
