## 1. 这份规范解决什么问题

当前 `ChatPage.kt` 里对 `@` 和 `/` 的处理只有两个函数，加起来不到 30 行：

```kotlin
// ChatPage.kt L1051
private fun updateInputPanel(text: String) {
    inputPanel = when {
        text.trimStart().startsWith("@") -> InputPanel.SYMBOL
        text.trimStart().startsWith("/") -> InputPanel.COMMAND
        else -> InputPanel.NONE
    }
}

// ChatPage.kt L1333  InputAssistantRow：候选是写死的 3 条
InputPanel.SYMBOL  -> listOf("@贵州茅台", "@五粮液", "@上证指数")
InputPanel.COMMAND -> listOf("/复盘", "/对比", "/解读")
```

### 1.1 缺陷清单（按严重度排序）

| # | 缺陷 | 现状表现 | 根因 |
|---|---|---|---|
| D1 | **触发只认首字符** | 输入"帮我看看@"没有任何联想；只有整段文本以 `@` 开头才触发 | 用 `text.trimStart().startsWith("@")` 判定，没有光标/词法概念 |
| D2 | **候选写死** | 永远只有茅台/五粮液/上证指数 3 条，与用户输入无关 | 没有接入搜索/缓存数据源，没有过滤与排序 |
| D3 | **无 token 固化** | 选中 `@贵州茅台` 只是把字符串塞进输入框，`@` 还是普通文本，删一个字符就变成 `@贵州茅` | 没有用 Kuikly 的 `InputSpans`，提及不是原子单元 |
| D4 | **发送无结构** | 发送的是纯文本，服务端意图全靠 `EntityRecognizer` 发送后再猜 | 输入期意图与发送期识别两条管线没有对齐 |
| D5 | **无退出规则** | 输入 `@茅台 好不好` 空格后联想面板仍然挂在上面（只要文本仍以 @ 开头） | 没有 terminator（空格/删除/失焦）概念 |
| D6 | **无消歧** | "白酒"匹配 20 只股票时无任何机制；同代码多市场（A/H/美）无区分 | 无候选排序与"多匹配聚合"设计 |
| D7 | **指令无参数** | `/对比` 是纯文本，不引导用户补全"对比谁和谁" | 无命令注册表与参数 schema |
| D8 | **无拼音匹配** | 输入 `@moutai` 无结果 | 未启用 Kuikly `enablePinyinCallback` 与拼音索引 |
| D9 | **无键盘导航** | 面板只能点按，无法上下键/确认键操作 | 未处理 selection 键盘事件 |
| D10 | **@ 与 / 互斥且与 MEDIA 冲突** | `InputPanel` 是单枚举，拍照面板与联想面板不能共存 | 面板维度未拆分（见 §3.4） |

### 1.2 设计目标

> **`@` 与 `/` 不是"快捷输入"，而是「输入即结构化」的两条入口。**
> 用户在敲键盘的那一刻，系统就知道他在指哪只股票、在调哪个指令——而不是等发送后再去猜。

- **G1 光标即真相**：一切触发判定以光标位置的词法状态为准，与整段文本无关。
- **G2 选中即固化**：候选一旦被选中，变成不可分割的原子 token（chip），发送时携带结构化数据。
- **G3 零上下文丢失**：触发、过滤、固化、编辑、删除的全过程不破坏输入框其余草稿。
- **G4 指令即协议**：`/` 命令有注册表、参数 schema 与执行路径，未知指令优雅降级为普通文本。

## 2. 技术底座：Kuikly 2.25 TextArea 能力盘点

已核对 `core-2.25.0-2.1.21-sources.jar`，以下能力可用于当前输入栏改造；其中 `inputSpans` 不是 range API，且 H5/原生表现不一致，详见 §11.2：

| 能力 | API | 用途 |
|---|---|---|
| 选区回调 | `TextAreaEvent.selectionChange` → `onSelectionChange` | 每次光标移动拿到 `cursorIndex`，触发判定的数据源 |
| 组合输入回调 | `enablePinyinCallback` + 拼音回调事件 | 中文输入法组合态期间**暂停**触发判定，避免拼音串误触发 |
| 富文本 span | `TextAreaAttr.inputSpans(InputSpans)`；`InputSpan` 以连续文本片段表达样式 | token 视觉固化的潜在载体，但不能按 start/end 局部打 span |
| 状态回写 | `setTextInputState(state)` / `getTextInputState()` | 选中候选后替换文本区间并保持光标位置 |
| 受控设置 | `setText(text)`（内部维护 cursor 一致性） | 替换触发区间 |

**关键结论**：触发、候选、结构化发送、参数态可以用现有 API 稳定实现；视觉 chip 与退格整删需要在真机上验证 `inputSpans` 同步语义后再接入。

## 3. 核心概念模型

### 3.1 Trigger Session（触发会话）

从用户敲下触发字符（`@` 或 `/`）到该次触发被终结（选中/中止/删除）之间的一段状态。**同一时刻最多存在一个活动 Trigger Session。**

```
TriggerSession {
  type: AT | SLASH
  triggerStart: Int      // 触发字符在文本中的偏移
  queryStart: Int        // = triggerStart + 1
  cursor: Int            // 当前光标（必须 > queryStart 才有效）
  query: String          // text[queryStart until cursor]，组合态期间冻结
  solidified: Boolean    // 该区间是否已固化为 token
}
```

### 3.2 词法判定算法（替代 startsWith）

**每次 `textChanged` / `selectionChange` 时运行**，从光标位置向左扫描：

```
fun detectTrigger(text: String, cursor: Int, composing: Boolean): TriggerSession? {
  if (composing) return null                        // 拼音组合态：冻结判定，见 §3.5
  if (cursor == 0) return null
  // 1. 从光标向左找触发字符，途中只允许「词内字符」
  var i = cursor - 1
  while (i >= 0) {
    val c = text[i]
    if (c == '@' || c == '/') {
      // 2. 触发字符的前一个字符必须是「边界」：空串/空白/行首/换行/已固化 token 尾部
      val prev = if (i == 0) ' ' else text[i - 1]
      return if (prev.isWhitespace()) TriggerSession(type = …, triggerStart = i, cursor = cursor)
             else null                               // "abc@def" 里的 @ 是邮箱，不触发
    }
    if (c.isWhitespace()) return null               // 遇到空白：光标不在触发词内，无会话
    i--
  }
  return null
}
```

**边界规则（硬性）**：

| 场景 | 判定 | 理由 |
|---|---|---|
| `@茅台`（行首） | ✅ 触发 | 前驱是边界 |
| `帮我看看@茅台` | ✅ 触发 | `@` 前是空白 |
| `abc@163.com` | ❌ 不触发 | `@` 前是词内字符（邮箱） |
| `@茅台 空 格` | ❌ 触发中止 | 光标越过了空白（terminator，见 §3.3） |
| `@@茅台` | 第二个 `@` 触发，第一个作废 | 向左扫描命中最近一个 |
| 已固化 token 后直接打 `@` | ✅ 触发 | 固化 token 尾部视同边界 |

### 3.3 Terminator（终结符）

活动会话在以下任一情况**立即中止**，面板收起、query 清空：

| 终结符 | 行为 |
|---|---|
| 空格 / 换行（光标越过） | 中止。已键入的 `@query` 保留为普通文本，**不**自动选中任何候选 |
| 删除到 `queryStart` 之前（把 `@` 也删了） | 中止 |
| 光标移出触发词区间（点按/长按移动光标） | 中止 |
| 输入框失焦且面板非固定 | 中止（遵循 09 规范的粘滞闩锁，输入态本身不退出） |
| Esc / 收起面板按钮 | 中止，保留文本 |
| 组合态开始（进入拼音预输入） | **冻结**（非中止）：面板显示"输入中…"状态，组合结束重新判定 |

**空格不自动选中（与 Slack 一致，与飞书不同）**：自动选中在股票场景是危险的——拼音没打完、候选还没看清，一个空格就把错误标的固化了。中止后面板消失，用户可删掉重来，成本低于错误固化。

### 3.4 面板维度拆分（修复 D10）

`InputPanel` 从单枚举拆为两个正交维度：

```
assistantPanel: NONE | TRIGGER         // @ / 触发产生的联想面板（键盘在屏时）
mediaPanel:     Boolean               // 拍照/相册面板（键盘收起时）
```

互斥规则：`mediaPanel = true` 时强制 `assistantPanel = NONE`（拍照片和选标的不会同时发生）；关掉媒体面板回到输入态时，若光标仍在触发词内，**重新运行词法判定**恢复联想。

### 3.5 拼音组合态（修复 D8）

- 开启 `enablePinyinCallback`。
- 组合态期间：`composing = true`，`detectTrigger` 返回 null 之外**不清除**已活动会话，只是把 query 冻结在组合开始前的值，面板顶部显示"拼音输入中"细条。
- 组合结束（上屏）：用上屏后的文本重新判定。这样 `@maotai`（拼音串上屏后）与 `@茅台`（直接中文）走同一条管线。
- **拼音索引匹配**在候选层做（§4.3），不在触发层做——触发层永远只看上屏文本。

## 4. @ 提及详细设计

### 4.1 触发与面板出现

1. 用户键入 `@`（满足 §3.2 边界规则）→ 创建 TriggerSession，`query = ""`。
2. 面板**立即**展开（150ms 内），键盘不收起。面板出现动画：从输入栏下缘向上 8dp 位移 + fade in，时长 180ms，与 09 规范的辅助区动画一致。
3. 首屏（`query = ""`）内容 = **推荐序列**（§4.2），不是空白。这保证"敲一下 @"就有价值。

### 4.2 候选数据源与合并排序（修复 D2）

五个数据源，按优先级合并去重（以 symbol 为 key）：

| 优先级 | 数据源 | 内容 | 延迟要求 |
|---|---|---|---|
| S1 | `recentMentions` | 本会话最近提及过的标的（内存，最多 5 条） | 0ms |
| S2 | `watchlistCache` | 自选股本地缓存（最多 10 条） | 0ms |
| S3 | `hotIndex` | 内置指数：上证、深成、创业板、科创50、恒生、纳指、标普 | 0ms |
| S4 | `searchCache` | 最近一次搜索结果的本地缓存（TTL 5 分钟） | 0ms |
| S5 | `QuoteRepository.search(query)` | 当前为本地标的搜索入口；待 `QuoteProvider` 增加远端 search 后合并在线结果 | 本地 0ms；远端目标 < 300ms，超时显示"网络搜索中…" |

**空 query 的推荐序列** = `recentMentions` + `watchlistCache` + `hotIndex`，按此顺序拼接、去重、截断 12 条。

**非空 query 的排序公式**（每个候选打分，降序）：

```
score = 60 × 命中等级权重
      + 15 × min(热度分位, 1.0)          // 成交额/搜索热度分位，等比
      + 10 × (是否 recentMention ? 1 : 0)
      + 10 × (是否 watchlist ? 1 : 0)
      + 时效惩罚：每超过 50ms 的响应延迟 -1（本地缓存永远排前）

命中等级权重（对 query 的匹配方式，取最高者）：
  1.00  代码全等        "600519" → 600519.SH
  0.95  简称前缀全等    "贵州茅台" → 贵州茅台
  0.90  简称包含        "茅台" → 贵州茅台 / 茅台集团…
  0.80  拼音全拼前缀    "maotai" → 贵州茅台
  0.70  拼音首字母      "mt" → 贵州茅台 / 美的集团(meide? 否)…
  0.60  概念/板块词     "白酒" → 白酒板块聚合项（见 §4.4）
  0.40  别名/曾用名     "宁王" → 宁德时代
```

**同分数稳定性**：按 symbol 字典序兜底排序，保证本地缓存与远端结果到达先后不同时列表不跳动。

### 4.3 拼音索引

- 标的简称预生成 `pinyinFull`（全拼）与 `pinyinAbbr`（首字母）两列，随标的缓存落库（`Security` 实体新增两个可选字段）。
- 索引来源：内置 Top 3000 标的离线包（Demo 阶段可只内置 500）；其余标的仅支持简称/代码匹配。
- 匹配大小写不敏感；`query` 含中文字符时跳过拼音路径。

### 4.4 消歧与聚合（修复 D6）

**同代码多市场**：直接列为独立候选，行内右侧灰字标注市场（`贵州茅台  600519.SH` / `贵州茅台  600519.SH 已列`——实际按 symbol 去重后不会出现同代码；跨市场不同代码如 `比亚迪 002594.SZ` / `比亚迪集团 01211.HK` 是两条）。

**概念/板块聚合项**（命中等级 0.60）：当 query 命中概念词（如"白酒""新能源车""中特估"）时，插入一条特殊候选：

```
◧ 白酒 · 板块（共 68 只）     [板块]
```

选中聚合项 → 固化为 `@白酒(板块)` token，发送时展开为板块成分列表（取流通市值前 10）附在 prompt 上下文，不在输入框里展开 68 个名字。

**多匹配不自动聚合个股**：宁缺毋滥，避免"帮我看看@银行"被静默替换成某一只银行股。

### 4.5 候选面板 UI

```
┌──────────────────────────────────────┐
│ @ 标的                          ✕ 关闭│  ← 32dp 标题行；✕ = Esc 中止
├──────────────────────────────────────┤
│ ▸ 贵州茅台   600519.SH  沪A  ●+2.1% │  ← 48dp/行
│   五粮液     000858.SZ  深A    -0.3% │     候选序号隐含
│   白酒 · 板块（共 68 只）        [板块]│     ↑↓ 键盘高亮行
│   …（最多同时渲染 12 行，滚动）        │
├──────────────────────────────────────┤
│ 拼音输入中…                           │  ← 仅组合态时显示，20dp
└──────────────────────────────────────┘
```

行结构（左右对齐）：
- 左：候选名（15sp 常规）；命中片段**加粗**（"贵州**茅台**"）
- 右：代码（12sp 灰）· 市场 tag · 实时涨跌（**红涨绿跌**，无行情时不显示）
- 板块聚合行：左侧◧图标 + "板块"胶囊
- 选中态：背景 `brandSoft` + 左缘 3dp 品牌色条
- 面板高度：`min(行数 × 48dp + 52dp, 键盘上方可用高度的 45%)`，超出滚动

**键盘导航**：↑↓ 移动高亮（循环），Enter/发送键 → 高亮行若有则固化该候选（无高亮则正常发送），Tab = 下一个数据源分组。每次高亮移动触发轻微 haptic（`bridge.hapticLight()`）。

### 4.6 Token 固化（修复 D3）

选中候选（点按或 Enter）后：

1. **替换区间**：把 `text[triggerStart until cursor]`（即 `@query`）替换为 `@候选名`，用 `setTextInputState` 一次性写入，同时设置：
2. **加 span**：对 `[triggerStart, triggerStart + 候选名.length + 1)` 区间设置 `InputSpan`（品牌色前景 + `brandSoft` 背景 + 圆角效果——span 支持样式随渲染端，Demo 阶段先做前景色）。
3. **光标落位**：光标移到 token 右侧紧邻处。
4. **写入 registry**：`solidTokens += SolidToken(range, MentionEntity(symbol, name, type))`。
5. **会话结束**：面板收起（180ms 反向动画），`triggerSession = null`。
6. **光标后自动补一个空格**：仅当 token 右侧原本不是空白/结尾时，避免"固化后继续打字粘在 token 上"。

固化 token 的**原子性**：
- **退格删除**：光标紧贴 token 右侧按退格 → 整个 token 一次性删除（连同 `@`），span 与 registry 同步清理。不做"删一个字变成 @贵州茅"。
- **光标进入 token 内部**（点按/方向键）：token **暂时软化**——文本不变，但该 token 从 registry 标记为 `editing`，再次失焦/移出时若文本未被改动则恢复固化；若被改动则按普通文本处理（下次重新触发识别）。
- **选中 token 的一部分**：允许系统级选择（复制场景），但发送前会做 token 完整性校验（§4.8）。

### 4.7 多提及并存

- 无上限（软上限 8，第 9 个固化时面板顶部黄条提示"提及较多，建议聚焦"）。
- 每个 token 独立维护 range；**任何文本编辑后统一做 range 偏移补偿**（在光标左侧插入/删除 n 字符 → 右侧所有 token range ±n）。
- 输入框上方不额外渲染 chip 列表——token 本身就是 chip（span 即所见），避免双份状态。

### 4.8 发送协议（修复 D4）

```kotlin
data class SendPayload(
  val text: String,                    // 原文（含 @xxx 文本），用于 UI 气泡回显
  val mentions: List<MentionEntity>,   // 输入期固化的结构化提及
  val command: CommandInvocation?,     // §5 的指令调用，可为空
)

data class MentionEntity(
  val symbol: String,                  // "600519.SH" / "BK0477"（板块）
  val name: String,                    // "贵州茅台" / "白酒"
  val type: MentionType,               // STOCK / INDEX / BOARD / ETF
  val mentionText: String,             // "@贵州茅台"（用于与文本对账）
)
```

**发送前三道校验**（任一失败则降级，不阻塞发送）：
1. **range 对账**：每个 registry token 的 range 处文本 == `mentionText`。不等（用户手动改过）→ 该提及剔除，回退到 EntityRecognizer 识别。
2. **完整性**：mentions 数与文本中 `@` 固化 span 数一致。
3. **去重**：同 symbol 重复提及只保留一个。

**服务端 prompt 组装**：`mentions` 直接写入 system context（"用户在本次提问中明确提及：600519.SH 贵州茅台…"），`EntityRecognizer` 降级为补充管线（识别回答内容里的标的，用于卡片渲染——这个用途保留）。

## 5. / 指令详细设计

### 5.1 命令注册表（修复 D7）

单一事实源，`CommandRegistry`：

```kotlin
data class SlashCommand(
  val id: String,                      // "compare"
  val name: String,                    // "对比"
  val icon: String,                    // 渲染用图标标识
  val desc: String,                    // 一句话说明（面板行副标题）
  val aliases: List<String>,           // ["vs", "duibi"]
  val params: List<CommandParam>,      // 参数 schema
  val execution: Execution,            // 执行路径
  val availability: (UserState) -> Bool = { true },
)

enum class Execution {
  PROMPT_TEMPLATE,   // 本地拼 prompt 模板后走正常发送（大多数命令）
  LOCAL_ACTION,      // 不发消息，纯端上动作（如 /clear）
  CONTEXT_ONLY,      // 不产生独立消息，只注入上下文标记（如 /深水区）
}

data class CommandParam(
  val key: String,                    // "left"
  val label: String,                  // "标的 A"
  val type: ParamType,                // SECURITY / TEXT / ENUM / DATE
  val required: Boolean,
  val enumOptions: List<String> = emptyList(),
  val placeholder: String,            // "输入代码或名称"
)
```

### 5.2 触发与退出

- 词法判定与 §3.2 完全一致（`/` 同样要求前驱是边界——`https://` 中的 `//` 不触发，因为第一个 `/` 前是词内字符）。
- **额外规则**：query 中出现空格即终结命令名匹配阶段（`/复盘 贵州茅台` 中 `/复盘` 已定型），进入参数阶段（§5.4）。
- `/` 面板在空 query 时展示**全部可用命令**（按使用频次排序，频次为 0 时按注册顺序）；非空 query 按名称/别名前缀过滤。

### 5.4 参数态（核心新增）

选中带参命令后，输入框下方出现**参数槽位条**：

```
┌─────────────────────────────────────┐
│ /对比  贵州茅台 ⌶ __标的B__  维度▾    │
└─────────────────────────────────────┘
  ↑已完成    ↑当前焦点槽      ↑可选槽
```

规则：
- 每个参数一个**槽位胶囊**：已填=实底（可点按重填），当前=输入指示（光标闪烁轮廓），未到=虚线灰。
- 当前槽的类型决定联想行为：`SECURITY` 类型槽**复用 @ 的候选管线**（§4.2–4.5 完整套用，只是不需要敲 `@`）；`ENUM` 槽弹出选项胶囊；`TEXT` 槽无联想。
- 必选槽全部填满前，**发送键置灰**，点击发送键时缺失槽抖动提示（120ms × 2）。
- 可选槽可整段跳过（点"跳过"或直接发送）。
- 参数态下 `@` 仍然可用（参数外的正文提及），两个体系互不干扰。

### 5.5 执行路径

```
选中/发送
   ├─ Execution.LOCAL_ACTION  → 直接执行端上动作，输入框清空，不产生消息
   │                            （/清屏 直接 collapse + 清 messages）
   ├─ Execution.CONTEXT_ONLY  → 设置上下文标记，输入框保留（用户继续补正文），
   │                            输入框上方出现常驻标记条「深水区模式 · 点击取消」
   └─ Execution.PROMPT_TEMPLATE
        → localRender(template, params, mentions) 拼出最终 prompt
        → SendPayload(command = CommandInvocation(id, args, renderedPrompt))
        → 正常 send()，用户气泡显示「/对比 贵州茅台 vs 五粮液」人话形式，
          不显示渲染后的长 prompt
```

### 5.6 未知命令处理

输入 `/foo` 无匹配时：
1. 面板显示"没有找到 `/foo`"一行 + 最近似命令建议（编辑距离 ≤ 2）。
2. 用户直接发送 → **降级为普通文本发送**（不弹错误），但 prompt 组装时加一句系统注记"用户尝试了未知指令 foo"。
3. 绝不阻塞发送。`/` 体系是增强，不是关卡。

3. `triggerSession == null` 或其区间不与任何 solidToken 重叠。
4. `assistantPanel 可见 ⟺ triggerSession != null 或 paramState.active`。

## 7. 边界用例清单（验收时逐条过）

### 触发判定
1. `@` 打在句中（前有空格）→ 触发；打在 `abc` 后 → 不触发
2. `https://example.com` → 不触发（两个 `/` 前都是词内/非空白）
3. 输入 `//@茅台` → 触发（第二个 `@` 前是 `/`，属词内字符 → **不触发**；修正：`/` 非空白故不触发，符合预期）
4. `3/5 仓位` → 不触发
5. 光标移回已输入的 `@茅台` 词中间 → 恢复触发态（重新判定成功）
6. 全选删除 → 一切归零，面板收起
7. 粘贴含 `@茅台 ` 的整段文本 → 不触发（粘贴不产生逐键事件，仅在光标处判定一次；粘贴后光标在文本尾，若尾随 `@茅台` 则触发）

### 拼音
8. `@maotai` → 组合态中面板冻结，上屏后匹配"贵州茅台"
9. `@mt` → 首字母匹配，茅台在前
10. 组合态中按 Esc → 取消组合，session 恢复
11. 中英混输 `@贵州MT` → 简称包含 + 首字母组合匹配兜底

### 候选与固化
12. query 命中 0 结果 → 面板显示"没有找到『xxx』"+ 试试搜索/板块入口
13. 远端 300ms 未返回 → 先渲染本地缓存，返回后**列表不跳动**（§4.2 稳定排序）
14. 选中候选瞬间又收到迟到搜索结果 → 忽略（session 已终结）
15. 固化后立即退格 → 整 token 删除，不留残渣
16. 固化后在 token 前插入文字 → 右侧所有 token range 正确偏移
17. 删除 token 之间的普通文字跨多个 token → 偏移补偿正确
18. token 内部点击后修改一个字 → 软化，发送时对账失败，降级 EntityRecognizer
19. 同一标的提及两次 → 发送去重
20. 8 个以上提及 → 黄条提示
21. `@白酒` 选中板块聚合项 → token 固化为 `@白酒(板块)`，prompt 注入成分前 10

### 指令
22. `/对比 `（带空格）→ 命令名定型，参数槽出现
23. `/vs` → 别名命中"对比"
24. `/duib` → 拼音前缀命中
25. `/对比` 只填一个必选参数点发送 → 缺槽抖动，不发送
26. 参数槽 SECURITY 类型 → 不敲 @ 直接出标的候选
27. `/清屏` → 本地执行，不产生消息，输入框若非空则保留草稿
28. `/深水区` → 上下文标记条出现，继续输入正文
29. `/foo bar` 直接发送 → 降级普通文本
30. 指令 token 与 @ token 同存：`/解读 @贵州茅台 顺便提一下@五粮液` → command + mentions 各自正确
31. 发送后立刻再输入 `@` → 新 session 正常（上一条 payload 不残留）
32. 旋转/横竖屏或键盘高度变化 → 面板高度重算，session 保留

### 11.1.1 左下角按钮触发的实现要点

按钮只是"插入触发字符"，后续完全复用键盘输入的那套状态机，不另开分支：

1. **在光标处插入**：用 `composerCursor`（由 `selectionChange`/`textDidChange` 持续记录），
   而非无条件追加到末尾——用户可能正在句中编辑。
2. **前驱补空格**：光标前不是空白时先补一个空格，否则过不了 §3.2 的词法判定。
3. **原子写入文本 + 光标**：`TextAreaView.setTextInputState(TextInputState(text, cursor, cursor))`，
   不用已废弃的 `setText()`——后者会把光标重置到末尾。
4. **切换触发时先摘掉旧会话**：从 `@茅` 切到 `/` 时，先把旧会话区间删掉再插入，
   避免留下 `…@茅/` 这种脏片段。
5. **toggle**：再点同一个按钮即收起；若当前是命令参数态，收起时一并 `clearActiveCommand()`，
   否则会留下 `paramCommand != null` 但面板已关的不一致状态。

> 附带修正：`textDidChange` 的兜底光标原本写死 `it.text.length`，在句中插入时会用错光标、
> 把刚唤起的面板又判没。改为优先取 `composerCursor`（`selectionChange` 随后会用真实光标覆盖）。

### 11.1.2 面板高度：三行视窗 + 内部滚动

结论：**按候选数计算实际 `height()`，上限固定为 3 行，不用 `maxHeight`**。

中途曾用死定高 `height(176f)`，本意是"高度不跳动"，但实际观感很差——
候选只有 1–2 条（或空态）时，框里内容只占 36–46f，剩下的 130f 全是空白，
正是用户反馈的"全是大量空白"。定高在内容少时必然留白，这是它的固有代价。

随后试过 `maxHeight`，但 Kuikly 的 `Scroller` contentView 会按内容高度撑开，
实测压不住，候选列表仍会溢出遮挡其他区域。最终采用 `assistantPanelHeight(rowCount, rowHeight)`：
- 候选少 → 面板贴合内容，不留空白框；
- 候选多 → 高度封顶到 3 行，框内滚动，输入栏不会被无限顶高。

配套两条，进一步压低"面板 + 输入栏"的总高：
- 面板打开时输入框收紧为单行（`renderComposerTextArea(compact = assistantPanel != NONE)`），省约 36f；
- 面板打开时隐藏"最近标的"横条（面板本身已含"最近"数据源候选）。

### 11.1.3 候选行信息密度（对齐 HTML 原型）

早期版本每行只渲染"名称 + 代码 + 来源"三样，且是名称在上、代码在下的两行堆叠，
46f 的行高里显得稀疏。现改为单行横排五项，与 `docs/at-slash-preview.html` 一致：

```
[名称（匹配段着色加粗）]  [代码]  [市场]  [涨跌幅]  [来源]
贵州茅台               600519.SH  [沪A]   +2.8%   [自选]
白酒 · 板块            共 68 只   [板块]          [搜索]
```

- 涨跌幅是视觉锚点，也直接消掉了右端的空白感：红涨绿跌（中国习惯），
  数据来自 `CatalogEntry.chgPct`（板块无涨跌，用成分数量补位）。
- 匹配段着色由 `splitHighlight()` 切成前/中/后三段 Text 横排实现
  （Kuikly `Text` 不支持富文本，只能分段拼）。
- 代码、涨跌幅用定宽 + 右对齐，避免长名称把它们挤变形。

### 11.2 与设计有偏差的两项（受框架能力限制，已确认非实现疏漏）

**① 候选列表 ↑↓ 键盘导航、Esc 收起面板 —— 未接入**

核对 `core-2.25.0-2.1.21` 的 `TextAreaView` 事件列表，只有 8 个回调：
`textDidChange`、`textInputStateChange`、`selectionChange`、`inputFocus`、`inputBlur`、
`keyboardHeightChange`、`textLengthBeyondLimit`、`inputReturn`，**没有任何按键事件**（无 `keyDown`/`keyPress`）。
且四个目标端（Android/iOS/鸿蒙/H5）中移动端本身没有方向键，H5 也拿不到按键回调。
→ 候选选择改为纯点击；面板收起改由"删掉触发字符 / 光标移出 / 空格中止"自动完成。
保留 `atHighlight`/`slashHighlight` 用于高亮渲染，将来若框架补了按键事件可直接接上。

**② Token 视觉固化（高亮 chip + 退格整删）—— 未接入**

`TextAreaAttr.inputSpans()` 确有能力，但存在两端语义不一致：
- H5 渲染端 `KRTextAreaView` 完全不处理 `VALUES`，直接忽略（走 `ele.value` 纯文本）；
- 原生端 `InputSpan` 自带 `text`，span 与文本必须严格同序分区，一旦不同步会损坏输入框内容。

在无法真机验证的前提下贸然接入风险过高，故本轮只落地**发送侧对账**（`verify()`），
视觉固化待有真机验证条件时补做；届时实现要点：把全文按激活 token 切分成连续 span 分区，
每次 `textDidChange` 全量重算，并对 H5 保持"忽略即降级为纯文本"的兜底。

### 11.6 面板响应式重渲染修复（2026-09-10，R1/R7）

**真机根因**：三个子面板的内容都写在 `vif` 的普通 builder 闭包里——Kuikly `ConditionView`
的 creator 只在条件翻转时构建一次（`didCreated` 守卫），条件保持 true 期间内容永不重建。
面板挂载那一刻 `atCandidates` 还是空的，之后 `clear()+addAll()` 的任何更新都打在非响应式
闭包上 → @ 面板永远停在「没有可推荐的标的」，/ 参数面板打字期间槽位/进度全部冻结（单测
只测 rank 逻辑所以全绿，真机才暴露）。

修复（AGENTS.md R7 已归档）：

- `renderAtCandidateRows`：分支判定改三段 `vif`（组合态/空态/列表态）；候选行走
  `vfor({ atCandidates })`；空态文案在 `attr` 内响应式读 query。
- `renderSlashCommandRows`：同构处理（未识别/空态/列表态三段 vif + `vfor`）。
- `renderCommandParams`：内容包进单元素 `ObservableList<Int>`（`paramPanelRenderKey`）
  的 `vfor` 作整帧重建 key；bump 点 = `enterCommandParams`/`resumeCommandParamsOrClose`
  （每次按键）/`setComposerText`（点选与槽位重填路径）/远端建议到达/行情回填（`applyChgPct`）。
- 真机验证：小米 23116PN5BC 装包后复测 @gzmt，修复前复现「面板空态冻结」，修复后待设备
  回连复核（编译 + 全量单测已绿）。
