## 0. 为什么需要一套分析法，而不是一句「要有层次」

项目铁律 #5 已写明「层叠 > 卡片堆叠」，市场页 v2.0（doc 20）也是照此做的。但**它目前只是一句主张 + 一次成功案例**，没有可迁移的判定工具——所以自选页、术语表页仍然停在纯堆叠形态（实测：自选页 z 轴只有 1 层，N 行等高同构；术语表页同为 1 层）。

本文把「层次」拆成**四个可判定、可打分、可验收的维度**，合称 **LDRS 分析法**：

| 字母 | 维度 | 回答的问题 | 判据类型 |
|---|---|---|---|
| **L** | Layer 语义层 | 这块内容在回答用户的第几个问题？ | 遮蔽测试 / 一句话测试 |
| **D** | Depth 视觉层 | 视觉重量是否匹配语义层级？ | z 轴预算表 / 堆叠黑名单 |
| **R** | Relation 结构层 | 这块数据是「数量」还是「关系」？画出来了吗？ | 三元测试 / 关系-图形映射表 |
| **S** | Scan 行为层 | 3 秒 / 30 秒 / 3 分钟各能获得什么？ | 拇指遮挡测试 / 两次点击法则 |

**用法**：任一界面先按 L→D→R→S 顺序过一遍，每维 0–3 分，总分 12。**低于 8 分必须重构。** 打分结果写进评审记录，不是主观判断。

## 1. L · 语义层：问答链下沉法

### 1.1 方法

从用户**进入页面那一刻脑子里的问题**出发，逐层下沉。层级由「回答第几个问题」决定，不是由「内容多重要」决定。

```
Q0  用户的心智问题      「今天我的自选怎么样？」
      ↓
L1  结论层              一句话 + 一个主数字
      ↓ 用户自然追问
Q1  「凭什么这么说？」
      ↓
L2  证据层              2–3 个数字 + 1 条关系图
      ↓
Q2  「具体是哪只？」
      ↓
L3  明细层              逐条数据
      ↓
Q3  「这数准吗？什么时候的？」
      ↓
L4  元数据层            口径 · 来源 · 时间 · 数据模式
```

### 1.2 三条判定法则

| # | 法则 | 操作 | 不合格长什么样 |
|---|---|---|---|
| **L-1** | **遮蔽测试** | 遮住 L3/L4，用户仍能获得答案 | 遮住明细就答不上 → L1/L2 是空的 |
| **L-2** | **反向测试** | 遮住顶部 200px（L1 区），用户答不上来 | 遮住也无所谓 → L1 是废话 |
| **L-3** | **一句话测试** | L1 读出来不尴尬，且是**结论**不是**标签** | 「自选股 · 共 8 只」是标签，不合格；「8 只自选今日 −1.24%，多数跟随大盘回落」合格 |

**L-3 是最常犯的错。** 当前两个页的 `AppTopBar` subtitle 都是标签而非结论：

- 自选页：*"已关注 50 只上限内的标的，点进详情可继续追问"* → 描述的是**功能**，不是用户**此刻的状态**
- 术语表页：*"共 61 个常用概念，点击展开例子与进阶解释"* → 描述的是**操作**，不是**状态**

### 1.3 评分（0–3）

| 分 | 判据 |
|---|---|
| 3 | L1 结论存在且通过 L-3；L2 证据 2–3 个且含至少 1 条关系图；L3/L4 齐备 |
| 2 | L1 存在但偏标签；或 L2 缺失关系图 |
| 1 | 无 L1，只有 L3 明细 |
| 0 | 连 L3 都组织混乱，或 L4 口径缺失 |

## 2. D · 视觉层：z 轴预算分配

### 2.1 深度预算表

层次靠 **z 深度**造，不靠加盒子、加边框、加饱和色。

| z | 名称 | 手法 | 承载内容 | 同屏上限 |
|---|---|---|---|---|
| **z0** | 氛围底 | 双径向渐变，不可交互，高 160–200px | **L1 结论的容器** | 1 |
| **z1** | 衬后面板 | `opacity .9`，无 blur，**负边距被上层压住** | L3 明细 / 低显著性区块 | 2–3 |
| **z2** | 常规面 | `surface` + 1px `divider` + 阴影 sh1 | L2 证据 / 中等显著性区块 | 3–4 |
| **z3** | 主卡玻璃 | `marketGlass` + blur20 + 阴影 sh3 | **焦点对象**（最异常的那一块） | **1–2** |
| **z5** | 浮层 | 阴影 + 遮罩 | 交互态（sheet / peek / 搜索展开） | 按需 |

**造景深的三个手法（全部已验证于 doc 20 市场页）**
1. **负边距重叠**：上层下移 −18 ~ −22px 压住下层
2. **三级漫射阴影**：sh1（z2）`<` sh2 `<` sh3（z3），极轻，不硬边
3. **顶部 1px 高光发丝边**：`marketGlassEdge`

### 2.2 四条判定法则

| # | 法则 |
|---|---|
| **D-1** | 概览类页面同屏 z 层数 **≥3**；**z3 主卡 ≤2**（超过 = 没有焦点） |
| **D-2** | **等高同构块 ≤2** 个（第 3 个开始即判定为堆叠） |
| **D-3** | 层级只能由 **z 深度 + 字号/字重** 表达；**禁止**用边框粗细、饱和色数量、圆角大小表达层级 |
| **D-4** | 操作按钮**不常驻可见**：低频操作走左滑/长按，把视觉重量让给信息 |

### 2.3 堆叠黑名单（9 项，命中任意一项即判定「堆叠」）

> 与 doc 21 §4.3 的「AI 味黑名单」是两张独立清单，评审时分别走查。

| # | 黑名单项 | 为什么廉价 |
|---|---|---|
| 1 | **tile 方阵**（等宽等高网格 ≥4 格） | 完全放弃信息分级，把决策推给用户 |
| 2 | **3 个以上等高同构卡** | 同构即同权重，等于没有层次 |
| 3 | 用**边框粗细**表达层级 | 是加盒子不是造深度 |
| 4 | 用**饱和色数量**表达层级 | 破坏 doc 19 色彩语义（rise/fall/brand 各有专属含义） |
| 5 | **列表行右侧多个同构按钮并列** | 主次不分；操作与信息等权重 |
| 6 | 纯文字组头 + 每条一张卡 | 层级靠"分组"而非"深度" |
| 7 | **隐藏状态机**（点击循环切换多态，用户看不到全部选项） | 交互不可预测 |
| 8 | 数字用**非等宽字体** | tick 时布局抖动 |
| 9 | 平盘 / 停牌 / 非交易时段**不用 `flat` 灰** | 违背 A 股官方灰色语义 |

### 2.4 评分（0–3）

| 分 | 判据 |
|---|---|
| 3 | z 层数 ≥3；等高同构块 ≤2；黑名单零命中 |
| 2 | z 层数 = 2；或黑名单命中 1 项 |
| 1 | z 层数 = 2 且黑名单命中 2 项 |
| 0 | z 层数 = 1（纯堆叠）或黑名单命中 ≥3 项 |

## 3. R · 结构层：数量 / 关系判定

### 3.1 方法

对**每一个出现 ≥3 个并列数字的区块**提问：

> 这是一组**互相独立的数量**，还是一个**关系**？

- 若是**数量** → 可以罗列（但仍要问：它真的没有内部结构吗？）
- 若是**关系** → **必须画出来**，罗列即失败

**理由**：关系的本质是「数字之间怎么比较」，罗列把它变成用户的脑力劳动。项目铁律 #5 里「关系用可视化表达」说的就是这条。

### 3.2 关系 → 图形映射表

| 关系类型 | 图形 | 本文用法 |
|---|---|---|
| **部分-整体** | 分段比例条 / 堆叠条 | 自选涨跌家数、术语掌握状态、行业权重 |
| **排序 / 名次** | 等级条（条宽编码数值） | 相关性 Top5 配对、贡献度 |
| **对比** | 中心分界条 / 同轴双条 | 涨 vs 跌、组合波动 vs 大盘 |
| **分布** | 直方图 / 热力格 | 共现矩阵、涨跌幅分布 |
| **相关 / 重叠** | **共现矩阵热力**（明度编码） | 自选票两两相关性 |
| **变化 / 趋势** | 折线 / 残影对照 | 暴露历史快照 |
| **依赖 / 先后** | **有向路径 / 阶梯链** | **术语前置依赖（L2 知识）** |
| **时间轴** | 竖向时间线 | 未来 30 天事件（解禁/财报/减持） |

**明度编码原则**：强度类（相关性、热度、掌握度）**只用明度阶梯，不加饱和色**。饱和色在 doc 19 里已被 rise/fall/brand/term 占满，挪用会破坏语义。

### 3.3 两条判定法则

| # | 法则 | 操作 |
|---|---|---|
| **R-1** | **三元测试** | 凡 ≥3 个并列数字，必须能说出一个关系名（上表 8 选 1）。说不出 → 信息组织有问题，应合并或删除 |
| **R-2** | **一图胜三数** | 画出来后，若用户仍需逐个读数字才能理解 → 图选错了 |

### 3.4 评分（0–3）

| 分 | 判据 |
|---|---|
| 3 | 全部关系型数据已可视化；无一处「该画却罗列」 |
| 2 | 主要关系已画，次要关系仍罗列 |
| 1 | 仅 1 处关系可视化，其余罗列 |
| 0 | 零关系可视化（全部罗列） |

## 4. S · 行为层：3 / 30 / 180 秒法则

### 4.1 时间预算

| 时长 | 用户应获得 | 对应层级 |
|---|---|---|
| **3 秒** | 一个数字 + 一句话 | L1 |
| **30 秒** | 扫完证据块（2–4 个） | L2 |
| **180 秒** | 下钻到明细与口径 | L3 / L4 |

### 4.2 三条判定法则

| # | 法则 | 操作 |
|---|---|---|
| **S-1** | **拇指遮挡测试** | 用手遮住屏幕只露顶部 200px —— 这 200px 必须包含 L1 |
| **S-2** | **两次点击法则** | 主任务完成 ≤2 次点击（如：自选 → 风险地图 = 1 次） |
| **S-3** | **视觉重量 ∝ 语义层级** | L1 主数字 ≥30px/800；L2 数字 ≤20px；L3 数字 ≤16px。**字重必须单调递减** |

### 4.3 评分（0–3）

| 分 | 判据 |
|---|---|
| 3 | 通过 S-1 / S-2 / S-3 全部三条 |
| 2 | 通过两条 |
| 1 | 通过一条（通常是 S-3） |
| 0 | 顶部 200px 内无结论（S-1 失败）—— 搜索框、筛选器、标题占据首屏即此档 |

**两条实现约束**（踩过，见 `ChatScaffolding.kt` 头部注释与 `SwipeActionRow` 文档注释）：
- `animate()` 的 value 实参不参与判定，它绑定的是 `ReactiveObserver.currentObservablePropertyKey`
  （紧邻其左侧**最后读到**的 observable）。所以 offset 必须在 animate 实参位置**现场再读一次**。
- 动画注册是**每帧**的（`AnimationState.nextAnimations` 每轮 clear）。跟手阶段只要不调用
  animate 就天然直接落位，无需额外开关——这是「跟手 vs 吸附」能共存在一个 attr 闭包里的原因。
