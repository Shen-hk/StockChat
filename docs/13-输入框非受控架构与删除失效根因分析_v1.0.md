# 13-输入框非受控架构与删除失效根因分析 v1.1

## 文档定位

记录输入栏（Composer）从「受控双实例」到「非受控持久单实例」的架构结论，
以及「内容无法删除 / 退格错乱 / 光标消失」的根因链。本文是排障存档，
后续改动输入框数据流前先读本文与 MEMORY 的 Kuikly 编码坑条目。

依据：ChatPage.kt 业务代码 + Kuikly 2.25.0-2.1.21 Android 渲染层
（KRTextFieldView / KRTextAreaView）反编译字节码核实。

## 一、根因链：为什么删不掉

故障不是单点 bug，是两条缺陷叠加：

### 1. 受控 textInputState 绑定 → 回声循环（结构性不可救）

旧实现 `textInputState { currentComposerTextInputState() }` 把「草稿文本 +
估算光标 + 组合态」整体做成响应式 prop。故障链：

```
原生 textDidChange
  → 业务写 observable 草稿（+ 估算光标 + 清组合态）
  → textInputState 响应式绑定重放 setProp
  → 原生在 IME 组合态进行中被 setTextInputState 打断
  → 组合会话被杀 → 光标消失、退格删错（删的不是最后一个字）
```

框架自带的防回声守卫拦不住：`textDidChange` 注册路径不置
`isProcessingNativeEvent`，业务估算态与原生真实态永远
`hasSameEditingState=false`，守卫判定「业务要改文本」于是照写。

### 2. 条件挂载 / 挂载前 autofocus → focus/blur 乒乓 → IME 僵尸连接

最初实现默认态、输入态各挂一个 TextArea。第一轮修复改成
「折叠态假输入条 + 展开态才 vif 挂真 TextArea + autofocus」，仍然没有
解决生命周期问题：Kuikly `createRenderView()` 会在原生 View attach 到窗口前
执行 `focus()`。真机日志为：

```
12:17:33.865 render TextArea
12:17:33.906 inputFocus
12:17:33.931 inputBlur   // 25ms 后，无任何用户操作或文本回调

InputMethodManager.mServedView 仍指向该 KRTextAreaView，但 Activity view dump 中它已不再
focused，即键盘持有残留 InputConnection，光标却不在输入框。
```

「无法删除」的主凶就是这个假聚焦连接：退格交给 IME/InputConnection，
但屏幕上的 EditText 已不是真正焦点。不应再增加 keyDown 拦截来补救。

## 二、修复后的架构（现行）

| 决策 | 实现 | 理由 |
|---|---|---|
| 非受控 | `text(mountSeed)` 仅作挂载种子，不绑定任何响应式文本 prop | 斩断回声循环 |
| 持久单实例 | 真 TextArea 从页面挂载到销毁始终存在且不换父节点；折叠/展开只切周边按钮与尺寸 | 杜绝 attach 前聚焦、实例替换和 IME 僵尸 |
| 无 autofocus | 用户直接点击已 attach 的真 TextArea；业务聚焦只对现存 ref 调 `focus()` | 解除聚焦与 vif 挂载时序的耦合 |
| 命令式回写 | 业务改草稿走 `setComposerText` → `view.setTextInputState`（callMethod） | 不经过 Props，不触发绑定重放 |
| 原子编辑快照 | `ComposerEditingReducer` 统一管理 text / selection / composition | 重复 text 事件幂等，过期 selection 事件丢弃 |
| 单一草稿写入边界 | ViewModel 的发送/会话方法不再私自清 `inputText` | 避免原生显示与业务草稿分叉、旧文本复活 |
| ref 可空 | `inputRef: ViewRef<TextAreaView>?`，默认态无实例 | 匹配单实例生命周期 |

### 框架侧关键事实（字节码核实，2.25.0-2.1.21）

- `KRTextFieldView$observeTextWatcher$1.afterTextChanged`：**先抛
  textInputStateChange、再抛 textDidChange**，两次参数都取自编辑后实时
  状态，不会互相携带旧值。
- `setTextInputState` 期间置 `isSettingTextInputState`，`afterTextChanged`
  与 `onSelectionChanged` 均检查该标记直接返回 → 命令式写回不产生回声。
- 因此 Android 上 `handleComposerTextChanged` 里 delta 恒为 0、光标以
  textInputStateChange 的 selectionEnd 为准；长度估算分支只是无
  state 事件先行平台的兜底。**不要删 updateComposerEditingState 的文本
  写入**，否则估算光标 = 已校准光标 + delta 会二次偏移，@// 触发判定错乱。

## 三、影响范围

- 输入态一切编辑（打字 / 退格 / 选区删除 / 拼音组合态）：旧架构下全部
  可能错乱，新架构下事件只读不写回，无打断路径。
- 默认态与输入态共用同一个原生 TextArea，多行草稿在默认态仅收紧到单行高度。
- 子线程追问框（`Input`，无 text 绑定）本来就是非受控，不受影响。
- 发送 / 清空 / 选候选 / 插入触发符：全部走 `setComposerText` 原子写入
  「文本 + 光标」，受 isSettingTextInputState 保护。

## 四、验收清单

- [ ] 输入一段文字，中途点击定位后连续退格：删的是光标前的字，光标不消失
- [ ] 拼音组合态（候选条未上屏）下退格：先删拼音字母，不杀组合会话
- [ ] 全选删除 / 长按清空后，默认态假输入条不复活旧草稿
- [ ] @ 面板展开时输入框收紧单行、关闭后恢复多行
- [ ] 发送后输入框清空，可立即接着输入下一句
- [ ] 输入中收起键盘再点击聊天区：回默认态，草稿保留；再点同一输入框可继续编辑
- [ ] ADB 日志中首次点击只有 inputFocus，不再在 25ms 内紧跟无原因 inputBlur
