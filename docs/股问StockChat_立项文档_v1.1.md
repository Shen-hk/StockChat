## 四、核心创新点速览（评审用）

1. **三流合一交互模型**：文本流（对话）× 卡片流（结构化）× 联动层（Context Bar）在同一页面共生，回答"聊着天就把盘看了"
2. **协议驱动的通用卡片体系**：AI 输出即协议——```` ```card:stock-quote ``` ```` 围栏块 + JSON 意图，客户端 CardRegistry 分发渲染，新增卡片类型零代码侵入
3. **意图与数据分离（真实 AI + 零幻觉行情）**：真实接入 DeepSeek v4-flash（SSE 流式，单次问答 ≈ 0.008 元），行情数字来自腾讯公开接口的真实数据（LLM 只出卡片意图，端侧填充真实数据）——LLM 幻觉无法污染任何一个行情数字；三级降级链（真实→缓存→Mock）保证任何网络环境下演示不中断
4. **实体高亮行内交互**：AI 回答中的股票名/代码/术语自动变为可点击热区，点击跳详情、长按出预览（补齐 KuiklyMarkdown 生态空白，可回馈社区）
5. **渐进式披露三级展开**：卡片折叠态（一句话结论）→ 展开态（图表+指标）→ 全页态（详情承接页），对抗信息过载
6. **归因链卡片**：把"为什么涨/跌"从新闻列表升级为「消息面+资金面+板块联动+情绪面」的可视化因果链
7. **合规与反游戏化设计**：不荐股、信源可溯、风险提示三件套内置进卡片协议，数据模式状态点诚实标注（在线真实/缓存/离线演示），北极星指标定位于"决策质量"而非"交易频率"（Robinhood 教训的正面解法）

### 4.1 关键技术决策速览（2026-08-23 实测侦察后确定）

| 决策 | 结论 | 一句话依据 |
|---|---|---|
| AI 引擎 | 真实 DeepSeek API 为主 + Mock 降级兜底（MiMo 备选） | 端点直连 0.11s、OpenAI 兼容、SSE 流式；单次问答 0.008 元，全程预算 < 20 元；导师可现场自由提问 |
| 行情数据 | 真实腾讯接口为主 + Mock 兜底 | 快照/分时/前复权K线三件套免费无 key 实测可用，A股/指数/港股全覆盖；与 Kuikly 同属腾讯生态 |
| 防幻觉架构 | 意图与数据分离（ADR-11） | LLM 知识截止 2024 年不可能知道今天行情 → 请求侧注入真实行情上下文、响应侧 LLM 只出意图、端侧填真实数字 |

# 00 · 需求分析与市场调研报告

> **项目**：股问 StockChat · AI 股票问答应用 Demo
> **版本**：v1.0 ｜ **日期**：2026-08-23 ｜ **状态**：评审稿
>
> **调研方式**：12 轮网络检索 + 10 个信源深度抓取（雪球、东方财富财富号、知乎、腾讯新闻·南都、叩富网、同花顺财经等）+ Kuikly 生态一手资料（官方文档站、KuiklyUI 仓库、issue #1477 全部 27 条评论、KuiklyMarkdown 源码级调研）

## 1. 市场背景：为什么此时做 AI 股票问答

### 1.1 用户基本盘

- 截至 2025 年末，A股投资者约 **2.51 亿户**，个人投资者占比 **99.76%**，是典型的散户市场（数据口径：中国结算/深交所）
- 散户贡献 60%-70% 的市场成交量，但 2025 年上半年盈利比例仅 **18.9%**，平均收益率约 **-23.6%**——需求旺盛与能力缺失的巨大剪刀差，正是工具型产品的机会
- 平均入市年龄 37.6 岁，31-50 岁中青年占比约 65%，30 岁以下占比已达 30%（平安证券&胡润白皮书）——Z 世代"AI 原生代"正在成为主力，对"问一句就有答案"的交互天然亲和

### 1.2 行业趋势

> 中央财经大学张宁："传统行情软件仅做数据展示的模式逐渐失效，行业竞争从渠道能力转向智能解读与决策效率，不具备 AI 能力的工具将被快速边缘化。"

大厂已全面布局：同花顺 i问财升级为投研 Agent、东方财富"妙想"大模型、蚂蚁"蚂小财"、新浪"芝麻 AI"、长桥 AI 财报解读。AI 问答不是选择题，而是行业明牌——但牌桌上各家打法趋同（卷选股、卷预测），反而留下了交互与定位层面的空档（见 §4）。

## 2. 用户画像与核心场景

### 2.1 典型用户画像（Persona）

| Persona | 占比 | 特征 | 核心诉求 | 对本产品的意义 |
|---|---|---|---|---|
| 追涨杀跌型 | 50%-60% | 年换手率超 500%，85% 依赖社交媒体获取信息 | 快速归因、辨别真假消息 | 归因链卡片 + 信源标注的直接受益者 |
| 套牢躺平型 | 20% | 持仓不动、偶尔看盘 | "我的票到底怎么了" | 主动式解读降低使用门槛 |
| 流星型（短线高频） | 10% | 日内交易，日均交易者亏损率 89% | 速度、异动提醒 | 盘中实时卡片（Demo 后期） |
| 觉醒的普通人 | 9% | 开始学习体系化投资 | 看懂财报、理解指标 | 术语翻译 + 自适应解释深度 |
| 新手小白 | 增量主力 | 看不懂 K 线、MACD，被专业界面劝退 | "人话"解释 | 本产品首要服务对象 |

### 2.2 核心使用场景（按时间轴）

- **盘中看盘**：盯行情、盯持仓、追热点异动（短线用户日均盯盘数小时）
- **盘后复盘**：梳理当日涨跌原因、读公告财报——散户普遍"复盘记录杂乱、长期资料无法沉淀"
- **选股查资料**：从 4000+ 只股票中筛选，70% 散户把"近期涨幅大"列为首要标准（亟需理性纠偏工具）
- **学习理解**：看不懂 K 线形态、MACD 底背离、财报术语，需要"人话翻译"
- **查资讯辨真假**：怕被小道消息、自媒体和"带节奏"误导

**关键行为数据**：普通投资者日均花费 1.6 小时筛选行情与资讯；63% 受访者表示信息过载；散户平均持股周期仅 32 天。

## 3. 现有产品的八大痛点

> 以下痛点均附真实用户声音佐证，来源见 §6。

**痛点 1：信息过载，有效信息密度极低 ⭐⭐⭐⭐⭐**

资讯、快讯、研报、股吧帖、推送无差别轰炸。同花顺被评"资讯数量极多，全网快讯、研报、公告、股吧消息全部堆砌，但没有智能筛选和总结……用户必须自己一条条翻看、辨别有用信息"。"信息不是太少，而是过载与整理低效"是调研中出现频率最高的表述。

**痛点 2：专业门槛高，术语不翻译 ⭐⭐⭐⭐⭐**

"通篇都是金融术语、技术指标、专业财报词汇，完全不做通俗翻译，新手看不懂……学习门槛极高，只适合有多年经验的老股民"（评同花顺）；通达信用户形容"打开只会觉得枯燥和茫然……是活受罪"。

**痛点 3：只给数据不给结论，缺"归因解释" ⭐⭐⭐⭐⭐**

"腾讯自选股只是把数据摆出来，不会用大白话解释数据背后代表什么、对股价有什么影响，属于'看得懂文字，看不懂逻辑'"；同花顺"只给数据指标，很少主动提示个股潜在风险"。行情软件本质是'数据展示器'，而股民要的是'解释器'。

**痛点 4：信息真假难辨，社区噪音大 ⭐⭐⭐⭐**

雪球大 V"金浤"公开推荐 32 只股票后反向卖出，被罚没 8325 万元并禁入 3 年；东方财富股吧"水军也不是一般的多，很多新手小白看股吧炒股，容易被带节奏"。

**痛点 5：多 APP 割裂，老股民被迫"四开" ⭐⭐⭐⭐**

"同花顺、东方财富、通达信（再加个雪球），缺一不可"——看盘、研报、社区、交易被拆进 3-4 个 APP，同一需求被人为切碎。

**痛点 6：AI 工具自身不争气——幻觉、滞后、踩合规红线 ⭐⭐⭐⭐**

南都实测发现"豆包、通义、腾讯元宝 App 均直接给出了股票名称和代码"（触碰荐股红线）；千问财经分析"仍会引用今日头条等自媒体平台的信息，有时甚至引用过时的数据"。通用大模型直接做股票问答，既不安全也不专业。

**痛点 7：关键时刻操作路径长、系统不稳 ⭐⭐⭐**

同花顺"清仓需逐只股票操作，遇到市场暴跌时操作耗时过长导致亏损扩大"；曾因系统崩溃登上热搜。

**痛点 8：功能堆砌与交互干扰 ⭐⭐⭐**

同花顺功能模块 200+、"功能按钮密集"；看盘界面竟有弹幕功能；开屏广告+弹窗+推销电话三连（工信部 2026 年 6 月通报 31 款 APP 存在"开屏弹窗、高灵敏度摇一摇乱跳转"）。

### 3.1 反面教材：Robinhood 的"游戏化"教训

Robinhood 的刮刮乐送股、彩带动画庆祝下单、热门股票榜制造 FOMO、一键交易——被批 "casino-like"（赌场化）设计：其用户交易频率达 Schwab 用户 40 倍、期权合约 88 倍，直接催生 Alex Kearns 悲剧与 SEC 处罚。

**对本项目的启示**：交互创新 ≠ 刺激交易。我们的交互设计宪章是——**用 AI 降低决策冲动，而不是放大它**。这既是伦理底线，也是差异化定位。

## 4. 差异化机会点（六大空档）

| # | 空档 | 现状 | 我们的切入 |
|---|---|---|---|
| 1 | "解释权"空档 | 大厂 AI 都在卷选股/预测，既不靠谱又踩合规红线 | 做归因解释器："XX 今天为什么跌"→ 消息面+资金面+板块联动+情绪面的有信源、有逻辑链的人话回答 |
| 2 | 信源透明空档 | 用户"分不清真假、怕被小道消息误导" | 每句结论带引用来源 + 可信度分级标注 |
| 3 | 新手翻译层空档 | 同花顺太专业、腾讯自选股太浅、Robinhood 式简化又危险 | 自适应解释深度：同一问题，新手得大白话+图示，老手得因子拆解 |
| 4 | 盘后陪伴空档 | 盘中工具饱和，盘后复盘"杂乱无章、无法沉淀" | 结构化复盘问答（Demo 概念展示） |
| 5 | 多 APP 割裂空档 | 老股民被迫装 3-4 个 APP | 对话窗口做统一入口，聚合行情/研报/公告/观点的跨源答案 |
| 6 | "防割韭菜"空档 | 社区产品因商业模式永远不敢做观点质检 | 概念功能：粘贴大 V 观点，AI 核查逻辑漏洞（Demo 后期） |

> **Demo 阶段主打空档 1+2+3**：归因解释 + 信源透明 + 新手翻译，三者恰好全部落在"AI 问答 + 结构化卡片"这条主线上。

## 5. 需求结论

### 5.1 从痛点到需求映射

| 痛点 | 产品需求 | 承载形态 |
|---|---|---|

正式产品的北极星建议为"用户提问后的决策质量改善"（持仓周期拉长、非理性交易频率下降）。Demo 阶段以原型验证代替：**首次提问到获得可理解答案的时长 < 15s**、卡片点击进入详情的转化率、追问 chip 使用率（衡量"降低提问成本"是否生效）。

# 01 · 产品需求文档（PRD）

> **项目**：股问 StockChat · AI 股票问答应用 Demo

## 1. 产品概述

### 1.1 产品定位

**股问 StockChat**：一个以 AI 对话为统一入口的股票行情解读助手。用户用自然语言提问，AI 以「Markdown 文本 + 结构化卡片」混排作答，卡片可点击进入股票详情承接页。

### 1.2 一句话原则

> **做股民的解释器，不做荐股机。**

产品不提供买卖建议、不预测涨跌，专注三件事：**归因解释**（为什么涨/跌）、**术语翻译**（说人话）、**信源透明**（结论可溯源）。

### 1.3 产品目标（Demo 阶段）

| 目标 | 度量 |
|---|---|
| 验证"聊看一体"交互范式 | 完整跑通「提问 → 混排回答 → 卡片互动 → 详情承接」闭环 |
| 验证通用卡片组件体系 | ≥6 种卡片类型全部通过 CardRegistry 零侵入注册，新增一种卡片 ≤ 0.5 人日 |
| 展示 Kuikly 跨端能力 | Android 为主验证端，H5 产物可用于浏览器直接演示分发 |

### 3.2 聊天主页面需求详述

**FR-C1 消息发送与展示**

- 输入框支持多行文本，回车/发送按钮发送；发送后消息立即上屏（乐观更新），AI 回答以流式增量渲染
- 消息列表支持下拉加载历史、自动滚到底部（用户手动上滚时暂停自动滚动）
- **FR-C1-1** 发送中输入框锁定、显示停止按钮，点击可中断生成（Demo 用本地流模拟器实现真实中断体验）
- **FR-C1-2** 会话记录本地持久化（Kuikly DataStore/文件存储），重启不丢失；支持新建会话与历史会话切换（P1，单一会话为 P0）

**FR-C2 AI 回答混排渲染（本项目灵魂）**

AI 回答 = 有序的「文本块 + 卡片块」序列，逐块流式渲染：

- 文本块：打字机效果增量渲染，支持 GFM 子集（标题/加粗/斜体/列表/表格/引用/行内代码）
- 卡片块：按协议渲染对应组件（见 3.3）
- **FR-C2-1** 流式中卡片 JSON 未闭合时显示骨架卡（占位+呼吸动画），闭合瞬间替换为真实卡片
- **FR-C2-2** 未知卡片类型显示灰色降级卡（"该内容类型暂不支持，点击查看原始数据"），保证协议向前兼容
- **FR-C2-3** AI 回答文本中的股票名/代码/术语自动渲染为可点击实体（下划线+品牌色），点击→详情页，长按→Context Bar（P1）

**FR-C3 追问 Chips**

- AI 每次回答结束后，在气泡尾部渲染 2-4 个建议追问（由 AI 响应协议给出）
- 点击 chip 等价于发送该问题；chips 在用户发送后淡出
- 设计意图：把"继续提问"的成本降到零（对应调研：散户提问意愿低、术语组织难）

**FR-C4 Context Bar（P1，交互创新点）**

- 长按消息中任意股票实体：屏幕底部滑出高度约 20% 的迷你行情条（价格、涨跌幅、迷你分时、快捷跳详情）
- 松手或点击空白处收起；期间对话流不动（覆盖式，不打断阅读位置）

**FR-C5 智能输入（P1）**

- 输入 `/` 唤起指令面板（如 /复盘、/对比）
- 输入 `@` 唤起标的快速选择器（防拼错股票名）

### 3.3 卡片体系需求（混排卡片清单）

> 完整设计规范见 04-通用卡片组件设计规范。此处定义产品视角的需求。

|---|---|---|---|---|
| 行情快照卡 StockQuoteCard | "XX 现在多少钱/什么状态" | 名称代码、现价、涨跌幅、今开/最高/最低/成交量、迷你走势图、涨跌色 | 点击→详情页；P1 左滑加自选 | P0 |
| 走势图卡 StockChartCard | "最近走势如何" | 分时/K线 Canvas 图、周期切换（日/周/月） | 点击→详情页走势区；图内手势查看数值（P2） | P0 |

| 维度 | 要求 |
|---|---|
| 性能 | 流式渲染帧率稳定；单条 2000 字回答+3 卡片，中端 Android 机无明显卡顿；卡片 diffUpdate 增量刷新 |

# 02 · 交互设计创新方案（头脑风暴 → 收敛 → 规范）

> **项目**：股问 StockChat · AI 股票问答应用 Demo
> **版本**：v1.0 ｜ **日期**：2026-08-23 ｜ **状态**：评审稿
>
> 本文档是全项目的创意核心：先发散（14 个交互创意全景），再收敛（三流合一模型），后规范（可落地的交互细则与组件化路径）。

## 1. 设计哲学：三条宪章

调研中 Robinhood 的 "casino-like" 反面教材（游戏化诱导交易 → 用户交易频率达同行 40 倍 → SEC 处罚）给了我们最清醒的警示。本项目全部交互设计遵循：

- **宪章一 · 抑制冲动**：交互创新的目的是降低理解成本，不是刺激交易频率。不加庆祝动画、不做 FOMO 榜单、不做一键下单。
- **宪章二 · 渐进披露**：默认给结论，按需给数据，主动下钻才给全貌。对抗"信息过载"（63% 用户抱怨的第一痛点）。
- **宪章三 · 聊看一体**：用户不应该在"问"和"看"之间被迫切换。聊天流即行情流，所有行情能力从对话中自然生长出来。

## 2. 头脑风暴全景：14 个交互创意

> 评分维度：新颖度（与现有产品差异）｜通用性（能否抽成通用组件）｜Demo 可行性（跨端 Kuikly + Mock 数据下能否落地）。满分 5。

### A 类 · 信息呈现层（AI 说什么、怎么摆）

**#01 结构化卡片流（基线形态）**

AI 回答中的行情数据不以表格 Markdown 呈现，而以原生卡片组件渲染：行情快照卡、走势图卡、归因链卡、对比卡、术语卡……卡片即协议（详见 04 号文档）。
灵感对标：KuiklyChatUI 的消息渲染工厂；差异点在于我们让卡片类型成为AI 输出协议的一部分，而非 UI 层的硬编码。
*新颖度 ★★★｜通用性 ★★★★★｜可行性 ★★★★★*

**#02 内联火花线（Inline Sparkline）★差异化**

股票实体 chip 自带 20px 高的迷你走势线：AI 说"茅台今天跌了 2.3%"，"茅台"这个词本身就是一根红色小趋势线 + 跌幅角标。文字即行情，读者不点任何东西就获得趋势直觉。
组件化路径：EntityChip 通用组件（实体文本 + sparkline + 涨跌角标），数据来自 QuoteProvider 快照接口，任何文本场景可复用。
*新颖度 ★★★★｜通用性 ★★★★★｜可行性 ★★★★*

**#03 渐进式披露三级展开 ★核心创意**

每张数据卡有三个密度态：
- **折叠态（默认）**：一句话结论 + 一个关键数字（"茅台 -2.3%，资金净流出为主因"）
- **展开态**：点击后展示完整图表与指标网格
- **全页态**：再点进入详情承接页

设计依据：新手要结论、老手要数据——一张卡自适应两类人（对应调研空档 3"自适应解释深度"）。
*新颖度 ★★★｜通用性 ★★★★★｜可行性 ★★★★★*

**#04 归因链卡片 ★★最强差异化**

回答"为什么跌"时，把"消息面 / 资金面 / 板块联动 / 情绪面"四因子渲染为贡献度横条 + 置信度角标的可视化因果链，每条因子带信源。把现有产品"丢一堆新闻让你自己猜"升级为"给你看推理链"。
*新颖度 ★★★★★｜通用性 ★★★★（可泛化为通用 AttributionChart）｜可行性 ★★★★*

**#05 信源面包屑**

AI 回答中每个关键结论句尾跟随一个小信源角标（¹ ² ³），点击弹出信源卡（来源、时间、可信度分级：公告/研报/媒体/自媒体）。直击"真假难辨"痛点。
*新颖度 ★★★★｜通用性 ★★★★★（协议字段 + 通用 SourceBadge）｜可行性 ★★★★*

### B 类 · 操纵层（怎么点、怎么滑）

**#06 实体高亮（Entity Linking）★核心创意**

AI 回答文本中的股票名/代码/术语自动识别并渲染为可点击热区（品牌色下划线）：单击→跳详情页，长按→Context Bar 预览。文本不再是死的。
技术含义：这是对 KuiklyMarkdown 生态的直接贡献——现有组件无行内交互能力，我们扩展 RichText span 体系实现，成果可回馈社区。
*新颖度 ★★★★｜通用性 ★★★★★｜可行性 ★★★★*

**#07 Context Bar（上下文联动条）★★核心创意**

长按任意股票实体，屏幕底部滑出约 20% 高度的迷你行情条（价格、涨跌、迷你分时、跳详情按钮），对话流纹丝不动。松手即收。灵感来自手机键盘的滑行输入：重交互但零页面跳转。
解决什么：现有产品"看一眼行情要切一次页面"，打断对话心流；Context Bar 让"瞟一眼"的成本趋近于零。
*新颖度 ★★★★★｜通用性 ★★★★（可泛化为通用 PeekBar 容器组件）｜可行性 ★★★*

**#08 追问 Chips（零成本分支）**

AI 回答尾部渲染 2-4 个建议追问按钮（"为什么跌""和五粮液比""财报怎么说"）。点击即发送。把"组织下一个问题"的认知成本转移给 AI。
设计细节：chips 分两种语义——下钻型（更深入本标的）与发散型（关联标的/话题），视觉上前实后虚。
*新颖度 ★★★｜通用性 ★★★★★（协议字段 + 通用 ChipRow）｜可行性 ★★★★★*

**#09 卡片手势**

卡片左滑→加入自选；卡片右上角 ⋯→转发/收藏。克制使用，不做右滑删除（误触代价高）。
*新颖度 ★★｜通用性 ★★★★｜可行性 ★★★★*

### C 类 · 输入层（怎么问）

**#10 智能输入框**

输入 `/` 唤起指令面板（/复盘、/对比、/解读）；输入 `@` 唤起标的联想（@贵州茅台）；输入框上方常驻"最近关注"实体 chip 横条，点击即把标的注入提问。
*新颖度 ★★★｜通用性 ★★★★｜可行性 ★★★*

**#11 拖拽提问（Drag-to-Ask）（概念储备）**

把一张卡片长按拖到输入框，自动组装成问题上下文（"帮我详细分析 [茅台行情卡]"）。卡片成为可拖拽的"名词"。
*新颖度 ★★★★★｜通用性 ★★★｜可行性 ★★（Kuikly 跨端拖拽手势成本高，列概念）*

### D 类 · 场景层（何时出现）

**#12 盘后复盘日报卡（概念展示）**

收盘后 AI 主动生成结构化复盘卡（今日持仓异动归因 + 明日关注事件 + 苏格拉底式反问"你今天的交易依据是什么"）。做"复盘教练"而非"预测大师"——直击散户 89% 亏损率的行为根源。
*新颖度 ★★★★★｜通用性 ★★★｜可行性 ★★（Demo 做静态概念卡展示）*

**#13 观点质检卡（概念展示）**

用户粘贴大 V 观点/截图，AI 输出"逻辑漏洞检查卡"：观点来源、历史战绩、利益关联、论证漏洞清单。社区产品因商业模式不敢做的功能。
*新颖度 ★★★★★｜通用性 ★★★｜可行性 ★★（Demo 做静态概念卡）*

**#14 情绪温度计**

回答涉及市场情绪时，附一个"今日市场情绪温度"小组件（涨跌家数比 + 情绪分档），替代"恐惧贪婪指数"的展示形式。
*新颖度 ★★★｜通用性 ★★★★｜可行性 ★★★*

## 3. 收敛：三流合一交互模型

14 个创意收敛为一个统一交互模型——聊天主页面同时承载三条信息流：

```
┌────────────────────────────────────────┐
│              聊天主页面                  │
│                                        │
│  ① 文本流（对话本体）                    │
│  ┌──────────────────────────────┐      │
│  │ 用户：茅台最近怎么样？          │      │
│  │ AI：今日茅台下跌 2.3%，主因是   │      │
│  │ [资金面净流出]…（实体高亮#06）  │      │
│  ├──────────────────────────────┤      │
│  │ ② 卡片流（结构化载体）          │      │
│  │ ┌────────────────────────┐   │      │
│  │ │ 折叠态：茅台 -2.3% ...   │   │      │
│  │ │ （点击展开→#03 渐进披露） │   │      │
│  │ └────────────────────────┘   │      │
│  │ [为什么跌] [和五粮液比]（#08） │      │
│  └──────────────────────────────┘      │
│                                        │
│  ③ 联动层（瞬时预览）                    │
│  ╔════════════════════════════╗        │
│  ║ Context Bar：茅台 迷你分时…  ║ ←长按  │
│  ╚════════════════════════════╝        │
│  ┌────────────────────────────┐        │
│  │ 输入框  [@最近关注 chips #10] │        │
│  └────────────────────────────┘        │
└────────────────────────────────────────┘
```

| 流 | 职责 | 常驻性 | 承载创意 |
|---|---|---|---|
| ① 文本流 | 对话叙事、解释、结论 | 常驻 | #06 实体高亮、#02 火花线、#05 信源角标 |
| ② 卡片流 | 结构化数据、图表、对比、归因 | 按需出现 | #01 卡片体系、#03 渐进披露、#04 归因链、#08 chips |
| ③ 联动层 | 瞬时预览，不打断心流 | 按需浮现 | #07 Context Bar |

**三流的关系设计**：

- 文本流是叙事主干（AI 的"话"），卡片流是证据陈列（AI 的"图"），联动层是注意力缓冲（"瞟一眼"）
- 卡片永远从文本流的语义中生长出来（AI 说茅台，茅台卡才出现），而不是模板化推送
- 任何卡片→详情页是"全页态"，是渐进披露的第三级，而非孤立页面——详情页是聊天流的延伸，聊天流是详情页的上下文（详情页底部"回到对话"按钮保持滚动位置）

### 3.1 与现有产品的交互对比

| 场景 | 传统股票 APP | 通用 AI 助手 | 股问 StockChat |
|---|---|---|---|
| 问"茅台为什么跌" | 搜股票→翻资讯 Tab→自己拼因果 | 纯文本一大段，无数据可信度 | 文本归因 + 归因链卡 + 信源角标 |
| 想看茅台行情 | 切自选页/搜索 | 文字描述价格 | 卡片直接在对话里，点卡片进详情 |
| 想继续深挖 | 重新组织搜索词 | 重新打字提问 | 点追问 chip，零成本分支 |
| 对话中瞟一眼行情 | 切后台切 APP | 做不到 | 长按实体→Context Bar |
| 看不懂术语 | 百度/知乎新开一页 | 追问一轮 | 点术语实体→术语卡展开 |

## 4. 关键交互详述（落地规范）

### 4.1 实体高亮（#06）

- **识别范围**：股票名（含简称/曾用名映射）、6 位代码、指数名、金融术语词典（首批 50 词：MACD、PE、换手率、北向资金……）
- **识别时机**：流式渲染的每个文本块完成后异步识别（不阻塞打字机效果）
- **视觉**：品牌色 + 下划线（虚线），与普通链接（实线）区分；术语实体加 📖 微图标
- **手势**：单击→详情页（股票）/ 弹出术语卡（术语）；长按→Context Bar（仅股票）
- **容错**：同名词歧义（如"平安"）优先取会话上下文中出现过的标的，其次弹选择浮层

### 4.2 渐进式披露（#03）

| 密度 | 触发 | 内容 | 高度约束 |
|---|---|---|---|
| 折叠态 | 默认 | 结论句 + 主数字 + 迷你图 | ≤ 96dp，保证一屏 3-4 张卡 |
| 展开态 | 点击卡片 | 完整图表 + 指标网格 + 因子条 | ≤ 40% 屏高，内滚动 |
| 全页态 | 点击"查看全部" | 详情承接页 | 全屏 |

展开动画用 Kuikly animate 属性，展开态互斥（同时只展开一张，自动折叠其他）——防止"手风琴地狱"。

### 4.3 Context Bar（#07）

- **触发**：长按实体 ≥ 350ms，Haptic 反馈后滑入（底部，覆盖式，transform 动画）
- **内容**：名称/现价/涨跌幅/30 日迷你分时/「看详情」按钮
- **消失**：松手 1.5s 后自动淡出（期间手指可拖向"看详情"热区形成滑行动作）
- **容器通用性**：PeekBar 是通用容器（内容区可注入任意紧凑组件），不止股票可复用

### 4.4 追问 Chips（#08）

- **数据来源**：AI 响应协议 suggestions 字段（AI 自己生成，非前端硬编码）
- **排布**：气泡下方横排，超出横滑；下钻型实底、发散型描边
- **生命周期**：点击即发送并淡出；新回答到达时替换为新 chips

### 4.5 详情承接页交互

- **承接感**：从卡片进入时，卡片主数字（价格/涨跌幅）做共享元素式放大转场（Kuikly animate 近似实现）；返回时逆动画
- **AI 视角前置**：详情页首屏 = 行情头部 + AI 解读区（归因链卡复用），指标区后置——与传统 APP"数据优先"反着来，强化"解释器"定位
- **闭环**：底部悬浮「↩ 回到对话」胶囊，点击回聊天页并恢复滚动位置与键盘状态

### 4.6 微交互清单

| 交互 | 规范 |
|---|---|
| 涨跌色语义 | 主题 token riseColor/fallColor，A股语境默认红涨绿跌，token 可切（美股语境绿涨红跌） |
| 流式打字机 | 逐字上屏，块级 diff 只重建尾块（沿用 KuiklyStreamingMarkdown 策略） |
| 卡片骨架 | 灰底圆角块 + 呼吸透明度动画，数据就绪后 150ms 内替换 |
| 发送态 | 发送按钮→停止按钮（方块图标），生成中输入框保持可用（可先编辑下一条） |
| 首次引导 | 首次进入展示 3 条示例问题 chip（"XX 今天为什么跌""MACD 是什么""茅台和五粮液怎么选"），点击即问 |

## 5. 无障碍与克制设计

- 涨跌不仅靠颜色：上涨实体带 ▲、下跌带 ▼（色盲友好）
- 卡片所有可点击区域 ≥ 44dp；chips ≥ 36dp 高
- **禁用清单（宪章一的落地）**：无彩带庆祝、无金币音效、无推送轰炸、无开屏广告、无"大家都在买"榜单
- **深色模式**：全量主题 token 化（autoDarkEnable 基础上自定义金融语义色板）

## 7. 演示脚本（Demo Day 叙事线）

按"痛点→方案"顺序编排 4 分钟演示：

| ADR-8 | 状态架构 | MVVM（Kuikly ViewModel）+ 单向数据流 + observable 响应式 | Kuikly 原生支持：by viewModels\<T>() 页面销毁自动清理；observableList + diffUpdate 高效增量刷新 | MVI：Demo 体量下仪式感过重，否决 |
| ADR-9 | 平台范围 | 主验证 Android + H5 演示产物；iOS/鸿蒙架构就绪 | 导师明确"安卓跨端项目"；H5 产物让评审浏览器直接打开（:shared:packLocalJsBundleDebug + jsBrowserRun），演示分发成本最低。注意：H5 端受浏览器 CORS 限制（腾讯行情接口未确认放行跨域），H5 端默认走 Mock Provider，Android 端无此限制走真实接口 | 六端全验证：超出 Demo 工期，否决 |
| ADR-10 | 会话持久化 | DataStore（KMP）或 JSON 文件 | 轻量、跨端 | SQLDelight：单会话场景过重，否决 |
| ADR-11 | 卡片数据可信架构 | 意图与数据分离（Intent-Data Separation）★ | LLM 知识截止 2024 年，不可能知道今天的行情——若让 LLM 输出价格/涨跌幅等数字，必然幻觉编造。因此协议规定：LLM 只输出卡片意图（type + symbol 及定性内容），行情数字段由端侧 QuoteProvider 从腾讯接口取真实数据填充。这是 ChatGPT function calling 的同构模式（LLM 决定调什么工具，工具返回真数据，端侧渲染）。收益：①行情数字 100% 真实、零幻觉 ②LLM 输出 token 减半 ③卡片数据天然与协议解耦 | LLM 全量输出卡片 JSON：幻觉污染行情数字，直接否决 |

## 4. 核心技术设计：AI 响应协议（本项目技术灵魂）

### 4.0 前置机制：上下文注入 + 意图与数据分离（ADR-11）

LLM 知识截止于训练数据日期（DeepSeek/MiMo 均如此），它不可能知道"今天"的行情。若直接问"茅台今天怎么样"，模型要么泛泛而谈要么编造数字。因此请求侧与响应侧各有一层关键设计：

**请求侧 · 上下文注入（RAG-lite）**：

```
用户提问："茅台最近怎么样"
   │
   ▼
① EntityRecognizer 识别问题中的标的（600519.SH）
   │
   ▼
② QuoteProvider 并行取真实数据：快照 + 分时 + 日K（腾讯接口）
   │
   ▼
③ 组装 System Prompt：
   ├─ 角色设定（股票解释器、不荐股、合规话术）
   ├─ 卡片协议说明（可用的 card: 类型 + 字段 schema + 示例）
   └─ ★ 实时行情上下文（真实数据）：
      【贵州茅台 600519 实时行情】2026-08-21
      现价 1272.83 (-1.45%)  今开 1291.50  最高 1291.50  最低 1272.01
      成交量 33472手  成交额 42.78亿  换手 0.27%  PE 19.54
      近5日K线: 08-17 收1293.09 | 08-18 收1297.99 | ...
      分时特征: 早盘冲高回落，午后放量下探
   │
   ▼
④ 发给 DeepSeek（携带注入上下文的多轮对话）
```

**响应侧 · 意图与数据分离**：

| 内容 | 生产者 | 通道 |
|---|---|---|
| 归因分析、解读文本、术语解释（定性） | LLM | Markdown 文本流 |
| 卡片意图（type + symbol + 定性字段如归因因子） | LLM | card: 围栏块 |
| 卡片数字段（价格/涨跌幅/OHLC/K线序列） | 端侧 QuoteProvider（腾讯真实接口） | 渲染时按 symbol 拉取填充 |

**好处**：①行情数字 100% 真实，LLM 幻觉无法污染数据 ②LLM 输出 token 减半（不必编大 JSON）③卡片数据与协议解耦，同一协议可接任意数据源。这与 ChatGPT function calling 同构：LLM 决定"调什么工具"，工具返回真数据，端侧渲染。

### 4.1 协议定义（意图化版本）

AI 的回答是一段 Markdown 文本流，其中卡片意图以围栏代码块表达（**注意：不含行情数字，数字由端侧填充**）：

````
贵州茅台今日下跌 1.45%，呈现放量下挫态势。

```card:stock-quote
{"symbol":"600519.SH"}
```

从因子看，资金面是主要拖累：

```card:attribution
{"symbol":"600519.SH","direction":"fall",
 "factors":[
  {"name":"资金面","weight":0.45,"confidence":"high",
   "desc":"盘面呈现放量下探，主动卖压明显","source":"行情数据推断"},
  {"name":"消息面","weight":0.30,"confidence":"medium",
   "desc":"白酒板块整体走弱拖累","source":"板块联动"}]}
```

```card:suggestions
{"chips":[{"text":"看K线走势","type":"drill"},{"text":"和五粮液比","type":"diverge"},{"text":"PE是什么","type":"diverge"}]}
```
````

**端侧数字填充**：stock-quote 卡渲染时，CardRenderer 持 symbol 调 QuoteProvider.snapshot("600519.SH") → 真实价格 1272.83 / -1.45% 上屏；stock-chart 卡同理拉真实 K 线序列。attribution 的因子权重与描述（定性内容）直接使用 LLM 输出。

**协议设计原则**：

1. **AI 侧零定制**：任何 LLM 只要被 Prompt 约束"用 card:类型 围栏块输出 JSON 意图"，即可接入——协议是 Markdown 的自然超集，对模型友好
2. **人机共读**：不传 JSON 时纯 Markdown 也能看；传了 JSON 人类也能读
3. **向前兼容**：客户端不认识的 card:xxx 类型走降级卡；JSON 字段缺失走默认值；解析永不抛异常
4. **数据不可信内容不外流**：LLM 即使在围栏块里输出了价格字段，端侧一律忽略并以真实数据覆盖（防幻觉兜底）

### 4.4 图表引擎（数据渲染分离，issue #1477 方法论落地）

```
chart/model（纯 Kotlin，无 UI 依赖，可单测）     chart/view（Canvas 渲染）

│ TimeLineCalculator          │    │ TimeLineView               │

└────────────────────────────┘    └────────────────────────────┘

- 坐标计算、刻度生成、数据窗口、命中检测全部在 model 层（参考 issue #1477 获奖实现的关键设计："坐标计算、刻度、数据范围和命中检测均与界面渲染分离，便于跨端复用和单元测试"）
- View 层只做"几何 → Canvas 指令"的映射，同一 Geometry 可驱动 Android/iOS/Web 三端渲染器
- 性能：绘制用 Path 合批；数据窗口滑动用几何裁剪而非重算

### 4.5 实体高亮实现方案

- **识别**：EntityDictionary（标的词典 + 50 术语词典）构建 Trie 树，EntityRecognizer.match(text): List\<EntitySpan>——纯函数、可单测、可异步
- **消歧**：会话上下文标的优先 → 全局热门 → 弹选择
- **渲染**：文本块渲染完成后，将 span 列表注入富文本分段（借鉴 KuiklyMarkdown annotator/ 富文本分段机制，扩展其 span 体系支持 entity 类型 + 点击事件）
- **降级**：识别失败或词典未命中时不影响原文渲染

## 1. 方法论来源：issue #1477 提炼的五条通用性法则

issue #1477（KuiklyUI"图表组件开发"任务，8 位开发者交付、3 位获奖）是一次"组件通用性"的集中工程实践。从其任务定义、验收标准与全部 27 条评论的方案讨论中，我们提炼出五条法则，作为本组件库的设计公理：

| # | 法则 | issue #1477 中的出处 | 本组件库的落地 |
|---|---|---|---|
| L1 | 纯公共实现，不绑定原生视图 | Shen-hk 方案："基于 Kuikly Canvas 与 KMP 的 commonMain 单一实现，无需注册平台原生 View" | 全部组件 commonMain 纯 Kotlin，图表走 Canvas 自绘 |
| L2 | 数据与渲染彻底分离 | Study0915 方案（获奖）："坐标计算、刻度、数据范围和命中检测均与界面渲染分离，便于跨端复用和单元测试" | CardModel（纯数据）/ ChartCalculator（纯函数）与 Renderer 分离 |
| L3 | 数据源 Provider 接口解耦 | Study0915："可复现的 Mock 数据 + 可替换 Provider 接口，不依赖密钥或付费服务" | QuoteProvider / AiProvider 接口 + Mock 实现 |
| L4 | 声明式 DSL + 类型化回调 | 各方案共识：DSL 逐项声明 + onItemSelected 等类型化事件 | StockCard { ... } DSL + sealed Event 回调 |
| L5 | 主题 token 化 + 逐项可覆盖 | 四套内置主题，颜色/字号/内边距 token 可逐项覆盖 | StockChatTheme token 体系（涨跌色语义化） |

**验收标准对齐**：issue #1477 的三条验收标准——功能完整、多平台运行、提供完整 API 文档和示例——同样作为本组件库的验收标准；其"交付形式为独立仓库"的精神，落地为 cards/ 模块的独立边界（可拆库发布）。

## 3. 核心接口规范（cards/core）

### 3.1 CardModel —— 数据基类（纯数据，可序列化，可单测）

```kotlin
interface CardModel {
    /** 协议类型标识，对应围栏块 ```card:{cardType} */
    val cardType: String
    /** 卡片唯一 id（流式 diff 用），默认由注册中心生成 */
    val cardId: String get() = "$cardType:${hashCode()}"
}
```

**约定**：

- 实现类为 @Serializable data class，字段给默认值（协议容错：JSON 字段缺失不崩）
- 禁止持有任何 View/Context/闭包引用——保证可序列化、可持久化、可快照测试

### 3.2 CardRenderer —— 渲染器接口

```kotlin
interface CardRenderer<M : CardModel> {
    /** 渲染内容区（CardShell 负责外壳） */
    fun render(ctx: BaseContext, container: ViewContainer,
               model: M, ctx2: CardContext)
    /** 可选：卡片事件回调（类型化，sealed class） */
    fun onEvent(model: M, event: CardEvent, ctx2: CardContext) {}
}
```

### 3.3 CardContext —— 渲染上下文（注入依赖，替代组件内取数）

```kotlin
class CardContext(
    val theme: StockChatTheme,          // 主题 token
    val density: CardDensity,           // FULL / COMPACT / MINI 三级密度
    val router: CardRouter,             // 路由能力（openDetail 等），由宿主实现
    val quoteProvider: QuoteProvider,   // 行情取数（骨架→数据两段渲染）
    val interaction: CardInteraction,   // 交互回调（onExpand/onCollapse/onSlide）
)
```

> **关键设计**：渲染器只消费上下文，不自行获取依赖。聊天页与详情页注入不同的 router/density 实现，同一渲染器在两处复用而无须感知宿主。

### 3.4 CardRegistry —— 注册分发中心（零侵入扩展点）

```kotlin
object CardRegistry {
    private val renderers = mutableMapOf<String, CardRenderer<*>>()

    /** 注册（业务启动时调用一次；新卡片 = 一行注册） */
    fun register(type: String, renderer: CardRenderer<*>)

    /** 分发：未注册类型返回内置 UnknownCardRenderer（降级卡），永不返回 null */
    fun dispatch(type: String): CardRenderer<*>

    /** 列出已注册类型（卡片画廊页/调试用） */
    fun registeredTypes(): List<String>
}
```

**降级链（协议容错的三道防线）**：

```
卡片块到达
  ├─ JSON 未闭合      → CardShell 骨架态（呼吸动画）
  ├─ JSON 闭合但解析失败 → 降级卡 v1（"内容暂无法展示 [查看原始数据]"）
  ├─ 解析成功但类型未注册 → 降级卡 v2（UnknownCardRenderer，同上）
  └─ 解析成功且已注册     → 正常渲染（字段缺失走默认值）
```

> 这条降级链使卡片协议天然向前兼容：服务端/AI 新增卡片类型，旧客户端优雅兜底；这正是"通用性"在协议层的体现。

## 4. CardShell —— 通用卡片外壳

所有卡片渲染器只实现内容区，外壳能力（占全卡 60% 的通用工作量）由 CardShell 统一提供：

| 能力 | 规范 |
|---|---|
| 三级密度 | FULL（聊天展开态/详情页，≤40% 屏高内滚动）/ COMPACT（聊天折叠态，≤96dp，一句话结论+主数字）/ MINI（Context Bar 条内，单行） |
| 骨架态 | 灰底圆角块 + 呼吸透明度动画；数据到达 150ms 内交叉淡入 |
| 降级态 | 灰边卡片 + "内容类型暂不支持" + 查看原始数据（展开 JSON 文本） |
| 展开/折叠 | CollapsibleCard 语义：展开动画用 Kuikly animate；同屏互斥展开 |
| 点击行为 | 点击外壳默认路由到"全页态"（详情页），渲染器可覆写 |
| 手势 | 左滑→onEvent(SlideAddWatch)；P1 生效 |
| 合规脚注 | riskDisclaimer=true 时底部自动加"AI 生成 · 仅供参考 · 不构成投资建议" |

**密度复用矩阵（同一渲染器 × 三密度 = 三处复用）**：

| 卡片 | FULL | COMPACT | MINI |
|---|---|---|---|
| StockQuoteCard | 详情页行情头 | 聊天折叠卡 | Context Bar 行情条 |
| StockChartCard | 详情页走势区 | 卡片内嵌缩略图 | Sparkline |

## 5. 主题 token 规范（cards/theme）

```kotlin
class StockChatTheme(
    // ---- 语义色（而非写死色值）----
    val riseColor: Long = 0xFFE03131.toInt(),      // 涨（A股默认红涨）
    val fallColor: Long = 0xFF0CA678.toInt(),      // 跌
    val flatColor: Long = 0xFF868E96.toInt(),      // 平
    // ---- 通用 token ----
    val bgCard: Long, val bgPage: Long,
    val textPrimary: Long, val textSecondary: Long, val textTertiary: Long,
    val brandColor: Long, val entityColor: Long,   // 实体高亮色
    val radiusCard: Float = 12f, val paddingCard: Float = 16f,
    val fontTitle: Float = 16f, val fontBody: Float = 14f, val fontCaption: Float = 12f,
) {
    companion object {
        val Light = StockChatTheme(...)
        val Dark  = StockChatTheme(...)   // 深色模式全 token 覆盖
        /** 涨跌语义切换（美股语境：riseColor=绿 fallColor=红） */
        val LightUs = Light.withSemantic(usStyle = true)
    }
}
```

**规范**：

- 组件内禁止硬编码颜色/字号/圆角——全部取自注入的 theme 实例（lint 规则检查）
- 涨跌色必须走 riseColor/fallColor 语义 token（一处切换全 App 生效，市场惯例可配置）
- 深色模式 = 换一个 Theme 实例，组件代码零改动
