## 1. 文档定位

02 号文档 §4.2 定了渐进披露的基线形态（折叠→展开→全页 + 同屏互斥的手风琴模式）。本文档把它**深化扩展**为六种可落地形式，并给出：

- 每种形式的**触发、手势、视觉、状态机**规范（给开发）
- **卡片-形式适配矩阵**——哪种卡片用哪种形式（给评审与设计）
- **工程接口**（`expandMode` 枚举 + `CollapsibleCard` 通用容器）——保证零重复开发
- 排期、裁剪、验收标准（给项目）

读者：开发（实现依据）+ 导师评审（创新性与通用性论证）+ 设计（视觉与交互规范）

## 2. 设计哲学：四条宪章

沿用 02 号文档三条宪章，新增第四条：

| 宪章 | 内涵 | 对渐进披露的约束 |
|---|---|---|
| 一 · 抑制冲动 | 降低理解成本，不刺激交易 | 展开是"获取信息"，不是"刺激下单" |
| 二 · 渐进披露 | 默认给结论，按需给数据 | 展开本身就是渐进披露的执行手段 |
| 三 · 聊看一体 | 问与看不被迫切换 | 展开尽量不离开聊天流 |
| **四 · 形式适配** | **不追求一致性，追求适配性** | **不同卡片用不同展开形式，而非一刀切** |

第四条是本文档的核心论点：**渐进披露不是一种模式，而是一组模式**。手风琴是好的默认基线，但归因卡走递进下钻、资讯卡走底部 Sheet、对比卡走并排展开，会让每种卡片长在它最该长的形态上。

## 3. 渐进披露的本质

### 3.1 两个正交维度

渐进披露有两个常被混淆的维度，必须分开设计：

| 维度 | 含义 | 本项目的取值 |
|---|---|---|
| **密度（Density）** | 切换到"多少信息量" | 折叠态 / 展开态 / 全页态（三级，见 04 号文档 CardShell） |
| **形式（Mode）** | "怎么切换"——原地展开、弹层、下钻、并排… | 六种（见 §4） |

密度是**数据层**问题（CardModel 决定每级显示哪些字段），形式是**交互层**问题（CardRenderer 决定切换的动画与容器）。两者正交：任何形式 × 任何密度 = 一个具体交互。

### 3.2 核心矛盾

信息密度与认知负荷的矛盾：
- 密度太低 → 用户要多次展开才能获得决策信息（操作成本高）
- 密度太高 → 一屏信息过载（63% 用户抱怨的第一痛点）

渐进披露的解法是**离散档位 + 形式适配**：
- 离散档位（折叠/展开/全页）保证每屏信息量可控
- 形式适配保证"切换档位"的动作本身不打断用户当前的任务流

### 3.3 为什么需要多种形式

手风琴（同屏互斥展开）的局限：
1. **看 A 要收 B**：切换成本高，不适合"边看归因边看资金流向"
2. **长内容撑开聊天流**：展开一张长资讯列表，聊天流被撑得很长，阅读位置丢失
3. **单焦点**：不适合"A vs B"对比这类天然需要双卡同屏的场景

不同卡片的信息形态不同（叙事链 vs 列表 vs 对比 vs 术语），单一形式无法最优服务所有卡片。

## 4. 六种交互形式规范

每种形式统一结构：定义 · 适用卡片 · 触发与手势 · 视觉规范 · 状态转换 · 与其他形式关系 · 工程要点。

### 4.1 手风琴（Accordion）—— 基线形态

**定义**：紧凑卡点击后在原地展开为完整态，同屏同时只展开一张，展开新卡时上一张自动收起。

**适用卡片**：`StockQuoteCard`（行情快照）、`StockChartCard`（走势图）—— 信息量适中、单焦点即可满足。

**触发与手势**：
- 单击紧凑卡 → 展开态
- 单击展开态卡头或「收起」按钮 → 折叠态
- 展开「查看全部」→ 全页态（详情承接页）
- 展开新卡时，原展开卡以 200ms 收起动画让位

**视觉规范**：
- 展开动画：Kuikly `animate` 属性，高度 0→目标值，250ms ease-out
- 展开态卡头加「收起 ▲」 affordance，折叠态加「查看完整内容 ▼」
- 同屏互斥由 `CollapsibleCard` 容器组管理，非卡片自管

**状态转换**：
```
折叠态 ──click──→ 展开态 ──"查看全部"──→ 全页态（跳详情页）
   ↑                                  │
   └───────────"回到对话"──────────────┘
展开态 ──click他卡──→ (自动)折叠态 + 他卡展开
```

**工程要点**：`AccordionGroup` 容器持有一个 `currentExpanded: String?` 状态，卡片只声明 `groupId` + `cardId`，互斥逻辑在容器层。

---

### 4.2 底部 Sheet（BottomSheet）—— 不占聊天流

**定义**：点击紧凑卡，从屏幕底部滑出可拖拽高度的浮层，承载完整内容，**不占聊天流位置**。

**适用卡片**：`NewsCard`（资讯列表，内容长）、`StockChartCard`（K 线全屏查看）、`AttributionCard`（多因子完整列表）。

**触发与手势**：
- 单击紧凑卡 → 底部 Sheet 滑入（默认半展态）
- 向上拖拽把手 → 半展 → 全展（最高 90% 屏高，内部滚动）
- 向下拖拽把手 → 半展 → peek 态（约 25% 屏高）→ 再下拉或点外部 → 关闭
- Sheet 关闭后，原紧凑卡不变（它只是触发器）

**三档高度档位**：
| 档位 | 高度 | 内容 |
|---|---|---|
| peek | ~25% 屏高 | 标题 + 一句话摘要 + 「展开更多」 |
| half | ~50% 屏高 | 标题 + 摘要 + 前 N 条 |
| full | ~90% 屏高（内部滚动） | 完整内容 |

**视觉规范**：
- Sheet 顶部圆角 16dp，顶部居中一个 36×4dp 拖拽把手
- 背景半透明遮罩 30% 黑，点击遮罩 = 下拉一档
- 滑入动画：translateY 100%→目标，250ms

**与其他形式关系**：底部 Sheet 是"全页态"的轻量替代——比跳详情页轻，但比原地展开重。适合"看完就回"的中等深度查看。

**工程要点**：`BottomSheetHost` 是页面级容器（聊天页/详情页各一个），卡片通过 `CardContext.interaction.openSheet(model, density)` 触发，不感知 Sheet 实现。

---

### 4.3 递进下钻（Progressive Drill-down）—— 卡内生长

**定义**：点击卡内某个因子/条目，**不替换整张卡、不跳页**，而是在卡片内部向下"长出"子区域，子区域可再被点击长出孙区域。一层套一层，叙事链天然分层。

**适用卡片**：`AttributionCard`（归因链，因子→信源）、`InsightCard`（AI 解读，要点→依据）。

**触发与手势**：
- 点击归因卡的某个因子条（如「资金面」）→ 该因子下方长出资金流向详情区
- 再点详情区某条 → 长出信源卡
- 子区域可独立收起（每个子区域有自己的「收起」）
- 同一卡片内可同时展开多个子区域（非互斥，因为是不同因子）

**视觉规范**：
- 每层缩进 12dp（视觉表达嵌套层级）
- 子区域用更浅的背景色（theme.bgSecondary → bgTertiary）
- 长出动画：高度 0→目标，从父区域底部向下展开，200ms
- 子区域顶部一条 2dp 品牌色细线，标示"从父生长"

**状态转换**：
```
归因卡（折叠态）
  └─ 点击「资金面」因子
     └─ 卡内长出：资金流向详情区
        └─ 点击某条资金数据
           └─ 长出：信源卡（MINI 密度）
              └─ 点击信源角标 → 跳信源详情页（全页态）
```

**与其他形式关系**：递进下钻是"原地展开"的深度版本——手风琴是"整卡展开"，递进下钻是"卡内局部展开"。二者可共存：归因卡整体走手风琴（展开/折叠），内部因子走递进下钻。

**工程要点**：
- `DrillStack` 容器维护一个 `List<DrillNode>` 栈，每次点击 push 一层，收起 pop
- 子区域是独立的 `CardModel`，复用 CardRegistry 渲染（信源卡就是 `NewsCard` 的 MINI 密度）
- 关键约束：子区域必须是 `CardModel`（纯数据），不能持有父卡引用——保证可序列化、可单测

### 4.4 嵌套对话展开（Nested Conversation）—— 展开即追问

**定义**：把"展开"变成"AI 就这个点继续深聊"——点击「查看完整」不展开静态内容，而是在该卡下方长出一个**子对话分支**，AI 就这个因子/要点继续问答，主对话流不动。

**适用卡片**：`InsightCard`（AI 解读，深挖 = 追问）、`AttributionCard`（某因子深挖 = 就此因子问 AI）。

**触发与手势**：
- 点击「深挖此点」按钮 → 卡下方长出子对话气泡区
- 子对话默认带一个 AI 首条回应（基于该卡上下文自动生成追问），用户可继续输入
- 子对话区可收起（收起时保留已生成内容，再展开恢复）
- 子对话与主对话独立计数、独立持久化

**视觉规范**：
- 子对话区缩进 16dp，左侧一条 2px 品牌色竖线标示"分支"
- 子对话气泡比主对话小一号（fontBody 13px → 12px）
- 子对话区顶部「分支：资金面深挖 · [收起]」

**状态转换**：
```
InsightCard
  └─ 点击「深挖：资金面」
     └─ 长出子对话分支
        ├─ AI（首条）：基于该因子上下文生成的深入解读
        ├─ 用户：继续追问
        └─ AI：继续回答
        └─ [收起] → 子对话折叠（内容保留）
```

**与其他形式关系**：这是最契合"聊看一体"哲学的形式——展开不是"显示更多静态数据"，而是"就此点继续对话"。把信息获取变成对话延伸。

**工程要点**：
- 子对话是独立的 `Message` 列表，挂在父 `Message` 的 `subThread` 字段上
- AI 请求构造时把父卡上下文（symbol + factor）注入 `System Prompt`
- 实现成本较高（涉及流式 + 子线程状态管理），列 P1-M5

---

### 4.5 焦点放大（Focus Magnify）—— 长按瞬时聚焦

**定义**：长按某张卡 → 该卡放大置顶、其他卡淡化半透明，松手回原位。**瞬时强化、不打断阅读位置**。

**适用卡片**：所有卡片通用（作为一种增强 affordance），尤其 `StockQuoteCard`（快速扫一眼行情）。

**触发与手势**：
- 长按卡片 ≥ 350ms → 进入焦点态（Haptic 反馈）
- 焦点态期间：该卡 scale 1.0→1.04，其他卡 opacity 1.0→0.35
- 松手 → 350ms 回到原态
- 焦点态期间向上滑 → 转为「全页态」（跳详情页，Pop 动作）
- 焦点态期间向下滑 → 收起为折叠态

**视觉规范**：
- 放大用 transform scale（不重排，性能好）
- 淡化用 opacity（不重排）
- 焦点态卡片加一层 2dp 品牌色描边
- 整个动画 200ms，松手回原 350ms

**与其他形式关系**：焦点放大是"瞬时预览"——和 Context Bar（长按实体出迷你行情）精神一致，但作用对象是卡片而非文本实体。它不替代手风琴，而是叠加在卡片上的轻交互层。

**工程要点**：
- 不创建新视图，只改 transform/opacity（Kuikly `animate` 作用于现有节点）
- 与列表滚动手势冲突防御：长按 350ms 延迟 + 移动阈值 8dp 取消（沿用 02 号文档 Context Bar 的冲突策略）

---

### 4.6 对比展开（Side-by-side）—— 双卡并排

**定义**：同时激活两张卡 → 两张并排展开成对比视图，而非单张互斥展开。专服务"A vs B"场景。

**适用卡片**：`CompareCard`（本职）、`StockQuoteCard`（用户主动选两只对比时）。

**触发与手势**：
- `CompareCard` 直接以并排形态渲染（它的默认形态就是并排）
- 普通卡进入对比态：长按一张卡 → 进入"待对比"模式（该卡高亮）→ 再点另一张卡 → 两张并排展开
- 对比态可切换主从（点击某张设为"主标的"）
- 对比态退出：点击对比视图外部

**视觉规范**：
- 并排布局，中间一条 1px 分隔线
- 两张卡同密度（自动取较高那张的高度）
- 指标差值条：在两卡之间渲染一条横向 bar，标示差值与方向
- 涨跌色语义：左卡用 riseColor/fallColor，右卡同；差值条用方向色

**与其他形式关系**：对比展开打破"单焦点"假设——它就是为多焦点设计的。与手风琴互斥规则冲突，因此 `CompareCard` 声明 `expandMode = SIDE_BY_SIDE`，退出互斥组。

**工程要点**：
- `CompareGroup` 容器接收两个 `CardModel`，渲染并排布局
- 差值计算是纯函数（`CompareCalculator.diff(a, b)`），可单测
- CompareCard 的 cardType 协议里直接带两个 symbol，端侧各拉各的真实行情

## 5. 卡片-形式适配矩阵

每张卡的主形式（P0 必做）与增强形式（P1 可选）：

| 卡片 | 主形式 | 增强形式 | 理由 |
|---|---|---|---|
| `StockQuoteCard` | 手风琴 | 焦点放大 | 快速扫一眼，长按聚焦即可 |
| `StockChartCard` | 手风琴 | 底部 Sheet（全屏查看） | 中等信息量，全屏走 Sheet 不撑流 |
| `AttributionCard` | **递进下钻** | 嵌套对话（因子深挖） | 因子→信源是天然叙事链 |
| `DefinitionCard` | 手风琴 | — | 轻量术语，原地展开即可 |
| `NewsCard` | **底部 Sheet** | — | 资讯列表长，Sheet 不占聊天流 |
| `InsightCard` | **嵌套对话展开** | 递进下钻 | 深挖=追问，契合聊看一体 |
| `CompareCard` | **对比展开** | — | 本职就是并排 |
| `RiskCard` | 静态（不展开） | — | 合规脚注，默认全显 |

**设计原则**：每张卡锁定**一种主形式**，避免一张卡同时支持三种以上形式（手势/状态机爆炸）。增强形式作为可选 affordance 叠加，不替代主形式。

## 6. 工程接口设计

### 6.1 expandMode 枚举

```kotlin
enum class ExpandMode {
    ACCORDION,          // 4.1 手风琴（默认）
    BOTTOM_SHEET,       // 4.2 底部 Sheet
    DRILL_DOWN,         // 4.3 递进下钻
    NESTED_CONVERSATION,// 4.4 嵌套对话展开
    FOCUS_MAGNIFY,      // 4.5 焦点放大（增强层，叠加用）
    SIDE_BY_SIDE        // 4.6 对比展开
}
```

卡片在 `CardModel` 中声明主形式：
```kotlin
@Serializable
data class AttributionCardModel(
    override val cardType: String = "attribution",
    val symbol: String,
    val direction: String,
    val factors: List<Factor>,
    val expandMode: ExpandMode = ExpandMode.DRILL_DOWN  // 默认递进下钻
) : CardModel
```

### 6.2 CollapsibleCard 通用容器

`CollapsibleCard` 是承载所有"原地展开类"形式（手风琴、递进下钻）的通用容器：

```kotlin
class CollapsibleCard : KtViewContainer() {
    var density: CardDensity       // FULL / COMPACT / MINI
    var expandMode: ExpandMode
    var model: CardModel
    var context: CardContext
    var groupId: String            // 互斥组（手风琴用）
    var isExpanded: Boolean        // 当前展开态

    override fun KtViewContainer.render() {
        // 外壳（CardShell 提供）+ 内容区（按 expandMode 分发）
    }
}
```

### 6.3 与 CardRegistry / CardShell 的关系

```
CardRegistry.dispatch(type) → XxxCardRenderer
                                  │
                                  ▼
                            CardShell（外壳：密度/骨架/降级/合规脚注）
                                  │
                                  ▼
                      按 model.expandMode 选择容器：
                       ├─ ACCORDION/DRILL_DOWN → CollapsibleCard
                       ├─ BOTTOM_SHEET        → 由 BottomSheetHost 承载
                       ├─ NESTED_CONVERSATION → SubThreadContainer
                       ├─ FOCUS_MAGNIFY       → 叠加在任意容器上（transform/opacity）
                       └─ SIDE_BY_SIDE        → CompareGroup
```

**关键约束**：渲染器（`XxxCardRenderer`）只写内容区，不感知容器形式——形式由 `model.expandMode` + `CardContext` 决定。这保证同一渲染器在不同形式下复用。

### 6.4 事件回调（类型化 sealed class）

```kotlin
sealed class CardEvent {
    object Expand : CardEvent()
    object Collapse : CardEvent()
    object RequestFullScreen : CardEvent()      // 跳详情页
    data class DrillInto(val factorId: String) : CardEvent()  // 递进下钻
    data class StartSubThread(val context: String) : CardEvent() // 嵌套对话
    data class CompareWith(val otherSymbol: String) : CardEvent()
    object FocusStart : CardEvent()             // 焦点放大
    object FocusEnd : CardEvent()
}
```

## 7. 交互状态机与冲突防御

### 7.1 同屏互斥规则

| 形式 | 互斥？ | 规则 |
|---|---|---|
| 手风琴 | 是 | 同 groupId 同时只展开一张 |
| 底部 Sheet | 是（单实例） | 同时只一个 Sheet |
| 递进下钻 | 否（卡内） | 同一卡内可多个子区域，不同卡独立 |
| 嵌套对话 | 否 | 每张卡可独立开子线程 |
| 焦点放大 | 是 | 同时只一张聚焦 |
| 对比展开 | 是（双卡组） | 同时只一组对比 |

### 7.2 手势冲突防御

| 冲突场景 | 防御策略 |
|---|---|
| 长按 vs 列表滚动 | 长按延迟 350ms + 移动阈值 8dp 取消（沿用 Context Bar 策略） |
| 焦点放大向上滑 vs 列表滚动 | 焦点态期间禁用列表滚动（PointerEvent 拦截） |
| 底部 Sheet 下拉 vs 聊天流滚动 | Sheet 打开时遮罩拦截聊天流触摸 |
| 递进下钻子区滚动 vs 父卡滚动 | 子区独立滚动容器，touch 事件不冒泡 |

### 7.3 动画时序约定

- 展开动画：250ms ease-out（高度/位移）
- 收起动画：200ms ease-in
- 焦点放大：进入 200ms，退出 350ms（退出慢一点，减少"弹回"突兀感）
- 同步互斥：旧卡收起 200ms 与新卡展开 250ms 并行（不串行，否则有"空档"）

## 8. 无障碍与克制设计

| 维度 | 规范 |
|---|---|
| 色盲友好 | 展开态不仅靠颜色变化，加 ▲▼ 方向标示 |
| 触控区域 | 展开热区 ≥ 44dp；把手 ≥ 36×36dp |
| 减弱动效 | `@media (prefers-reduced-motion)` 下动画时长 → 0ms，直接切换状态 |
| 焦点可见性 | 键盘/无障碍模式下，可展开卡片需有可见 focus ring |
| 状态可读 | 展开态对屏幕阅读器播报"已展开，共 N 项" |
| 禁用项 | 无彩带庆祝展开、无音效、无 FOMO 榜单（宪章一落地） |

## 9. 排期与裁剪

### 9.1 Demo 阶段分级

| 形式 | 优先级 | 落地里程碑 | 说明 |
|---|---|---|---|
| 手风琴 | **P0** | M3 | 基线形态，全卡通用，闭环必需 |
| 递进下钻 | **P0** | M4 | AttributionCard 的差异化核心 |
| 底部 Sheet | **P0** | M4 | NewsCard / ChartCard 全屏查看 |
| 焦点放大 | P1 | M5 | 增强层，工期紧可砍 |
| 对比展开 | P1 | M5 | CompareCard 本职，CompareCard 本身就是 P1 |
| 嵌套对话展开 | P1 | M5 | 实现成本高（流式+子线程），可降为概念展示 |

### 9.2 裁剪预案（工期不足时按序砍）

1. 先砍 P1 尾部：嵌套对话展开（降为静态概念卡展示）
2. 再砍：焦点放大（不影响任何卡片主形式）
3. 极端情况：对比展开降为手风琴（CompareCard 用两张卡先后展开近似）
4. **保底不可砍**：手风琴 + 递进下钻 + 底部 Sheet = 渐进披露最小可用集
