## 1. 文档定位

本文档是「自选股」与「术语表」两个功能模块的合并 PRD，覆盖：

- **问题陈述与目标**——为什么现在做、做到什么程度算成功（给评审）
- **用户故事与功能需求**——P0/P1/P2 分级，含验收标准（给开发）
- **数据与接口参数表**——复用现有卡片协议、词典与渲染体系，零重复开发（给开发）
- **成功指标、开放问题、验收清单与分期**（给项目）

两模块合并成文的原因：**共用同一套实体基础设施**（EntityDictionary / Trie / 实体高亮 / MINI 渲染器），且在同一迭代内开发可摊薄词典与标的库的维护成本。但两模块的 P0 范围互相独立，任一模块可单独上线。

读者：开发（实现依据）+ 导师评审（范围与价值论证）+ 设计（视觉与交互规范）

## 2. 问题陈述

### 2.1 自选股

立项调研显示散户「盘中盯持仓、盘后复盘持仓」是日均数小时的高频场景（立项文档 §2.2），而股问目前是**无记忆的单次问答**——用户每次都要重新输入标的名称，「我的票今天怎么样」这句最自然的问题没有数据支撑。会话内标的消歧（已上线）只记忆当次会话，无法跨会话沉淀。

不做的代价：用户的核心资产（持仓关注列表）留在同花顺/自选股等竞品里，股问退化为「偶尔查一下」的工具而非日常入口。

### 2.2 术语表

术语不翻译是立项调研的第二痛点（⭐⭐⭐⭐⭐）。当前术语卡（DefinitionCard）与实体高亮已上线，但**词典仍是首批演示集合**，未达立项要求的完整 50 词与曾用名数据源（项目实施记录 §5.2 遗留 P1：覆盖率无法宣称达到 95%）。同时术语只能「撞上才看得到」——AI 回答里没出现的术语，用户无处可查，学习场景（「觉醒的普通人」画像的核心诉求）没有承接形态。

不做的代价：术语翻译这一差异化卖点停留在演示水平，覆盖率抽检不过关即无法对评审宣称达标。

## 3. 目标与非目标

### 3.1 目标（Goals）

| # | 目标 | 衡量方式 | 目标值 |
|---|---|---|---|
| G1 | 用户能把标的沉淀到自选，并跨会话复用 | 添加自选后 7 日内再次发起含自选标的提问的比例 | ≥ 40%（演示环境下以固定问题集走查验证链路通） |
| G2 | 「我的自选今天怎么样」一句话出整体结论 | 固定问题集走查：该问句返回聚合回答 + 各自选标的 MINI 卡 | 100% 触发，无幻觉数字（端侧填充真实行情） |
| G3 | 术语词典达到立项规模 | 词典词条数 | ≥ 50 词，含别名/英文缩写映射 |
| G4 | 术语识别覆盖率可宣称 | 固定测试语料（含大小写变体、中英文混排）命中率 | ≥ 95% |
| G5 | 术语可主动浏览，不依赖 AI 回答碰巧提到 | 术语表入口可达性 | 任意页面 ≤ 2 步进入术语列表 |

### 3.2 非目标（Non-Goals）

| # | 不做 | 原因 |
|---|---|---|
| N1 | **不做交易/下单/券商接入** | 宪章一「抑制冲动」；合规红线，Demo 阶段明确排除 |
| N2 | **不做异动推送/盯盘提醒** | 需后台推送通道与实时行情订阅，超出一个迭代；列为 P2 架构预留 |
| N3 | **不做自选股分组/多组合管理** | 演示阶段单列表足够；分组是确定性 fast-follow（P1） |
| N4 | **不做用户自定义词条/社区共建词典** | 内容审核成本高，Demo 阶段词库由团队维护 |
| N5 | **不做词库在线热更新** | 词典随版本内置发布即可；热更新列为 P2 架构预留（词典数据结构需与代码解耦） |
| N6 | **不做英文/双语术语表** | 目标用户为 A 股散户，中文优先；ASCII 术语仅做识别容错 |

## 4. 用户故事

按优先级排序（US-W = 自选股，US-G = 术语表）：

| # | 角色 | 故事 | 价值 | 优先级 |
|---|---|---|---|---|
| US-W1 | 套牢躺平型股民 | 作为长期持有几只股票的股民，我希望把持有的票加入自选，以便不用每次重新输入名字就能问它的情况 | 核心资产沉淀，提问成本归零 | P0 |
| US-W2 | 新手股民 | 作为新手，我希望在 AI 回答里长按股票名就能加自选，以便不打断阅读顺手收藏 | 聊看一体：收藏发生在阅读流内 | P0 |
| US-W3 | 股民 | 作为股民，我希望问「我的自选今天怎么样」得到一句话结论 + 各票关键数据，以便 10 秒掌握全局 | 渐进披露：默认给结论，按需展开 | P0 |
| US-W4 | 股民 | 作为股民，我希望有一个自选列表页能扫一眼全部自选行情，以便盘后快速复盘 | 承接「盘中盯盘/盘后复盘」场景 | P0 |
| US-G1 | 新手小白 | 作为看不懂术语的新手，我希望 AI 回答里的术语都有可点解释且命中率足够高，以便不被「MACD 底背离」这类词劝退 | 立项痛点 2 的直接交付 | P0 |
| US-G2 | 觉醒的普通人 | 作为想系统学习的用户，我希望有一个术语表页面能按分类浏览全部词条，以便主动学习而不是等 AI 碰巧提到 | 学习场景承接形态 | P0 |
| US-W5 | 股民 | 作为股民，我希望在输入框 `@` 时自选标的排在候选最前，以便少打字 | 输入效率 | P1 |
| US-G3 | 老手 | 作为老手，我希望术语卡里的「进阶解释」能展开，以便同一词条服务不同深度 | 自适应解释深度（立项空档 3） | P1（卡片已支持，仅需词典补全进阶字段） |
| US-W6 | 股民 | 作为股民，我希望能删除/排序自选，以便列表保持干净 | 基础管理 | P0（删除）/ P1（排序） |
| US-G4 | 用户 | 作为用户，我希望搜索术语时输拼音首字母或英文缩写也能命中（如输 "PE"、"hsl" 命中换手率），以便怎么输都找得到 | 词典可达性 | P1 |

边缘场景（必须在验收中覆盖）：

- 自选为空时，「我的自选怎么样」→ 引导添加而非报错（空状态即教学）
- 自选标的停牌/退市 → 列表与回答中如实标注状态，不展示陈旧价格冒充实时
- 离线/缓存模式下，自选列表与聚合回答的数据模式角标诚实标注（沿用三级降级链）
- 同名标的（如「平安」）加自选时走既有消歧选择器，不允许静默加错
- 术语在流式渲染中途到达 → 沿用现有「文本块完成后异步识别」，不阻塞打字机

## 5. 功能需求

### Part A · 自选股（FR-W）

#### P0（Must-Have）

**FR-W1 自选数据模型与本地持久化**

- 自选条目 = `{ symbol, name, addedAt, sortOrder }`，symbol 复用 `Security.kt` 的标的标识
- 端侧本地持久化（KMP 共享层存储），跨会话保留；无账号体系，不云端同步
- 容量上限 50 只（演示规模，防滥用）
- 验收：
  - [ ] 杀进程重启后自选列表完整保留
  - [ ] 添加第 51 只时给出「自选已满」提示而非崩溃或静默失败

**FR-W2 添加自选（三个入口，行为一致）**

- 入口 1：聊天文本中**长按股票实体** → Context Bar 增加「加自选」操作
- 入口 2：股票详情页行情头 → 「加自选/已自选」状态切换
- 入口 3：自选列表页 → 搜索添加（复用 `@` 候选的标的搜索能力）
- 同名标的必须经消歧选择器确认真实 symbol 后才写入
- 已自选的标的重复添加 → 幂等，提示「已在自选中」
- 验收：
  - [ ] 三个入口添加同一标的，列表中只出现一次
  - [ ] 输入「平安」触发选择浮层，确认后才加入对应标的
  - [ ] 添加后立即生效：当次会话即可问「我的自选怎么样」

**FR-W3 自选列表页**

- 每行复用 **MINI 行情渲染器**（`StockCardRenderers.kt`，禁止新写行情行组件）：名称、现价、涨跌幅（红涨绿跌 + `+`/`−` 符号）、MINI 分时
- 数据模式角标（在线真实/缓存/离线演示）沿用现有统一文案
- 点击行 → 股票详情页；长按行 → 操作浮层（删除自选；P1 置顶/排序）
- 空态：引导文案 + 「去聊聊添加」入口，不留白屏
- 停牌/退市标的：状态标注，价格区域显示「停牌」而非旧价
- 验收：
  - [ ] 20 只自选滚动流畅，复用 Scroller 体系无卡死
  - [ ] 断网时列表可读，角标显示离线/缓存模式
  - [ ] 删除即时生效且有二次确认或撤销入口

**FR-W4 「我的自选」对话联动**

- 「我的自选/我持有的/我的票 + 怎么样/如何/今天」类问句 → AI 回答聚合：
  1. 一句话整体结论（LLM 定性，基于端侧注入的真实行情上下文）
  2. 各自选标的 COMPACT/MINI 行情卡（端侧按 symbol 填真实数字，意图与数据分离原则不变）
- 自选为空 → 回答引导「先去添加自选」，不编造标的
- 验收：
  - [ ] 固定问题集 5 条变体问法全部触发聚合回答
  - [ ] 回答中所有数字与详情页一致（无 LLM 幻觉数字）
  - [ ] 空自选问句返回引导而非报错

#### P1（Nice-to-Have）

- **FR-W5** `@` 候选列表中自选标的置顶并加 ★ 标识
- **FR-W6** 自选手动排序（长按拖动）与置顶
- **FR-W7** 自选列表页顶部聚合头：自选整体涨跌家数统计（涨 X 家 / 跌 Y 家），一句话结论前置

#### P2（Future Considerations）

- 异动提醒/推送（需推送通道与订阅架构，数据模型预留 `alertRules` 字段位置）
- 自选股分组（数据结构预留 `groupId`）
- 云端同步（需账号体系，Demo 阶段不涉及）
- **架构要求**：v1 数据模型即按上述预留字段设计存储 schema，避免二期迁移成本

### Part B · 术语表（FR-G）

#### P0（Must-Have）

**FR-G1 词典扩展至完整规模（≥ 50 词）**

- 词条结构：`{ term, aliases[], asciiAliases[], category, plainExplanation, example, advancedExplanation? }`
- 分类维度（首版 5 类）：技术指标（MACD/KDJ/均线…）、估值指标（PE/PB/ROE…）、交易机制（T+1/涨跌停/集合竞价…）、资金与情绪（北向资金/换手率/龙虎榜…）、财报概念（营收/净利润/毛利率…）
- 每词必填：人话解释（≤ 60 字，说人话，禁止抄教科书）、一个 A 股语境的例子
- `advancedExplanation` 选填但技术指标类必须提供（承接 US-G3）
- 验收：
  - [ ] 词条数 ≥ 50，五类均有覆盖
  - [ ] 全部词条通过「新手可读性」走查（非专业用户读懂率抽检）

**FR-G2 识别覆盖率达标（≥ 95%）**

- 沿用 Trie 最长匹配 + ASCII 大小写容错；补齐别名表（如「市盈率/PE/pe/P/E」同指）
- 建立固定测试语料集（含大小写变体、中英文混排、别名、干扰词如「平安」），纳入 `commonTest`
- 消歧沿用会话内标的优先策略；术语与股票同名时（如「苹果」）**默认解释为股票**，术语解释在详情页可 secondary 触达
- 验收：
  - [ ] 固定语料命中率 ≥ 95%，CI 可重复验证
  - [ ] 干扰词用例不误标（如人名/普通词不被高亮）

**FR-G3 术语表浏览页**

- 入口 ≤ 2 步：聊天空态欢迎页示例问题之一 + 自选/详情页入口（具体入口位置见 §8 开放问题 Q2）
- 列表按分类分组展示，组头吸顶；每行 = 术语 + 一句话人话解释（截断）
- 点击词条 → 弹出术语卡（复用 DefinitionCard COMPACT → 手风琴展开进阶解释，形态已在 06 号文档定义，不重造）
- 顶部搜索框：实时过滤，支持中文/拼音首字母/英文缩写（P1 中拼音可降级为仅中英文）
- 验收：
  - [ ] 任意词条 2 次点击内看到完整人话解释
  - [ ] 搜索 "PE" 命中「市盈率」，搜索「换手」命中「换手率」
  - [ ] 视觉走查：术语实体色、卡片密度符合 theme token，无自造颜色值

#### P1（Nice-to-Have）

- **FR-G4** 拼音首字母检索（"hsl" → 换手率）
- **FR-G5** 术语卡底部「相关术语」推荐（同分类内 2-3 词，零成本继续学）
- **FR-G6** 曾用名/别名数据源扩展（项目实施记录遗留项，与词典扩展同批处理）

#### P2（Future Considerations）

- 词库与代码解耦（独立数据文件/资源包），为热更新预留
- 「我刚看过的术语」历史记录
- 术语掌握度标记（学习中/已掌握）——学习路径的第一步，Demo 后评估

## 6. 数据与接口参数表

### 6.1 复用清单（零新造组件原则）

| 能力 | 复用对象 | 位置 |
|---|---|---|
| 自选行行情渲染 | MINI 行情 Renderer | `cards/stock/StockCardRenderers.kt` |
| 术语解释展示 | DefinitionCard（COMPACT + 手风琴） | 卡片注册体系 + 06 号文档手风琴规范 |
| 标的搜索/消歧 | `@` 候选 + 会话内优先消歧策略 | 输入栏候选体系（10 号文档） |
| 实体识别 | Trie 最长匹配 + ASCII 容错 | `EntityDictionary.kt` / EntityRecognizer |
| 行情数据 | 三级降级链（真实→缓存→Mock）+ 模式角标 | QuoteProvider 统一数据 |
| 视觉 token | 涨跌色 `#FF4D4F`/`#00B578`、术语色、玻璃材质 | `StockChatTheme.kt` / `GlassTokens.kt` |

### 6.2 新增数据结构

| 结构 | 字段 | 说明 |
|---|---|---|
| WatchlistItem | symbol / name / addedAt / sortOrder / (预留 groupId, alertRules) | 本地持久化，上限 50 |
| GlossaryEntry | term / aliases[] / asciiAliases[] / category / plainExplanation / example / advancedExplanation? | 内置发布，≥ 50 条 |

### 6.3 AI 协议影响

- 「我的自选」聚合回答：LLM 输出意图（哪些标的 + 定性结论），端侧按 symbol 填真实行情——**沿用意图与数据分离，不新增协议类型**，复用 `card:stock-quote` 批量意图即可
- 术语解释仍走文本流 + 术语实体高亮 + 点击弹 DefinitionCard，协议无变更
