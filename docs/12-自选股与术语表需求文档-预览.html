01文档定位

两个模块合并成文的原因：共用同一套实体基础设施（EntityDictionary / Trie / 实体高亮 / MINI 渲染器），且同一迭代内开发可摊薄词典与标的库的维护成本。但两模块的 P0 范围互相独立，任一模块可单独上线。

02问题陈述

自选股

股问是「无记忆的单次问答」

立项调研显示散户「盘中盯持仓、盘后复盘持仓」是日均数小时的高频场景，而用户每次提问都要重新输入标的名称，「我的票今天怎么样」这句最自然的问题没有数据支撑。会话内标的消歧只记忆当次会话，无法跨会话沉淀。

不做的代价：用户的核心资产留在竞品里，股问退化为「偶尔查一下」的工具，而非日常入口。
术语表

术语翻译停留在「撞上才看得到」

术语不翻译是立项调研的第二痛点（⭐⭐⭐⭐⭐）。术语卡与实体高亮已上线，但词典仍是首批演示集合，未达立项要求的完整 50 词与曾用名数据源，覆盖率无法宣称达到 95%。AI 回答里没出现的术语，用户无处可查。

不做的代价：学习场景（「觉醒的普通人」画像核心诉求）没有承接形态，覆盖率抽检不过关即无法对评审宣称达标。

03目标与非目标

3.1 目标（Goals）

#目标衡量方式目标值
G1用户能把标的沉淀到自选，并跨会话复用添加自选后 7 日内再次发起含自选标的提问的比例≥ 40%（演示环境以固定问题集走查验证链路通）
G2「我的自选今天怎么样」一句话出整体结论固定问题集走查：返回聚合回答 + 各自选标的 MINI 卡100% 触发，无幻觉数字（端侧填充真实行情）
G3术语词典达到立项规模词典词条数≥ 50 词，含别名 / 英文缩写映射
G4术语识别覆盖率可宣称固定测试语料（含大小写变体、中英文混排）命中率≥ 95%
G5术语可主动浏览，不依赖 AI 回答碰巧提到术语表入口可达性任意页面 ≤ 2 步进入术语列表

3.2 非目标（Non-Goals）—— 防范围蔓延

#不做原因
N1交易 / 下单 / 券商接入宪章一「抑制冲动」；合规红线，Demo 阶段明确排除
N2异动推送 / 盯盘提醒需后台推送通道与实时行情订阅，超出一个迭代；列为 P2 架构预留
N3自选股分组 / 多组合管理演示阶段单列表足够；分组是确定性 fast-follow（P1）
N4用户自定义词条 / 社区共建词典内容审核成本高，Demo 阶段词库由团队维护
N5词库在线热更新词典随版本内置发布即可；热更新列 P2，数据结构需与代码解耦
N6英文 / 双语术语表目标用户为 A 股散户，中文优先；ASCII 术语仅做识别容错

#角色故事价值优先级

US-W3股民作为股民，我希望问「我的自选今天怎么样」得到一句话结论 + 各票关键数据，以便 10 秒掌握全局渐进披露：默认给结论，按需展开P0
US-W4股民作为股民，我希望有一个自选列表页能扫一眼全部自选行情，以便盘后快速复盘承接「盘中盯盘 / 盘后复盘」场景P0
US-G1新手小白作为看不懂术语的新手，我希望 AI 回答里的术语都有可点解释且命中率足够高，以便不被「MACD 底背离」这类词劝退立项痛点 2 的直接交付P0

US-G3老手作为老手，我希望术语卡里的「进阶解释」能展开，以便同一词条服务不同深度自适应解释深度（立项空档 3）P1
US-G4用户作为用户，我希望搜索术语时输拼音首字母或英文缩写也能命中（如 "PE"、"hsl" 命中换手率）词典可达性P1

边缘场景（验收必须覆盖）

  • 自选为空时，「我的自选怎么样」→ 引导添加而非报错（空状态即教学）
  • 自选标的停牌 / 退市 → 如实标注状态，不展示陈旧价格冒充实时
  • 离线 / 缓存模式下，列表与聚合回答的数据模式角标诚实标注（沿用三级降级链）
  • 同名标的（如「平安」）加自选时走既有消歧选择器，不允许静默加错
  • 术语在流式渲染中途到达 → 沿用「文本块完成后异步识别」，不阻塞打字机
