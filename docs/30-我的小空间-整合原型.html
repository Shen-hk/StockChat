我的小空间 —— 异动预警 × 风险地图 × 自选 一体化

把「自选股 · 异动预警 · 风险地图」三个独立页面整合为一个个人空间（Home Base）： 自选是唯一输入源，预警从「盯价格」升级为「盯价格 + 盯事件 + 盯暴露变化」，风险地图成为空间的风险底座， AI 以条件触发的解释者身份贯穿（简报 / 归因 / 追问出口），全程只解释已发生的事，不做任何买卖建议。 可交互：筛选、展开、追问、开关。

调研 1现状：三页割裂，闭环断在入口

自选（WatchlistPage）、异动预警（AlertCenterPage）、风险地图（RiskMapPage）各自独立、抽屉三层入口。预警只做单票价格阈值 ±3%，与风险地图的「暴露 / 事件」能力零复用 —— 用户要自己把三页的信息在脑子里拼起来。

调研 2对标：蚂小财串联 vs 同花顺并列

同花顺 Lumi 把「持仓风险检查」做成了并列功能项；蚂小财走「体检 → 了解风险 → 学习」的串联形态。我们的整合方向是串联：预警消息是钩子，点开即归因，归因即风险，风险即术语，术语即知识库。

调研 3预警的行业现状：只有价格，没有"与我有关"

主流券商 App 的预警几乎全部是价格/涨跌幅触发，触发后只给一个数字，用户不知道"然后呢"。差异化机会：预警 = 行情异动 + 事件临近（解禁/财报）+ 暴露变化（集中度突变），每条都带归因检查顺序与「追问 AI」出口。

调研 4合规边界（doc 23 硬约束）

N-R6 原否决的是远程推送（催促操作）。本次改为应用内消息中心：打开才看、消息只解释已发生波动、附带检查顺序而非操作建议；不出现评分/等级/匹配词汇；等权估算常驻标注；AI 触点预算 ≤5 处全条件触发。

交互设计说明 · 与 AI 的关系 · 落地路径

① 一页三区，联动代替跳转

首页 = 聚合结论 + 预警预览 + 关注分层 + AI 简报。收件箱与风险底座从首页一次点击可达，且互相出超链：风险地图的"事件 → 转为预警"、收件箱的"暴露变化 → 去风险地图"。

② 预警从"盯价格"升级为"盯三样"

行情异动（已有 AlertStore 阈值）+ 事件临近（解禁/财报/减持，数据源已在 Provider 内）+ 暴露变化（RiskSnapshotStore 周快照对比，已有）。三类消息同一条时间线，分类 tab 过滤。

③ 消息提示 = 应用内 badge + 收件箱

不做远程推送（N-R6 维持）：badge 只在 App 内显示未读数；消息点开才消费；"收盘后免打扰"开关把盘后异动合并进次日早简报，避免催促感。

④ AI 触点预算：4 处，全条件触发

AI 简报（每日 ≤1 条，平静日不出现）· 归因检查顺序（消息内置）·「问 AI」追问（用户主动）· 暴露页内联注释（≤3，沿用 C-3 预算）。AI 永远是"解释者"，输出全是事实句。

⑤ 落地：增量改造，不推倒重来

WatchlistPage 聚合头下插入 InboxPreview；AlertCenterPage → AlertInboxPage（加事件/暴露两类消息源 + 已读状态）；RiskMapPage 加"转为预警"出口。三个 Store 全部复用，alertRules schema 已预留。

⑥ 闭环的最后一环

消息里的术语（解禁/相关系数）→ L0 术语 sheet → 知识库记一笔；简报里的"你最近老遇到"接 TermTracker。预警是钩子，知识是沉淀，自选是源头 —— doc 23 的闭环在"空间"内首尾相接。

合规边界（沿用 doc 23 §4.1，逐条自查）：无风险测评 / 无 C1-C5、R1-R5 / 无"匹配、适配、你的风险等级、评分、健康分"词汇 / 无仓位、止损、调仓建议 / 消息只陈述已发生事实并附检查顺序 / 等权估算角标常驻 / 免打扰与静默优先于推送感 / 「问 AI」走对话页 AttributionIntent 链路，页内不自行编造原因。
