## 0. 摘要

**一句话结论：自选库、风险能力、知识库不是三个功能，是一条闭环的三个环节；而这条闭环整体精准落在中证协 2026-06 分级准入里唯一被点名「优先推广」的那一格。**

```
自选（我在看什么）→ 风险地图（我承担了什么）→ 知识库（我还缺什么）→ 回到自选
```

三者的重新定位：

| 模块 | 现状 | 重新定位 | 一句话 |
|---|---|---|---|
| 自选库 | 行情收藏夹 | **投资关注图谱** | 存的不只是代码，是「我为什么看它」 |
| 风险能力 | 零实现 | **风险暴露解释器**（非风险等级裁判） | 不判定你该承担什么，只解释你正在承担什么 |
| 知识库 | 抽屉里的词典列表 | **三层知识架构**（JIT 触发 + 认知地图） | 术语在卡住的那一刻出现，知识在回头看时成形 |

**最关键的合规结论（本文 §4.1 有完整法条依据）**：风险测评问卷、C1–C5 投资者分级、R1–R5 产品分级、适当性匹配意见——这四件事是《适当性管理办法》给**持牌经营机构**设定的法定义务，**非持牌主体做即超范围，是硬红线**。《办法》第二十二条更是直接禁止「向普通投资者主动推介风险等级高于其风险承受能力的产品或者服务」。而中证协分级准入把**持仓分析**明确列为面向客户的低风险场景、应**简化登记并优先推广**。所以本文把「风险能力」整体定义为**暴露解释**，而非**等级评判**——既合规最优，又恰好是竞品没做好的地方。

## 2. 三模块为什么是一条链路

### 2.1 现状盘点（代码实证，非推测）

| 项 | 实测结果 | 出处 |
|---|---|---|
| 自选持久化 | 本地 `PagerKeyValueStorage`，key `stockchat_watchlist_v1`，上限 **50** | `WatchlistStore.kt` |
| 自选字段 | `symbol/name/addedAtMillis/sortOrder/groupId/alertRules`（后两个为 P2 预留，已写入 schema） | 同上 |
| 自选行渲染 | 复用 `StockQuoteCardModel` + `CardDensity.MINI`（符合 12 号文档「零新造组件」原则） | `WatchlistPage.kt` |
| 自选聚合头 | **无**。FR-W7（涨跌家数统计）在 12 号文档列为 P1，未实现 | `WatchlistPage.kt` |
| 自选分组 | 三个 chip（全部/核心观察/待研究）+ 行内三态循环按钮（未分组→核心→研究） | 同上 |
| 自选入口 | 抽屉 `onOpenWatchlist`；详情页；长按实体（三入口齐备） | `ChatPage.kt:917` |
| 术语词条数 | **61 条**（12 号文档目标 ≥50，已超额） | `Glossary.kt` |
| 术语分类 | 技术指标 16 / 财报概念 14 / 交易机制 11 / 资金与情绪 10 / 估值指标 10 | 同上 |
| 术语检索 | 中文名 / 英文缩写 / 别名，分级打分排序；拼音首字母为 P1 未实现 | `Glossary.search()` |
| 术语入口 | 抽屉 `onOpenGlossary`，**2 层深** | `ChatPage.kt:916` |
| 风险能力 | **零实现**。仅在两处有零散痕迹：`EastMoneyInsightProvider.riskLabel()`（公告文本关键词打标「关注风险」）、`CardGalleryPage` 的 `concept:portfolio` 概念卡 | 全库 grep |
| 已有卡片类型 | `attribution / billboard / corporate-actions / definition / disclosures / financial / fund-flow / insight / news / product-concept / shareholders / stock-chart / stock-compare / stock-quote`（14 类） | `CardModel.kt` 系 |

**三个必须承认的判断**：

1. 自选股与术语表的 P0 在 v1.0 已基本交付，12 号文档的两条主线目标（G1–G5）已达成。**继续在原有框架里加功能是低价值的**——真正的缺口是「三者没有关系」。
2. 风险能力不是「再加一个页面」，它是**让自选和知识库产生关系的中介**。没有风险分析，自选永远只是行情列表；没有术语解释，风险分析用户根本读不懂。
3. `CardGalleryPage` 里躺着的 `concept:portfolio`（「导入持仓后只解释集中度、行业分布和共同风险暴露」）与 `concept:journal`（「买入前只记录事实与原始理由，复盘时逐条核对哪些逻辑已经变化」）**是项目自己提出的、但没有落地的两条产品思想**。本文 §3.2 与 §4.2 把它们正式落地。

### 2.2 三者真实的依赖关系

```
                    ┌──────────────────────┐
                    │   自选（关注图谱）      │
                    │  我在看什么、为什么看    │
                    └──────────┬───────────┘
                               │ 唯一输入源
                               ▼
                    ┌──────────────────────┐
                    │   风险地图（暴露解释）   │
                    │  这些东西押注了哪些      │
                    │  共同变量？              │
                    └──────────┬───────────┘
                               │ 输出中出现用户不认识的概念
                               ▼
                    ┌──────────────────────┐
                    │   知识库（认知地图）     │
                    │  我还缺什么、下一步懂什么 │
                    └──────────┬───────────┘
                               │ 懂了之后更会看
                               └──────► 回到自选
```

- **自选 → 风险**：风险分析的全部输入来自自选。自选为空 → 风险页空态引导加自选。**这天然解决了风险能力的冷启动。**
- **风险 → 知识**：暴露解释必然产生术语（「相关系数」「行业集中度」「商誉占净资产比」）。这些术语正是用户**最想懂**的——因为它们出现在**自己的钱**上，而不是泛泛的教程里。这是 JIT 学习动机最强的时刻。
- **知识 → 自选**：懂得「同涨同跌 = 押注同一变量」之后，用户回头看自选的眼光变了。这是本产品「做股民的解释器」定位的完整兑现。

### 2.3 对标：蚂小财的串联 vs 同花顺的并列

**同花顺 AI（Lumi）官方功能清单**（一手来源 `basic.10jqka.com.cn/ai_data/...`）显示其 AI 能力被组织成 5 组 20 项，其中与本文相关的：

- 账户分析组：**持仓风险检查（识别个股、行业仓位集中带来的持仓隐患）**、盈亏归因、账户自动复盘
- 确定投资目标组：**风险等级评估（根据收入、负债情况匹配适配的账户风险标准）**、资金分配规划

**关键差异**：同花顺是持牌证券投资咨询机构，**可以做风险等级评估**；它不是我们的对标路径，因为**我们没有牌照**。但它的「持仓风险检查」描述——「识别个股、行业仓位集中带来的持仓隐患」——**恰好是中证协分级里被优先推广的那一格，也是我们唯一该走的格子**。

**蚂小财**（蚂蚁集团 AI 金融管家，2019 上线，2024-09 新版，截至 2024-08 月活 7000 万、45% 来自三线及以下城市）的公开描述是：用户可「进行理财健康体检、对自己的理财行为进行评估、**了解持仓风险、学习理财知识**、获得个性定制配置策略」。**注意这个顺序：体检 → 了解风险 → 学习知识。它把三件事串起来了。** 这正是本文 §2.2 闭环的行业验证。

**结论**：同花顺走的是「并列 + 判定」（它是持牌方，可以判定用户），蚂小财走的是「串联 + 陪伴」。**我们的对标是蚂小财的串联形态，但把「判定用户风险等级」这一环整体替换为「解释标的暴露」。** 这个替换不是妥协，是更优解——因为它把产品从「给用户贴标签」变成「给用户讲清楚」，与项目宪章「解释器，不做荐股机」完全一致，且合规风险从高风险格降到优先推广格。

## 3. 自选库（Watchlist）

### 3.1 现状诊断（6 条，均基于代码实读）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| W-1 | **它是列表，不是「库」** | `WatchlistPage` = 搜索框 + 3 chip + N 行 MINI 卡。无聚合视图、无状态分类、无时间维度 | 20 只自选给不出「今天整体怎么样」，而这是 US-W3 的核心价值 |
| W-2 | **视觉纯卡片堆叠** | N 行等高同构（MINI 卡 + 2 个同构按钮），z 轴只有一层 | 命中项目铁律 #5 黑名单头号信号 |
| W-3 | **分组交互是隐藏状态机** | `cycleGroup()`：点击 → 未分组→核心→研究 三态循环 | 用户看不到全部选项，只能盲点；且分组是低频操作却占据与「移除」同等的视觉权重 |
| W-4 | **聚合头缺失** | FR-W7 列为 P1 未实现 | 用户要自己在脑内对 20 个涨跌幅求和 |
| W-5 | **「为什么看它」从未被记录** | `WatchlistItem` 只有 symbol/name/时间/排序 | 「加自选」是用户唯一的**主动意图声明**时刻，这一刻的信息被永久丢弃 |
| W-6 | **自选 ≠ 持仓，但用户心智里是** | 模型只有自选无持仓 | 风险分析无从计算集中度（无权重） |

### 3.2 重新定位：从「行情收藏夹」到「投资关注图谱」

| 维度 | 现在（收藏夹） | 应该（关注图谱） |
|---|---|---|
| 存什么 | symbol + name | + **关注理由 + 加入时快照 + 来源** |
| 呈现 | 平铺行情列表 | **聚合结论（L1）+ 分层暴露（L2/L3）** |
| 回答 | 「多少钱」 | 「我关注的东西今天发生了什么、为什么」 |
| 与风险 | 无关联 | **风险地图的唯一输入源** |
| 与知识 | 无关联 | **术语解释的场景触发器** |

**最重要的一条设计：记录「关注理由」。**

这不是锦上添花，是本项目最高价值的差异化点，四层理由：

1. **它是项目自己的产品思想，但没落地。** `CardGalleryPage` 的 `concept:journal` 已写明「买入前只记录事实与原始理由，卖出或复盘时逐条核对哪些逻辑已经变化」。思想提出来了，自选却只存了个代码。
2. **加自选是用户唯一主动表达意图的时刻。** 这一刻的理由，是后续所有解释的锚点。没有它，我们只能解释「发生了什么」；有了它，才能解释「**你当初看中的那个逻辑，还在不在**」。
3. **行业方法论支持。** 有知有行/且慢的核心方法论即「投前建立预期、投后陪伴」；有知有行甚至为海外产品设计二十几道考题做认知门槛。我们不做门槛（那是限制用户），改做**理由记录**（这是赋能用户）——形态相反，目标一致。
4. **数据支持「拿不住」是散户亏损主因。** 且慢公开数据：持仓 < 3 个月的客户盈利占比仅 **63.17%**、平均收益率 **−0.21%**；持仓 > 2 年的客户盈利占比 **93.85%**、平均收益率 **+28.97%**。（口径：且慢平台客户，二手转引，对外引用须注明）**「记录理由 → 复盘核对逻辑是否变化」正是对症的解法。**

### 3.3 目标与非目标

**Goals**

| # | 目标 | 衡量 | 目标值 |
|---|---|---|---|
| G-W1 | 自选页 3 秒给出整体结论 | 聚合头存在且首屏可见（顶部 200px 内） | 100% |
| G-W2 | 关注理由被记录 | 新增自选时填写理由的比例（真机走查 + 埋点） | ≥ 30% |

| # | 不做 | 原因 |

### 3.4 用户故事

| US-W4 | 股民 | 希望记录「我为什么关注它」，几个月后能回看当时是不是这个逻辑 | P0（**新增，核心**） |

| US-W7 | 股民 | 希望 `@` 候选里自选置顶并带 ★ | P1 |

**边缘场景（验收必覆盖）**
- 自选为空 → 聚合头不显示，空态引导去聊天添加（不在空态报错）
- 全部自选停牌 → 聚合结论显示「N 只停牌」，不编造涨跌
- 离线/缓存 → 数据模式角标诚实标注（沿用三级降级链）
- 同名标的 → 必须经消歧选择器，不允许静默加错
- 用户填了理由但未填仓位 → 风险分析用等权，并显式标注「等权估算」

### 3.5 功能需求

#### P0

**FR-W1 自选聚合头（补齐 FR-W7，从 P1 提到 P0）**
- 顶部**无卡片**，直接落在氛围底上（z0）：一句话结论 + 1 个主数字
- 主数字：**今日自选等权涨跌幅**（大字 ≥30px/800，等宽数字）
- 结论由**规则引擎**出（不调 LLM），规则：涨跌幅区间 + 红绿盘家数比 → 一句话模板
- 下方一条比例条：涨 / 平 / 跌 三段（关系可视化，不罗列）
- 右侧 `>` 进入风险地图页
- 验收：首屏 200px 内可见；数字与各行明细一致；行情平静时结论为中性表述不夸大

**FR-W2 关注理由（核心新增）**
- 三个添加入口（长按实体 / 详情页 / 搜索添加）**都走同一理由浮层**，不跳过
- 浮层提供**一行输入 + 3 个常用理由 chip**（业绩 / 政策 / 技术面），可跳过（允许留空，不强制）
- 理由长度上限 40 字，明文存储，不外传
- 自选行**不展示理由**（保持扫描效率），点击行进详情或长按可看
- 理由在**详情页**与**风险地图页**作为对照物出现：当初理由 vs 当前事实
- 验收：三入口行为一致；留空不阻断添加；杀进程重启理由保留

**FR-W3 自选行信息重构（视觉，规格见 doc 24 §5.1）**
- 行 = MINI 行情卡 + **状态徽标**（异动/事件/停牌），移除右侧两个同构按钮
- 分组改为**长按菜单**里的选项（去掉隐藏状态机）
- 「移除」改为**左滑**，带撤销（撤销能力已有 `undoRemove()`，保留）
- 验收：无 3 行以上等高同构；同屏 z 深度 ≥3

**FR-W4 状态筛选（替分组 chip）**
- 三个 chip：**全部 / 异动 / 事件待办**
  - 异动 = |涨跌幅| ≥ 3% 或 涨停/跌停 或 进入连板梯队
  - 事件待办 = 未来 30 天有解禁 / 财报预约 / 分红除权，或近 7 天有减持公告
- 分组 chip 保留但**降级到第二行且弱化**
- 验收：异动/事件判定与详情页数据一致

**FR-W5 自选 → 风险地图 的一键通路**
- 聚合头右侧 `>` + 底部一行「我押注了什么 ›」
- 验收：自选非空时 1 次点击到达风险地图且分析完整

#### P1
- **FR-W6** `@` 候选自选置顶 + ★
- **FR-W7** 拖动排序与置顶

## 4. 风险能力（Risk）

> **本章 §4.1 是全篇最重要的合规论证，任何实现前必须先读完。**

### 4.1 合规边界：什么绝对不能做

#### 4.1.1 法条依据（一手）

《证券期货投资者适当性管理办法》（2016 通过，2020/2022 两次修正）关键条款：

| 条款 | 内容要点 | 对本产品的含义 |
|---|---|---|
| **第三条** | 「**向投资者销售**证券期货产品或者**提供证券期货服务的机构（以下简称经营机构）**应当……提出明确的适当性匹配意见，将适当的产品或者服务销售或者提供给适合的投资者，并对违法违规行为承担法律责任」 | 义务主体是**经营机构**（持牌）。我们不是，因此**不承担也不得行使**这套义务 |
| **第六条** | 经营机构应当了解投资者：财务状况（收入来源和数额、资产、债务）、投资相关学习工作经历及投资经验、投资期限品种期望收益等投资目标、**风险偏好及可承受的损失**、诚信记录等 | 采集这套信息 = 在做适当性评估的前置动作 |
| **第十条** | 经营机构应当「综合考虑收入来源、资产状况、债务、投资知识和经验、风险偏好、诚信状况等因素，**确定普通投资者的风险承受能力，对其进行细化分类和管理**」 | C1–C5 分级是**经营机构**的法定义务 |
| **第十六/十七条** | 经营机构应当「根据风险特征和程度，对销售的产品或者提供的服务**划分风险等级**」（R1–R5） | R1–R5 分级同样是经营机构义务 |
| **第二十二条** | 禁止经营机构「向不符合准入要求的投资者销售产品或者提供服务」；「**向普通投资者主动推介风险等级高于其风险承受能力的产品或者服务**」 | 任何基于「用户风险等级」的筛选/推荐均在此列 |
| **第二十九条** | 经营机构应当「制定适当性内部管理制度……**并对每名投资者提出匹配意见**」 | 「匹配意见」是专属动作 |
| **第三十二条** | 匹配方案、告知警示资料、录音录像资料、自查报告等**保存期限不得少于 20 年** | 若做了，就要承担 20 年留痕义务——我们不具备 |

**投资者分级与产品分级的行业通行做法**（供识别用，我们不采用）：普通投资者按问卷得分分 C1(保守/1–20) / C2(谨慎/21–40) / C3(稳健/41–60) / C4(积极/61–80) / C5(激进/81–100)；产品/服务风险等级 R1–R5；匹配规则为 Cn 可买 Rn 及以下。

### 4.2 定位：风险暴露解释器

> **不判定你该承担什么风险，只解释你正在承担什么风险。**

一句话区分两种做法：

- ❌ **裁判**（我们不做）：「你是 C3 稳健型，这个 R4 产品不适合你。」—— 给用户贴标签，需要牌照。
- ✅ **解释器**（我们做）：「你关注的 8 只票里 5 只在同一条产业链上，今天同跌，因为上游原材料降价。**你以为分散了，其实押注了同一个变量。**」—— 讲清楚事实与机制，不需要牌照，且更有用。

**为什么这是更优解而不是妥协**：

1. **合规最优**：落在中证协分级里唯一被点名「优先推广」的格子。
2. **与宪章一致**：解释器，不做荐股机。
3. **竞品空缺**：同花顺有牌照所以做「风险等级评估」（判定用户），蚂小财做「理财健康体检」（评估行为）——**没有人把「组合暴露的机制」讲清楚**。
4. **数据可支撑**：六个维度全部可由现有 Provider 计算（§4.5），无新增付费数据源。
5. **它让自选和知识库产生关系**：这是三模块闭环的中介，单独做风险没有意义。

### 4.5 六个暴露维度

| # | 维度 | 计算 | 数据源 | 一句话结论形态 |
|---|---|---|---|---|
| 1 | **集中度** | 单只权重、Top3 权重和、HHI（赫芬达尔指数 = Σwᵢ²） | 用户仓位（可选）/ 等权兜底 | 「前 3 只占了 71%，你的盈亏主要由它们决定」 |
| 2 | **行业重叠** | 行业分布、CR3 行业占比、是否同一产业链上下游 | 东财板块 `fs=m:90+t:2` / 涨停池 `hybk` | 「5 只在同一条链上，你以为分散了」 |
| 3 | **相关性** | 两两 20 日收益 Pearson 相关系数、同涨同跌天数占比 | 腾讯 K 线 `web.ifzq.gtimg.cn` | 「这 3 只近 20 天有 16 天同向，几乎等于一只票」 |
| 4 | **波动暴露** | 组合加权年化波动率 ÷ 沪深300 年化波动率 | 同上 | 「你的组合波动是大盘的 1.8 倍」 |
| 5 | **事件风险** | 未来 30 天解禁 / 财报预约 / 分红除权；近 30 天减持、质押、商誉占比、ST 预警 | 东财 `datacenter-web`（`RPT_LICO_FN_CPD`、股东户数、龙虎榜）+ `np-anotice-stock` 公告 | 「未来 30 天有 2 只解禁，1 只财报预约」 |
| 6 | **情绪暴露** | 自选中涨停/连板/换手率 Top 分位占比 | 东财 `push2ex/getTopicZTPool`（`lbc`/`fund`）+ 资金流 | 「有 3 只在连板梯队里，波动会明显放大」 |

**维度 1–4 需要权重**：用户填了仓位用真实权重；未填用等权，并在**该维度卡片上单独标注「等权估算」**（不只页头一处）。这符合项目「口径诚实」铁律。

**全部结论由规则引擎产出，不调 LLM**。理由：① 暴露指标是确定性计算，LLM 无从发挥且会引入幻觉；② 端侧计算零延迟、可单测；③ 合规上可完全归因。AI 只在**机制说明**环节介入（§4.6 FR-R4），且形态受 doc 21「AI 克制三铁律」约束。

## 5. 知识库（Knowledge）

### 5.1 现状诊断

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| K-1 | **藏得太深** | 入口仅抽屉 `onOpenGlossary`，2 层深 | 用户「天天给他找」——找不到 |
| K-2 | **它是词典列表，不是知识库** | 61 条按 5 类分组平铺，组头为纯文字 | 看不出 MACD 与均线谁先学，看不出学会 KDJ 需要什么前置知识 |
| K-3 | **与使用场景脱节** | 聊天内的高亮解释（已有且好）与术语表页**完全隔离** | 两侧不通，术语表页沦为「没人来的图书馆」 |

### 5.2 理论依据

#### 5.2.1 五个需求时刻（Gottfredson, Moments of Need）

| # | 时刻 | 当前覆盖 |
|---|---|---|
| 1 | 第一次学（New） | ✅ 术语表页浏览 |
| 2 | 想学更多（More） | ✅ 进阶解释手风琴 |
| 3 | **试着应用 / 记住（Apply）** | ❌ |
| 4 | 事情变了（Change） | ❌ |
| 5 | **出错了 / 看不懂（Solve）** | ⚠️ 部分（聊天内高亮） |

**时刻 3 与时刻 5 恰恰是散户最需要知识的瞬间**——看到「MACD 底背离」看不懂的那一刻，看到「你的组合相关系数 0.82」看不懂的那一刻。当前产品在这两个时刻几乎缺位。

#### 5.2.2 Just-in-time 的辩证（本文核心论证）

- **纯 Just-in-case**（先建知识库存，等未来调用）：动机为零。知识留存率在课程结束后 30 分钟内掉到 6 成以下，2 天后所剩无几。**这正是当前术语表页的问题——没人主动来读词典。**
- **纯 Just-in-time**（只在遇到时解释）：陷阱是**碎片化，形不成认知地图**——「就像一个城市拥有无数条道路，却没有地图：每次都能到达目的地，却不知道自己究竟身处哪里。」
- **正确解：JIT 触发 + 地图收敛，双向绑定。**
  - JIT 层负责**动机**（在卡住的那一刻出现）
  - 地图层负责**结构**（回答「我到哪了，下一步学什么」）
  - 每次 JIT 触发都记一笔，汇入地图；地图反向告诉 JIT 层「这个词你已经遇到 3 次了，要不要把这一组系统看一下」

**这条论证直接决定了知识库的产品形态**：它不是「更好的词典列表」，而是**一张属于用户自己的、会生长的认知地图**。

### 5.3 定位：三层知识架构

```

    术语在用户卡住的那一刻出现在原地
    已有：EntityRichText 高亮 + DefinitionCard
    扩展：自选聚合结论 / 风险暴露解释 / 市场页口径角标 / 详情页财务字段
      │
      │ 每次触发记一笔
      ▼
L1 我的知识地图（Map）  ← 替代现有术语表首页，本文新增
    5 个概念域的掌握度地图 + 「下一步该懂什么」
    形态：层叠面板，非卡片列表（doc 24 §5.3）
      │
      │ 发现缺口
      ▼
```

### 5.6 功能需求

#### P0

**FR-K2 术语掌握状态**
```kotlin
enum class TermState { UNSEEN, SEEN, FAMILIAR, READ }
// 判定：SEEN=点开过1次；FAMILIAR=触发≥3次；READ=主动标记 或 连续2次触发未再点开
data class TermProgress(val key: String, val state: TermState, val hitCount: Int, val lastAt: Long)
```
- 持久化到本地（同 `WatchlistStore` 体系），不外传
- 状态**只影响排序与推荐**，不做任何能力评价
- 验收：杀进程重启保留；状态迁移规则单测覆盖

**FR-K3 前置依赖图**
- 每个词条增加 `prerequisites: List<String>`（前置词 key）与 `leadsTo: List<String>`（后继）
- 词条卡底部显示「要先懂：均线 → 看懂后：布林带」
- 点击任一依赖 → 跳到该词（并记一笔 SEEN）
- 验收：技术指标类 16 词的依赖关系全部填写且无环（单测）

**FR-K4 JIT 触发埋点统一收口**
- 统一入口 `TermTracker.mark(key, source)`，`source ∈ {chat, watchlist, riskmap, market, detail, search}`
- 触发点：聊天实体高亮（已有）、自选聚合结论、风险地图六维度标题、市场页口径角标、详情页财务字段
- 每次触发 `hitCount++`，汇入知识地图
- 验收：六个 source 全部可达；重复触发不重复计数（同一会话同词 5 分钟内合并）

**FR-K5 术语内联解释（L0）**
