## 1. 这份规范解决什么问题

改造前，`WelcomeSection` 的全部实现只有 27 行：

```kotlin
internal fun ViewContainer<*, *>.WelcomeSection(theme: StockChatTheme, onChoose: (String) -> Unit) {
    View {
        attr { paddingTop(52f); paddingLeft(20f); paddingRight(20f); alignItemsCenter() }
        View {
            attr { size(56f, 56f); allCenter(); borderRadius(16f); backgroundColor(theme.brand) }
            Text { attr { text("↗"); fontSize(29f); fontWeightBold(); color(theme.onBrand) } }
        }
        Text { attr { text("你好，我是股问 AI"); ... } }
        Text { attr { text("做股民的解释器，不做荐股机"); ... } }
        WelcomeChip("📊", "贵州茅台今天为什么跌？", theme.riseSoft, theme.rise, theme, onChoose)
        WelcomeChip("📖", "MACD 金叉是什么意思？", theme.brandSoft, theme.term, theme, onChoose)
        WelcomeChip("⚖", "茅台和五粮液怎么选？", theme.brandSoft, theme.brand, theme, onChoose)
    }
}
```

它存在五个问题，其中最后一个是**合规硬伤**：

| # | 问题                         | 具体表现                           | 影响                                                                                 |
| - | -------------------------- | ------------------------------ | ---------------------------------------------------------------------------------- |
| 1 | **没有背景层**                  | 整个欢迎区就是 `page` 底色 + 居中三行文字     | 首屏视觉重量几乎为零，这是"太简洁"的第一观感来源                                                          |
| 2 | **图标是 emoji / Unicode 字符** | `↗` `⚖` `📊` `📖`              | 跨端字形不一致（Android / H5 差异明显），且项目已有 `LineIcons.kt` 线性图标库却未使用                          |
| 3 | **介绍词太薄**                  | 只有一句 slogan，没有能力说明             | 新用户不知道"我能拿它干什么"，能力边界不明                                                             |
| 4 | **信任资产没亮出来**               | ADR-11「意图与数据分离」保证行情零幻觉，但首屏只字未提 | 对抗"AI 给我 2024 年的资料"这一最大抱怨的武器，藏在架构文档里没人看                                            |
| 5 | **⚠️ 合规风险文案**              | 第三条示例「**茅台和五粮液怎么选？**」          | "怎么选"是选股建议的边缘，与 Non-goals「不做荐股机」直接冲突。中证协 2026-06 分级准入把「个股推荐、估值」列为**高风险，应审慎评估展业风险** |

**根因**：欢迎页被当成"一个占位提示"来实现，而不是"产品的第一张脸"。

**目标**：把首屏变成三件事的载体——**降低第一次开口的门槛**、**说清能力边界**、**亮出信任资产**。

## 2. 设计原则

| 原则                            | 说明                                              | 违反的代价                                 |
| ----------------------------- | ----------------------------------------------- | ------------------------------------- |
| **① 背景服务于内容，不抢戏**             | 背景层峰值透明度 ≤ 16%，且必须在深色模式下重测对比度                   | 背景一抢戏，就变成"花哨的金融 App"，与"克制 = 护城河"的定位冲突 |
| **② 介绍词只说"能解释什么"，不说"能帮你赚什么"** | 文案只能出现"解释 / 讲清 / 读懂 / 对比事实"，禁止"选 / 买 / 推荐 / 预测" | 踩合规红线，且摧毁"不做荐股机"的全部差异化                |
| **③ 信任必须在首屏可见**               | 把 ADR-11 的架构优势翻译成一句用户能懂的话                       | 用户不知道为什么该信你，就会拿你和"那些 AI 荐股的"归为一类      |

---

## 3. 信息架构：两档形态

欢迎页的价值是**降低第一次开口的门槛**，不是**每次都重新介绍自己**。老用户点"新会话"是来找入口的，不是来看介绍的。因此拆成两档：

| 区块           | 首次 / 空会话  | 新建会话（老用户）          |
| ------------ | --------- | ------------------ |
| 背景层          | 显示        | 显示（透明度降一档）         |
| 问候语          | 显示（按时段）   | 显示（按时段 + 后缀）       |
| Logo         | 52×52     | 36×36 或隐去          |
| 主标题 + slogan | 显示        | **隐去**             |
| 能力 pill（3 个） | 显示        | **隐去**             |
| 一句话说明        | 显示        | **隐去**             |
| 信任条          | 显示（玻璃卡内）  | 保留，压缩为单行 meta      |
| 示例问题         | 4 条（固定顺序） | 4 条（**从未问过的分类优先**） |

**效果**：精简版首屏高度压掉约 **40%**，用户直接进入示例问题区。

> **判档依据**：`ChatSessionStore` 已有会话记录 → 走精简档；全新安装 / 无历史 → 走完整档。

## 4. 介绍词文案规范

### 4.1 问候语（按时段变化）

| 时段          | 完整档 | 精简档      |
| ----------- | --- | -------- |
| 06:00–11:00 | 早上好 | 早上好，聊点新的 |
| 11:00–13:00 | 中午好 | 中午好，聊点新的 |
| 13:00–18:00 | 下午好 | 下午好，聊点新的 |
| 18:00–24:00 | 晚上好 | 晚上好，聊点新的 |
| 00:00–06:00 | 夜深了 | 夜深了，聊点新的 |

> 复用 `QuoteClock` 的当前时间取值逻辑，按本地小时判断。

### 4.2 主文案

| 位置      | 文案                                   | 令牌                                                         |
| ------- | ------------------------------------ | ---------------------------------------------------------- |
| 主标题     | 你好，我是股问                              | `theme.type.h1`（20f）· `fontWeightBold` · `textPrimary`     |
| Slogan  | 做股民的解释器，不做荐股机                        | `theme.type.sm`（13f）· `textSecondary`                      |
| 一句话说明   | 看不懂的行情、术语和财报，我讲给你听。只解释发生了什么，不预测该买什么。 | `theme.type.body`（14f）· `textSecondary` · 行高 1.75          |
| 能力 pill | 解释涨跌 · 讲清术语 · 读懂财报                   | `theme.type.meta`（10f）· `surfaceMuted` 底 · `textSecondary` |
| 信任条     | 🔒 行情来自交易所实时数据 · 每条结论都标了出处和时间        | `theme.type.meta`（10f）· `textTertiary`                     |



> **主标题从「你好，我是股问 AI」改为「你好，我是股问」**——去掉 "AI"。产品名就是产品名，不需要自我标注技术成分（正如微信不说"微信 App"）。

### 4.3 为什么信任条必须加

调研里最刺痛的一条用户原话：

> **"AI 一直给我过去的消息，问完一看股价根本不对，再问它，说看的是 2024 年的资料"**（新华社系媒体实测，2026-06）

股问的架构天然免疫这个问题——LLM 只出卡片意图，行情数字由端侧 Provider 填真实数据，幻觉无法污染任何一个数字（ADR-11）。**但用户不读架构文档。**

把这句话放进首屏，是成本最低、差异化最强的信任建设：**一句话，把架构优势翻译成用户能懂的语言。**

## 5. 示例问题规范

### 5.1 四条示例（含分类标签与副说明）

| 分类       | 问法                  | 副说明              | 图标底 / 图标色             |
| -------- | ------------------- | ---------------- | --------------------- |
| 解释异动     | 贵州茅台今天为什么跌？         | 消息面 · 资金面 · 板块联动 | `riseSoft` / `rise`   |
| 讲清术语     | MACD 金叉是什么意思？       | 一句话讲清，再举个例子      | `brandSoft` / `term`  |
| 读懂财报     | 用三句话讲下贵州茅台的中报       | 营收 · 净利 · 同比变化   | `fallSoft` / `fall`   |
| **事实对比** | **对比茅台和五粮液的营收与净利润** | **只陈事实，不做选择建议**  | `brandSoft` / `brand` |

**第三条「读懂财报」是新增的**：财报季是证券 App 月活增长的主因之一（易观千帆 / 每经 2026-05-22），而"不懂基础财报分析"的散户占 **49%**（雪球整理）。原三条里没有财报入口，是一个明显的能力缺口。

### 5.2 ⚠️ 合规红线（写死，不可协商）

> **欢迎区里任何一条引导，都不能出现：「怎么选」「该不该买」「值得买吗」「推荐」「能否买入」。**

原第三条「茅台和五粮液怎么选？」必须替换为「对比茅台和五粮液的营收与净利润」——**只陈述事实，不做选择建议**，不碰中证协分级表中"高风险"的个股推荐与估值。

**判据**：问法必须是**可陈述事实**的（是多少 / 为什么 / 什么意思 / 对比什么），不能是**需要价值判断**的（选哪个 / 该不该 / 好不好）。

> 参考：东方财富妙想被问"推荐几只个股"时答"我不能直接推荐，但选出以下结果参考"然后筛出 10 只——这种"嘴上说不要、身体很诚实"的形态，恰恰是合规风险最高的形态。股问不沾这条边。

### 5.3 精简档的轮换策略

在 `KeyValueStorage` 里维护一个"已问过的分类"集合，新建会话时**优先取未覆盖的分类**，全部覆盖后回到默认顺序。避免老用户每次新建都看到同样的四个问题。

## 6. 视觉规范

### 6.1 Token 映射（禁止新增硬编码色值）

| 元素             | 令牌                                                                                     |
| -------------- | -------------------------------------------------------------------------------------- |
| 页面底            | `theme.page`                                                                           |
| 玻璃卡 / 示例卡      | `theme.surface`（方案 A 用 `theme.glass` 材质）                                               |
| 能力 pill 底      | `theme.surfaceMuted`                                                                   |
| 主标题 / 正文 / 副说明 | `theme.textPrimary` / `textSecondary` / `textTertiary`                                 |
| Logo 渐变        | `theme.brand` → `theme.term`（135°）                                                     |
| 图标配色           | 见 5.1 表，全部取自 `riseSoft`/`rise`/`brandSoft`/`term`/`fallSoft`/`fall`                    |
| 分隔线            | `theme.divider`                                                                        |
| 字号             | 全部走 `theme.type`（display 38 / h1 20 / title 16 / body 14 / sm 13 / label 11 / meta 10） |
| 间距             | 全部走 `theme.spacing`（xs 4 / sm 8 / md 12 / lg 16 / xl 20 / x2 24 / x3 28 / x4 32）       |

### 6.2 三个方案

| 方案                    | 背景做法                               | 内容容器                                           | 气质                              | 风险                                        |
| --------------------- | ---------------------------------- | ---------------------------------------------- | ------------------------------- | ----------------------------------------- |
| **A · 光晕玻璃态**（推荐）     | 2–3 个品牌色径向渐变光斑，峰值透明度 ≤16%，随滚动轻微视差  | 玻璃卡承载介绍词（复用 `GlassContainer`，与顶栏岛、输入栏胶囊同一材质系统） | 有存在感但不抢戏，与项目玻璃态长板一脉相承           | Kuikly 无原生 `radial-gradient`，需降级方案（见 6.3） |
| **B · 行情纹理底**         | 抽象 K 线 + 网格 SVG 底纹（透明度 ≤6%），顶部渐隐遮罩 | 无容器，内容直接铺在纹理上                                  | 金融属性强，信息密度高，偏专业                 | 纹理密度难调，稍重就显"老牌行情软件"（大智慧被吐槽"界面老旧"）         |
| **C · 极简留白** ✅**已选定** | 纯底 + 顶部一束柔光                        | 无容器，靠留白与关键词轮播动效引导                              | 最克制，与"克制 = 护城河"定位最一致；**降级成本最低** | 首屏偏空 → 用 6.4.3 的密度补偿解决                    |

> **选型说明**：三个方案的介绍词、示例问题、两档形态完全一致，差异只在背景与容器。  
> 选 C 的实质是——**把"背景"做到最轻，把注意力全部还给内容**。这既最贴合股问的克制定位，也让 Kuikly 端降级成本最低：柔光去掉后视觉损失几乎为零，而方案 A 降级后反而会退化成 C。

### 6.3 方案 A 背景的 Kuikly 落地路径

Kuikly 无原生 `radial-gradient`。两条路：

1. **优先**：背景层用 `Blur` + 纯色 View 叠加模拟光晕，复用 `glass/GlassRenderer` 的三级降级（实时 Blur → 快照 → 92% 不透明简化）；目标端无 Blur 时**退回纯 `page` 底色，不伪装为玻璃**（沿用既有降级原则）。
2. **备选**：预置一张极轻的渐变位图（WebP，≤20KB），随包体分发。

> 降级第 3 档（92% 不透明简化）下，方案 A 会退化为接近方案 C 的观感——这是可接受的，符合"不支持时不伪装"的既有约定。

## 6.4 方案 C 详细规范（选定方案）

### 6.4.1 背景柔光

| 主题 | 参数                                                                                    |
| -- | ------------------------------------------------------------------------------------- |
| 浅色 | `radial-gradient(ellipse 78% 40% at 50% 22%, rgba(37,99,235,.075), transparent 70%)`  |
| 深色 | `radial-gradient(ellipse 78% 40% at 50% 22%, rgba(130,168,255,.10), transparent 70%)` |

- 柔光中心位于屏幕横向中点、纵向 **22%** 处（约在 Logo 与标题之间），形成自上而下的视觉引导
- 峰值透明度 **≤10%**，深色模式略高以补偿暗底的光感衰减
- **降级**：目标端不支持时**直接去掉柔光，退回纯 `page` 底色**。这是 C 相对 A 的最大优势——去掉后不产生任何"半途而废"的观感

### 6.4.2 留白节奏（dp）

| 元素      | 上间距     | 备注                                         |
| ------- | ------- | ------------------------------------------ |
| 问候语     | 18      | 状态栏 + 导航行之下                                |
| Logo    | 10      | 完整档 52×52 ／ 精简档 36×36                      |
| 主标题     | 16      | `type.h1` 20f                              |
| Slogan  | 6       | `type.sm` 13f                              |
| 一句话说明   | 16      | `type.body` 14f，行高 **1.9**（比 A 更松，用行高换呼吸感） |
| **信任条** | **24**  | **比 A 的 11 大得多——用它做视觉分隔，替代玻璃卡的分隔作用**       |
| 分组标题    | 20      | `type.label` 10f                           |
| 示例卡     | 8（卡间 8） | 密度区开始                                      |
| 输入栏     | 16      | —                                          |

### 6.4.3 密度补偿（防止首屏偏空）

方案 C 唯一的风险是"空"。三招补偿，本质都是**用对比制造层次**：

1. **上松下紧**——上方（问候 → 信任条）用大留白，下方（示例卡）用 8dp 紧密排布。留白与密度形成对比，反而更聚焦。
2. **信任条做分隔**——把信任条上间距拉到 24dp，让它承担"分隔线"的角色：省掉一条 `divider`，也省掉一个玻璃卡容器。
3. **示例卡保持白底 + 边框**（`surface` + `divider`），在一片留白中形成明确的密度区，成为视觉落点。

> **判断标准**：首屏滚动前，用户视线应落在**示例问题区**，而不是中间的空白。**留白是过渡，不是终点。**

### 6.4.4 关键词轮播动效（方案 C 唯一动效）

| 参数   | 值                                  |
| ---- | ---------------------------------- |
| 词表   | 行情 → 术语 → 财报 → 公告                  |
| 显示速度 | **200ms / 字**                      |
| 完整停留 | **1200ms**                         |
| 删除速度 | **120ms / 字**                      |
| 切换间隔 | 300ms                              |
| 光标   | 宽 2px，`brand` 色，1.1s `step-end` 闪烁 |
| 单轮周期 | 约 3.4s                             |

**动效必须可中断**（否则会变成噪音）：

| 触发           | 行为              |
| ------------ | --------------- |
| 用户聚焦输入框      | 立即停止，固定为默认词「行情」 |
| 用户点击任一示例问题   | 立即停止            |
| 页面离屏 / 进入详情页 | 立即停止，返回时不再自动重启  |

**无障碍**：系统开启「减弱动态效果」时，**停止轮播**，静态显示「行情」，不闪烁光标。

> **节奏与详情页规范区分**：AI 回答正文打字机 **30ms/字**（详情页改版方案 F 节），欢迎区关键词轮播 **200ms/字**。前者是长文本快速呈现，后者是 2 字短词需要停留——场景不同，不可混用。

### 6.4.5 两档形态在方案 C 下的差异

|       | 完整档           | 精简档                  |
| ----- | ------------- | -------------------- |
| 柔光    | 显示            | 显示（透明度 ×0.6）         |
| 一句话说明 | 含轮播词的完整两行     | **整段隐去**（轮播动效随之消失）   |
| 信任条   | 上间距 24dp，作为分隔 | 上间距压到 12dp，作为单行 meta |

> 注意：**轮播动效只存在于完整档**。精简档本来就隐去了一句话说明，不额外加动效——老用户不需要被逗趣。

## 7. 落地要点

| 项        | 说明                                                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **图标**   | 全部换成 `LineIcons.kt` 线性图标（需新增：`trend-down` / `book` / `file-text` / `columns` / `shield-check`，stroke 1.8，24×24 viewBox）。**不再使用任何 emoji 或 Unicode 字符作图标。**                                    |
| **组件拆分** | 现状 `WelcomeSection` 一个函数塞完所有内容。建议拆为：`WelcomeBackdrop`（背景层，按方案可替换）、`WelcomeHero`（问候 + Logo + 标题 + slogan）、`WelcomeCapabilityRow`（能力 pill）、`WelcomeTrustRow`（信任条）、`QuestionStarterCard`（示例卡）。  |
| **两档切换** | `WelcomeSection(theme, mode: WelcomeMode, onChoose)`，`WelcomeMode` 枚举 `FULL` / `BRIEF`。由 `ChatPage` 根据 `ChatSessionStore` 是否有历史会话传入。                                                         |
| **示例轮换** | `KeyValueStorage` 存已问分类集合；精简档从未覆盖分类优先取。                                                                                                                                                      |
| **无障碍**  | 示例卡需带可点击语义与朗读文案（"示例问题：贵州茅台今天为什么跌？"）；Logo 标记为装饰元素不朗读。                                                                                                                                         |
| **动效**   | 方案 A/B 只做首屏 300ms 淡入 + 卡片依次上滑 40ms 阶梯延迟。方案 C 另需关键词轮播（200ms/字递进子串）。**注意与「详情页高级感改版方案」的节奏区分**：AI 回答正文打字机沿用 **30ms/字**（见当日详情页规范 F 节），欢迎区关键词轮播用 **200ms/字**——前者是长文本快速呈现，后者是 2 字短词需停留，两者场景不同，不可混用。 |

## 8. 验收标准

- [ ] 首屏在浅色 / 深色两种主题下均无对比度问题（背景峰值透明度 ≤16%，尤其在深色模式下重测）
- [ ] 欢迎区**不含任何 emoji 或 Unicode 字符图标**，全部为 `LineIcons` 线性图标
- [ ] 示例问题文案**不含**「怎么选 / 该不该买 / 值得买吗 / 推荐」任一词汇
- [ ] 信任条文案在首屏可见，且无需滚动即可读到
- [ ] 有历史会话时点"新会话"，走精简档：主标题 / slogan / 能力 pill / 一句话说明均不出现
- [ ] Android 真机 + H5 两端字形一致（重点验 `LineIcons` 与中文行高）
- [ ] 背景层在不支持 Blur 的目标端正确降级为纯 `page` 底色，不出现半透明残影
- [ ] 点击任一示例问题，问题文本正确注入输入框并可发送
- [ ] 所有颜色、字号、间距取自 `StockChatTheme` 令牌，全文件无硬编码色值
