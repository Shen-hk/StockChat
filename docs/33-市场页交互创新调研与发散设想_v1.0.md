## 1. 现状诊断：doc 31 补的是"规范缺口"，页面本质仍是"照片"

31 号文档做了两件事：补齐 spec 22 的 4 条动效缺口、把 AI 复盘卡从静态文案升级为流式。这些是**合规且必要**的，但做完之后市场页的本质没变：

> **每一个数字都是"现在时"。页面展示的是最新一帧快照，过去的数据在每次刷新时被随手丢弃。**

而市场页与详情页最大的不同恰恰是：详情页的资产是"这一只股票的深度"，市场页的资产是**"全市场 × 时间的广度"**。宽度、涨停数、封板率、板块榜……这些数据每 3 秒就在管道里流过一次（spec 22 §7 轮询预算），`MarketPage.refreshOverview` 拿到 `MarketOverview` 后渲染最新值，**旧帧直接被覆盖**。用户问"今天市场怎么样"，其实问的是"今天市场**经历了**什么"——一条河被压成了一张照片。

**核心判断**：市场页交互创新的最大金矿不在新组件、新 AI 能力，而在**把已经轮询过、却被丢弃的"上一帧"存下来**。时间维度一建立，回放、叙事、时刻、对比、年轮五类交互全部解锁——这就是"交互的基础是数据的丰富"在本页的具体形状。

## 2. 数据富矿盘点（本文的地基）

按"已在管道里流 / 在返回里但被丢弃 / 端侧可派生"三层盘点（字段以 `MarketInsightProvider.kt` 现有模型为准）：

| 层 | 数据资产 | 现状 | 存下来之后解锁什么 |
|---|---|---|---|
| 在流 | `MarketOverview` 全量（指数、宽度三数、涨停/跌停、封板率、炸板数、最高板、量能三档、北向、板块榜） | 只渲染最新帧，旧帧覆盖 | **快照序列**：全页时间机器、叙事轴、温度日内轨迹 |
| 在流 | 涨停池 `LimitUpStock`（sector / consecutiveBoards / sealedAmount / **openCount 炸板次数**） | 聚合成 4 个数字 | 池子成员差分 → **涨停潮 / 炸板潮时刻检测**（哪一分钟哪个板块集中上板） |
| 在流 | 板块榜 `SectorRank`（mainFlow / changePercent） | 取 TopN 渲染 | **位次序列** → 板块超车动画、主线切换判定有了连续证据 |
| 在流 | 新浪全市场列表（宽度来源） | 聚合成 3 个数 | 每分钟红盘率点 → **分时宽度曲线**（个股涨跌 AD 线，零售端极少见） |
| 丢弃 | 腾讯指数分时（详情页已在用） | 市场页未复用 | 叙事轴副曲线、昨日影子线 |
| 派生 | 每日收盘归档（涨停数/封板率/红盘率/量能，一行/日） | 无 | **情绪年轮**：60 交易日热力条（冷启动用内置近 30 日基线） |
| 派生 | `EventDetector` 端侧规则（量能突变 / 宽度急变 / 涨停潮 / 炸板潮 / 封板率破阈） | 无（doc 21 §4 阈值已有定义） | **事件流**：关键时刻卡、高能条、复盘句锚点 |

**结论**：九成创新**零新数据源、零新请求**——只需要一个端侧 `SnapshotStore`（按分钟节流存快照，240 帧/交易日，内存 ring buffer + 单日归档）。数据早就在流，只是没人接住它。

## 3. 外部场景调研（10 个来源）

| 来源 | 效果 | 为什么妙 | 转译价值 |
|---|---|---|---|
| 彩云天气 · 雷达回放 | 拖动时间轴逐帧回放过去/推演未来的雨图，「拖动时间轴，就像进度条一样把雨势演给你看」 | 把"一张天气截图"变成"一段可回放的天气纪录片"，时间轴是第一交互 | 全页回放 scrub（②） |
| 英雄联盟 · 经济差曲线 | 转播顶部一条**发散曲线**：中轴上方蓝方优势、下方红方优势，团战事件钉在曲线上 | 一条曲线同时回答"谁占优、优势多大、什么时候易手" | 多空叙事轴的形状语言（①） |
| ESPN · 赛后胜率图 + Excitement Index | 赛后回放整场胜率摆动曲线；把逐回合胜率变化绝对值求和 = "比赛精彩程度指数" | **赛后回放形态被广泛赞，实时胜率被骂**（Defector：实时概率与比分冗余、误导）——启示：只做已发生事实的回放，不做预测 | 只做复盘态回放；"波动强度"可做描述性指标（合规安全） |
| F1 · Timing Tower | 常驻位置塔，位次变动、进站、攻防一目了然；2026 新版因简化过度被车迷骂 | 位次**变动本身**就是信息；但"过度简化数字精度"会被资深用户反感——A 股用户同理，精度不可牺牲 | 板块竞速场（⑤） |
| B站 · 高能进度条 | 弹幕密度波形叠加在进度条上，波峰 = 高能时刻，点波峰直达 | 用户贡献的数据密度变成导航地图——**进度条本身成了内容** | 事件密度波形 = 叙事轴的底层视觉（①③共用） |
| Spotify Wrapped | 竖屏逐帧故事卡，每帧一个 Big Ass Number，无图表、强叙事、零分享成本 | "数据报告"做成"性格测试"式的身份叙事；结构 = 钩子→铺垫→反转→揭晓 | 收盘五帧（⑧）；克制点：一年一次 vs 我们一天一次必须更轻 |
| GitHub · 贡献热力图 | 365 天格子墙，一眼看到活跃周期与断档 | 把"长期习惯"压成一个可扫视的色块矩阵 | 情绪年轮（⑦） |
| CNN · 恐贪指数 | 七分量等权仪表盘，指针 + 分量表 | **先例**：把 7 个指标压成 1 个数，但分量公开可查 | 透明情绪温度计（⑥）的分量拆解范式 |
| 开盘啦 · 市场情绪温度计 | 0–100 综合强度（绿/橙/红），涨停表现/赚钱效应/连板高度评分 ⚠️ **本土已有先例** | 证明需求真实存在；但其话术是"判断未来大盘强弱"（预测向），且公式黑箱 | **差异化**：只描述不预测 + 公式全透明可点开 + 日内轨迹曲线。不差异化就是抄开盘啦 |
| 电竞赛后战报 · 时间轴 | 击杀/推塔/龙团按时间轴排列，点节点看回放 | 把"一场比赛"压缩成"5 个值得回看的节点" | 关键时刻卡（③） |

**共性提炼**：天气、电竞、体育、视频四个场景都完成了同一次跃迁——**从"显示当前值"跃迁到"把时间做成可交互的对象"**。行情数据的时间密度远高于以上任何场景，却只有分时图一处用到了时间，还是"看价"而非"看势"。

## 4. 市场页交互第六宪章

27 号宪章五（就地作答）管详情页。市场页追加一条：

> **六 · 可回放（Replayable）**：市场页是一部**可拖动的纪录片，不是一张照片**。页面上任何数字都应能回答"当时呢？"——拖回任意时刻，整页回到那一刻；松手回"现在"，回放中必须带「历史回放」水印，绝不与实时混淆。

两条从宪章：**① 全部回放只覆盖已发生事实**（ESPN 教训：实时概率是误导，赛后回放是共识）；**② 事件的检测全部端侧规则**（复用 doc 21 §4 阈值），AI 只负责把事件串成话，不负责发现事件。

## 5. 八个发散设想

### ① 今日叙事轴 Storyline ★★★★★（P1 亮点，新 Hero 候选）

**灵感**：LoL 经济差曲线 + B站高能进度条 + ESPN 赛后胜率图。
**一句话**：Hero 下方一条**多空叙事轴**——中轴 50（多空平衡），上方红色面积 = 红盘率超出部分，下方绿色面积 = 失守部分，量能密度作底部细条；端侧检测出的 4–6 个事件以钉子标在轴上。
**惊艳点**：今天"冲高回落、尾盘修复"的故事，一条曲线讲完；比 8 个并排数字快 10 秒。
**数据基础**：新浪全市场列表每分钟红盘率（已在算，只差存点）+ EventDetector。
**市场 ≠ 上证**：主曲线默认**全市场口径**（红盘率），可切换上证/创业板/北证50 等指数度量，分界线随口径变化（50% ↔ 昨收 0%）。「北证50 逆势走强」这类信号只在多指数口径下可见——这正是 doc 21 保留完整指数带的理由，叙事轴不能把市场压扁成单一上证。
**克制点**：轴是**数据本体**不是装饰；事件钉 ≤6；收盘态最完整，盘中实时生长。

### ② 时间机器 TimeScrub ★★★★★（P1 亮点，本篇的"圈选即问"）

**灵感**：彩云天气雷达回放 + Google Maps 时间线。
**一句话**：**拖动叙事轴 = 全页回到那一刻**——指数、宽度条、涨停四维、量能、北向、梯队、板块榜全部随帧更新；回放中顶部出现「正在看 10:42 的市场 · 历史回放」品牌色水印 chip + 「回到现在」按钮。
**惊艳点**：用户第一次"拖动整个市场"——没有 A 股零售 App 支持整页时间回放（个股分时回放有，全市场页面级回放无）。
**数据基础**：`SnapshotStore`（核心新增基建，§7）。快照序列**天然含全部指数**（`MarketOverview.indices` 本就是列表，腾讯一次批量快照即返回）——时间机器的作用面是**整个指数带**，不是单一上证。
**克制点**：回放态全部数字降饱和 5% + 水印常驻，杜绝"把历史当实时"的误读；二次确认不弹窗，一键回现在；午休/休市回放到边界帧为止。

### ③ 关键时刻 KeyMoments ★★★★（P1）

**灵感**：电竞战报时间轴 + 27④ 异动声呐（详情页版）。
**一句话**：叙事轴下方一排**横向时刻卡**（09:31 竞价·机器人涨停潮 / 10:42 放量跳水 / 13:32 二次探底·炸板潮 / 14:47 尾盘回流），每卡 = 时间 + 一句事实 + 3 个关键数，点卡 = 时间机器跳到该帧。
**数据基础**：EventDetector 纯函数（阈值全部沿用 doc 21 §4：量能偏离 >10%、封板率 <80%、涨停数环比骤降 >70% 等），单测友好。
**克制点**：≤6 张卡；每句必须是**已发生的统计事实**；无事件日不显示（铁律 1：条件触发）。

### ④ 可导航复盘 NavigableRecap ★★★★（P1，直接回应"31 的 AI 卡不够"）

**灵感**：27② 句图联动的市场页版。
**一句话**：AI 复盘卡从"一段流式文字"升级为 **3–5 句带时间锚点的叙事句**——每句右侧挂时间区间角标，点句子 → 叙事轴对应段高亮 + 时间机器跳到该段起点；反向：scrub 经过某句的区间时该句点亮。
**惊艳点**：复盘从"结论"变成"目录"——「10:42 放量跳水，封板率 85%→62%」这句话是真的可以走过去的。
**数据基础**：分句与锚点由**端侧模板生成**（句子槽位自带 timeRange，事件流填充），LLM 只润色措辞、不发明坐标——27② 已验证的 anchor 机制直接复用。
**克制点**：与 31 号 AI 复盘卡同一状态机（idle→thinking→streaming→done），流式完成后逐句挂锚点；无 Key 时维持 31 号降级路径。

### ⑤ 板块竞速场 SectorRace ★★★☆（P2）

**灵感**：F1 Timing Tower。
**一句话**：板块榜 Top5 的**位次变动可视化**——scrub 时间轴时，板块行按位次重排，超车行闪一下品牌色 + 「↑3」位次箭头（对比 30 分钟前）；「存储芯片 7→1」的主线切换在竞速场里是被看见的。
**数据基础**：板块榜轮询的位次序列（已在每次刷新里返回，只差存位次）。
**克制点**：只在回放/scrub 时重排，实时态位次箭头静默；不构成推荐语义（榜单本身已在 doc 21 收录，本条只加时间维度）。

### ⑥ 透明情绪温度计 TempTransparent ★★★☆（P2）

**灵感**：CNN 恐贪指数 + 开盘啦温度计（先例，见 §3 诚实标注）。
**一句话**：现有 `moodScore`（端侧已算）升级为**可解释的温度计**——数值 + 弧形表盘 + **分量拆解**（宽度贡献 x、涨停热度贡献 y、封板率贡献 z，公式点开可见）+ 日内轨迹小曲线（温度是怎么走到现在的）。
**差异化（不做就是抄）**：开盘啦的话术是"判断未来大盘强弱"，我们**只描述**："今天 46°，比昨早同时刻低 9°，主要是封板率拖累"——解释器，不是裁判。
**数据基础**：moodScore 已在 `MarketOverview`；分量来自快照序列。
**克制点**：禁用「你的风险等级/评分/匹配」类措辞（铁律 7 合规词表）；温度是市场温度，不是用户分数。

### ⑦ 情绪年轮 SentimentRings ★★☆（P3）

**灵感**：GitHub 贡献热力图。
**一句话**：量能卡下加一条**60 交易日热力带**（每格 = 一天，颜色深浅 = 涨停数或红盘率），点格子浮出当日三数摘要；今天是哪一格、处于近 60 日什么分位，一眼可扫。
**数据基础**：每日收盘归档一行/日（端侧），冷启动内置近 30 日基线。
**克制点**：P3，等归档积累；不得变成"历史会重演"的暗示文案。

### ⑧ 收盘五帧 MarketWrapped ★★☆（P3）

**灵感**：Spotify Wrapped。
**一句话**：收盘后首次进入市场页，复盘卡收口处出现「今日五帧」入口——竖屏逐帧故事（5 帧，每帧一个 Big Ass Number：「3,306 · 冲高回落 0.6%」「54 → 42 · 涨停退潮」「1.79万亿 · 放量还是缩量」），末帧一键生成分享图。
**克制点**：一天一次、可跳过、不弹窗、不自动播放；与"不做社区"不冲突（分享是输出不是 UGC）。优先级最低，评审若砍先砍它。

## 7. 数据与工程基建（本篇的真正主角）

### 7.1 SnapshotStore（新增，纯端侧）

- 盘中 3s 轮询（spec 22 §7）照旧，但**按分钟节流入库**：每分钟第一帧 + 与上帧差异超阈值的补帧，240 帧/交易日封顶；字段 = `MarketOverview` 投影（宽度三数/涨停四维/量能/北向/板块 TopN 位次/红盘率）。
- 内存 ring buffer + 当日 JSON 归档；隔日只留日级一行（供⑦）。
- 纯 Kotlin class，不碰 UI 层，可注入假序列做单测；`ArchitectureBoundariesTest` 合规（provider 层内）。

### 7.2 EventDetector（新增，纯函数）

- 输入快照序列，输出 `List<MarketEvent>{minute, type, headline, facts}`；规则全部沿用 doc 21 §4 阈值 + 涨停池差分（新上板集中度、openCount 跳增）。
- 与 doc 22 §1 显著性分级同源：L2 事件才允许上钉子，天然控制事件数量 ≤6。

### 7.3 复用与合规机制

- 锚点：复用 27② `anchor {start,end}` 协议，市场页 anchor 的单位是**分钟索引**而非 timeline index。
- Kuikly R1–R5：scrub 驱动 `scrubMinute` observable，各分区在 `attr {}` 内读对应快照值（R1）；回放水印 vif 挂载不动画（R4 已知限制，可接受）；时刻卡跳转用补间驱动 `scrubMinute`，不新增 animate 驱动源。
- 回放态标识：水印 chip + 全页数字降饱和 5% + 「回到现在」常驻，三重防误读。

## 8. 合规与克制

- **零预测**：八个设想全部只描述**已发生**的事实与统计（ESPN 实时胜率被骂、赛后回放被赞的教训直接写进设计）；不做胜率、不做概率、不做"接下来会怎样"。
- **AI 预算不涨**：叙事轴钉子/时刻卡是端侧数据标记，不算 AI 触点；AI 触点仍是 31 号的复盘卡 1 处（升级为④形态），全页 ≤5 不变。
- **温度计措辞**：只说市场温度，禁"评分/等级/匹配/你的风险"词表；与开盘啦"判断未来强弱"话术明确划界。
- **开盘啦先例诚实声明**：⑥ 不差异化即重复造轮子，评审可砍。
- **无障碍**：叙事轴提供时刻卡按钮等效路径；reduced-motion 下 scrub 跳变、位次重排直接切换。

## 9. 验收要点

- [ ] SnapshotStore：240 分钟序列完整、节流正确、隔日归档一行、单测覆盖
- [ ] 时间机器：拖到任意分钟，全页 8 类数字与快照一致；回放水印 + 一键回现在；reduce-motion 正常
- [ ] 指数度量切换（红盘率↔上证↔创业板↔北证50）后曲线/钉子/游标一致；指数带全量随帧更新
- [ ] 叙事轴：红盘率曲线与宽度条同源一致；事件钉 ≤6 且与 EventDetector 输出一致
