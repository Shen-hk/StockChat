> 更新：2026-09-09 ｜ Owner：架构集成人 ｜ 状态：代码与单测完成，待 Android/H5 人工回归

## 本轮短规格

- 目标：将聊天欢迎区从 `ChatPage` 的页面状态中抽为 Data / State / Coordinator / Component 的纵向切片，不改变文案、路由、动画数值与手势行为。
- 范围：欢迎词轮播、光标、示例卡两帧入场与 600ms 安全兜底、示例卡使用记录、"看行情" 的滑块/震动/跳转时序。
- 边界：不改 Drawer、Island、Voice、实体拖拽、输入框焦点、流式贴底；不新增 Gradle 模块或全局 Store。
- 验收：页面只转发生命周期和平台 Effect；异步任务在离页/销毁后不再写 UI；R4/R5 入场注册顺序保持；Android/H5 功能等价。

## 已验证的时序不变量

1. 欢迎示例卡仍然是 mounted → 32ms → presented；组件持续在预状态注册 `easeOut`，不写 0 时长 reset。
2. `pageDidDisappear` 取消所有 welcome 任务；若在 32ms 窗口离页，返回后会重新触发第二帧，不会留下透明卡片。
3. "看行情" 保持 240ms 后先震动再路由、420ms 后复位；离页后旧回调被版本号拦截。
4. Coordinator 不读取消息 observable；它只使用 Page 在生命周期/会话动作中传入的普通快照，避免定时器在 reactive closure 外读状态。

## 可交给他人的低耦合重构任务

每项必须独立分支/commit，合并前运行 common 单测与 Android 编译；不要与 `ChatPage` 的其它状态机混改。

### M1：欢迎组件物理归档（低风险）

- Owner 文件：`page/components/ChatScaffolding.kt` 中 Welcome 类型与 `WelcomeSection`，迁到 `chat/welcome/component/ChatWelcomeSection.kt`。
- 允许：只移动 Welcome UI、starter model 与私有渲染函数；更新 import。
- 禁止：改变文案、padding、颜色、`animate()` 调用位置、延迟和回调签名。
- 验收：冷启动欢迎卡与新会话欢迎卡均完整显示；`ChatWelcomeCoordinatorTest` 通过。

### M2：CardSheetState（中低风险）

- Owner 文件：`ChatPage.kt` 的 `sheetCard`、`sheetMounted/presented`、`SheetLevel` 与 `open/dismiss/raise/lowerCardSheet`；组件为 `page/components/CardSheet.kt`。
- 输出：`chat/sheet/state/CardSheetState.kt` 与 `CardSheetCoordinator.kt`；Page 保留 Card 的平台/路由回调。
- 禁止：不要同时改实体拖拽、Drawer 或 Island 的 z-index/手势；预状态不可注册零时长动画。
- 验收：打开、下滑、上拉、关闭、快速连续打开均正常；Android 手测 CardSheet 层级高于聊天内容、低于 Drawer。

### M3：附件与媒体面板（中风险）

- Owner 文件：`ChatPage.kt` 的 `composerAttachments`、`mediaSheetMounted/presented`、原生媒体回调与附件预览渲染。
- 输出：`chat/composer/state/ComposerAttachmentState.kt`、`MediaSheetCoordinator.kt`；媒体原生结果通过 Page Effect 进入 state。
- 禁止：不改 TextArea focus、VoiceRecorder、发送协议；不要在 Timer/原生回调直接读 UI observable。
- 验收：图片/文档添加、删除、上限、面板开合、发送后清空；Android/H5 各走一次。
