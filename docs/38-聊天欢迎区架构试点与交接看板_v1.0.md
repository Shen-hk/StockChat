## 本轮短规格

- 目标：将聊天欢迎区从 `ChatPage` 的页面状态中抽为 Data / State / Coordinator / Component 的纵向切片，不改变文案、路由、动画数值与手势行为。
- 范围：欢迎词轮播、光标、示例卡两帧入场与 600ms 安全兜底、示例卡使用记录、"看行情" 的滑块/震动/跳转时序。
- 边界：不改 Drawer、Island、Voice、实体拖拽、输入框焦点、流式贴底；不新增 Gradle 模块或全局 Store。
- 验收：页面只转发生命周期和平台 Effect；异步任务在离页/销毁后不再写 UI；R4/R5 入场注册顺序保持；Android/H5 功能等价。

## 已验证的时序不变量

1. 欢迎示例卡仍然是 mounted → 32ms → presented；组件持续在预状态注册 `easeOut`，不写 0 时长 reset。
2. `pageDidDisappear` 取消所有 welcome 任务；若在 32ms 窗口离页，返回后会重新触发第二帧，不会留下透明卡片。
3. "看行情" 保持 240ms 后先震动再路由、420ms 后复位；离页后旧回调被版本号拦截。
4. Coordinator 不读取消息 observable；它只使用 Page 在生命周期/会话动作中传入的普通快照，避免定时器在 reactive closure 外读状态。

## 下一纵切：ChatScrollState（已完成，待人工回归）

- 目标：把“发送后贴底、流式跟随、用户上滑接管、流结束宽限”的普通状态、版本号和轮询 Timer 从 `ChatPage` 收口到 Coordinator；Page 仅执行 `setContentOffset` 与既有 follow-up UI 回调。
- 不变量：首次发送仍是 animated 滚到底；流式/内容长高一律非动画；用户拖离底部后绝不抢回；流结束的 1.5s 宽限和流前 19s watchdog 保持原值。
- R1 方案：`streamState` 仅在 `vbind`/event 内读取并同步到 Coordinator 的普通镜像字段；Timer 不读取 `viewModel.streamState` 或任何 UI observable。
- 边界：不搬 Scroller ref、内容高度计算、回顶按钮、键盘事件、follow-up 的两帧 UI；不改变动画和 native scroll 参数。
- 验收：fake scheduler 已覆盖首次动画贴底、用户上滑接管、流结束宽限、离页取消；Android/H5 构建通过，待手测发送→流式→上滑→再次发送。
- 修正：用户主动上滑现在会取消尚未到期的发送贴底窗口，避免后台定时器把用户从历史消息强行拉回底部。
