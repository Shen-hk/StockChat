## 三、开发过程中遇到的问题

### 动效静默失效——Kuikly 声明式动画冻结

代码不报错、没有日志，但动画不播或降级成瞬间跳变。逐个排查后复现出这几条规律：

1. **animate() 的驱动 key 是隐式的**：它绑定的是 attr 块内"最后读取的那个 observable"，而不是显式参数。实测在 `attr {}` 里如果 `animate()` 之前读了别的 observable，驱动 key 就会被抢走，目标动画不生效。
2. **注册滞后一个变更周期**：看实现是 `beginApplyAttrProperty()` 先消费上一个周期的注册（AnimationState next→cur），然后重跑 attr 闭包、本周期的 `animate()` 只进 nextAnimations。也就是说"这次变更播放的动画"其实是"上个周期注册的那个"。这带来几个反直觉的推论：
   - 每个变更周期都必须无条件注册动画（否则下次变更没动画可播）；
   - 注册一个 `linear(0f)` 的 reset 动画会被下一次变更消费掉，导致入场降级为跳变；
   - 而同值写入因为 `ObservableProperties.setValue` 早退不触发通知，也没法用重写的方式冲掉错误的残留注册。
3. **响应式作用域只有 attr / event / vif / vfor / vbind 闭包**：在普通 builder 闭包（包括 Scroller 子项）里读 observable，读到的是初始快照且不建立依赖，state 变了界面也不动。
4. **animate(animation, value) 的第二参数 value: Any 在实现里完全没被使用，是死参数**——而官方文档 animation-declarative.md 却把 value 描述为"需传入一个控制动画状态的响应式变量"。也就是说文档宣称显式 driver、实现却是隐式 last-read 绑定，文档与实现感觉不太一样。
